# 第四阶段:数据库清理与优化(可选)

## 目标

删除历史 Delta 数据并执行 VACUUM 回收数据库空间,将数据库体积从 183 MB 降至 < 10 MB。

**注意:本阶段为可选操作,不影响系统功能。**

---

## 背景

在第一阶段完成后,历史 Delta 事件(97.9% 的数据库内容)已不再写入,但历史数据仍占据磁盘空间:

- **Delta 事件占比**:525,750 条(97.9%)
  - `reasoning.delta`: 约 40%
  - `output.delta`: 约 40%
  - `tool.call.delta`: 约 18%
- **数据库体积**:183 MB
- **预期清理后体积**:< 10 MB

---

## 清理方案

### 方案 1:删除历史 Delta 数据(推荐)

**适用场景:**
- 数据库体积过大影响备份或迁移
- 确认历史 Delta 数据无价值
- 需要回收磁盘空间

**SQL 脚本:**

```sql
-- 1. 统计清理前数据
SELECT 
    message_type,
    COUNT(*) as count,
    ROUND(COUNT(*) * 100.0 / (SELECT COUNT(*) FROM event_outbox), 2) as percentage
FROM event_outbox
WHERE message_type LIKE '%.delta'
GROUP BY message_type
ORDER BY count DESC;

-- 2. 删除历史 Delta 事件
DELETE FROM event_outbox 
WHERE message_type IN (
    'reasoning.delta',
    'output.delta',
    'tool.call.delta'
);

-- 3. 回收空间
VACUUM;

-- 4. 统计清理后数据
SELECT 
    COUNT(*) as total_events,
    COUNT(DISTINCT message_type) as distinct_types
FROM event_outbox;

SELECT DISTINCT message_type 
FROM event_outbox 
ORDER BY message_type;
```

### 方案 2:保留最近 N 天的 Delta 数据

**适用场景:**
- 需要保留部分历史 Delta 用于调试
- 分阶段逐步清理

**SQL 脚本:**

```sql
-- 删除 30 天前的 Delta 事件
DELETE FROM event_outbox 
WHERE message_type LIKE '%.delta'
  AND created_at < datetime('now', '-30 days');

VACUUM;
```

### 方案 3:归档后删除

**适用场景:**
- 需要保留历史数据备份
- 合规要求保留审计日志

**步骤:**

```sql
-- 1. 导出历史 Delta 数据到备份表
CREATE TABLE IF NOT EXISTS event_outbox_archive AS
SELECT * FROM event_outbox
WHERE message_type LIKE '%.delta';

-- 2. 导出到文件(使用 SQLite CLI)
.mode csv
.output event_outbox_archive.csv
SELECT * FROM event_outbox_archive;
.output stdout

-- 3. 确认备份后删除
DELETE FROM event_outbox 
WHERE message_type LIKE '%.delta';

VACUUM;

-- 4. 可选:删除备份表
DROP TABLE IF EXISTS event_outbox_archive;
```

## 执行步骤

### 步骤 1:备份数据库

**在执行任何删除操作前,务必备份数据库。**


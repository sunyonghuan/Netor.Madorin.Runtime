> **定位：次要层。** 本文是**独立命令**的参数级说明，服务测试台次要层。控制台重点（serve 宿主的 Client SDK 交互）见[05-serve 宿主深度测试设计](./05-serve宿主深度测试设计.md)。本文中的 `serve` 只说明启动参数（用于拉起被测实例），其协议交互不在此。

本文逐命令说明测试台在参数向导中要呈现的内容：用途、参数（含默认值与提示）、必填/互斥约束、退出码、JSON 信封要点、示例与风险。字段以命令矩阵和 CLI 规范为契约，以源码实际注册为准。

## 通用约定

**全局参数**（所有命令继承，向导在“默认参数设置”页统一配置，可逐命令覆盖）：

| 参数 | 类型 | 默认/语义 |
| --- | --- | --- |
| `--workspace` | 路径 | 独立命令默认当前目录；`serve` 必须显式传入 |
| `--data-dir` | 路径 | 独立命令默认用户数据区隔离目录；`serve` 默认 `<workspace>/.madorin` |
| `--log-level` | 枚举 | `Debug`/`Information`/`Warning`/`Error`，默认取当前配置 |
| `--no-color` | 开关 | 非 TTY 自动禁用；测试台采集时建议开启 |
| `--json` | 开关 | 统一 JSON 信封；`run` 的 JSONL 用 `--output-format jsonl` |

**固定退出码**：`0` 成功 · `1` 通用错误 · `2` 参数/配置错误 · `3` 认证失败 · `4` 工作区/数据错误 · `5` Runtime 连接失败 · `130` 用户中断。

**JSON 信封**：
```json
{ "success": true, "data": { }, "warnings": [], "diagnosticId": null }
```
失败时 `success:false`，`error.{code,message,isRetryable,diagnosticId}`。业务字段只在 `data`；诊断日志与进度只写 stderr。

**Secret 铁律**：任何 API Key 不作为明文命令行参数。向导对 Secret 项只接受“环境变量名”或不回显输入，绝不拼进 `--api-key`。

## 1. 服务与执行

### 1.1 `run` — 单次任务

用途：执行一次对话任务。测试台默认加 `--no-stream` 便于完整采集；有 `--input` 即非交互。

| 参数 | 提示 | 默认 |
| --- | --- | --- |
| `--provider` | Provider ID | 读配置默认 |
| `--model` | 模型 ID | 读配置默认 |
| `--agent` | Agent 定义或内置 ID | 读配置默认 |
| `--mode` | `expert`/`meeting`/`work` | `expert` |
| `--session` | 继续已有会话 ID | 新建 |
| `--input` | 单次输入文本 | — |
| `--input-file` | 从文件读输入 | — |
| `--output-file` | 输出写入文件 | stdout |
| `--output-format` | `text`/`json`/`jsonl` | `text` |
| `--no-stream` | 等完整结果 | 默认流式 |
| `--timeout` | 执行超时（秒） | — |

约束（返回 `2`）：`--input` 与 `--input-file` 互斥；`--output-file` 必须配合 `--input` 或 `--input-file`；交互模式下用 JSON/JSONL/`--no-stream` 非法；`--json` 与非 JSON 的 `--output-format` 冲突。退出码 `2/4/130`。

示例：`madorin run --input "hello" --no-stream --json`

### 1.2 `run`（REPL）— 进入交互模式

用途：不传 `--input` 进入单行 REPL。斜杠命令见[01 文档第 9 节](./01-命令层次与菜单树.md#9-交互模式repl斜杠命令速查)。测试台以子进程交互方式驱动，提供斜杠命令速查面板。

### 1.3 `serve` — 常驻 Runtime Server

用途：启动常驻服务，等待宿主通过 Named Pipe 连接，供 `ctl` 与实时监控使用。

| 参数 | 提示 | 默认 |
| --- | --- | --- |
| `--workspace` | **必填**，绑定工作区 | 无（缺失返回 `2`） |
| `--config-dir` | 配置目录 | — |
| `--log-dir` | 日志目录 | — |
| `--instance` | 实例名 | 自动生成 |
| `--pipe-prefix` | Named Pipe 前缀 | `madorin.ai.runtime` |
| `--max-runs` | 最大并发 Run | `4` |

退出码 `2/3/4`。测试台把 `serve` 作为后台长驻进程管理（启动、健康探测、停止），并在“实时监控”页消费。

## 2. 诊断与信息

### 2.1 `version`

用途：显示程序版本、协议版本、构建信息。只读，无锁。退出码 `1`。示例：`madorin version --json`。作为采集链路首个冒烟命令。

### 2.2 `doctor`

用途：检查 .NET 运行时、Named Pipe、工作区权限与配置、`.madorin` 数据完整性、Provider 配置与连通性、日志与 Blob 目录权限。

| 参数 | 提示 | 默认 |
| --- | --- | --- |
| `--provider` | 只检查指定 Provider | 全部 |
| `--fix` | 尝试自动修复 | 关 |
| `--yes` | 跳过确认（仅与 `--fix` 合用） | — |

约束：`--yes` 未配合 `--fix` 返回 `2`。`--fix` 会改数据，执行前备份；无法写备份目录则拒绝。退出码 `1/2/4`。示例：`madorin doctor --fix --yes`。

## 3. 配置与 Agent

### 3.1 `config show` / `config validate`

只读。`show` 脱敏 Secret；`validate` 校验。支持 `--workspace` 展示全局路径、工作区路径、存在状态与 `effectiveSelection.{agent,provider,model}.{value,source}`。退出码 `2/4`。所有输出不得含 API Key 或工作区 JSON 正文。

### 3.2 `config init` / `config edit`

交互创建/修改全局配置。配置写锁。输入 Secret 不回显。退出码 `2/4`。测试台在向导里对 Secret 走不回显输入。

### 3.3 `agent list`

只读。退出码 `2/4`。

### 3.4 `agent create [agentId]`

| 参数 | 提示 |
| --- | --- |
| `agentId` | 位置参数，可省略并交互输入 |
| `--name --description --system-prompt --provider --model --temperature` | Agent 属性 |

配置写锁。退出码 `2/4`。示例：`madorin agent create demo --name Demo`。

### 3.5 `agent edit <agentId>`

同属性参数集，更新定义。配置写锁。退出码 `2/4`。

### 3.6 `agent delete <agentId>` 🔴

| 参数 | 提示 |
| --- | --- |
| `--replacement` | 迁移默认引用到该 Agent |
| `--yes` | 确认删除 |

配置写锁。退出码 `2/4`。测试台执行前二次确认。

## 4. 记忆与会话

`memory <scope>` 的 `<scope>` 只接受 `global`（`~/.madorin/memory.md`）或 `project`（`<workspace>/.madorin/memory.md`）。

### 4.1 `memory show <scope>`
只读，无锁。退出码 `2/4`。

### 4.2 `memory init <scope>`
缺失时创建记忆文件。记忆写锁。退出码 `2/4`。

### 4.3 `memory add <scope>`
从标准输入读单行内容追加。记忆写锁。退出码 `2/4`。测试台向导采集一行文本，通过 stdin 喂给子进程。示例：`"Prefer UTC" | madorin memory add project`。

### 4.4 `memory edit <scope>`
调用受控编辑流程替换内容。记忆写锁。退出码 `2/4`。

### 4.5 `memory clear <scope>` 🔴
清空内容，需 `--yes`。记忆写锁。退出码 `2/4`。

### 4.6 `session list`

| 参数 | 提示 | 默认 |
| --- | --- | --- |
| `--status` | `active`/`archived`/`all` | `active` |
| `--mode` | `expert`/`meeting`/`work` | 全部 |

| `--search` | 标题/摘要关键字 | — |
| `--limit` | 最多条数 | `20` |

只读。退出码 `2/4`。

### 4.7 `session show <sessionId>`
`--messages` 附带消息摘要。只读。退出码 `2/4`。

### 4.8 `session export <sessionId>`

| 参数 | 提示 | 默认 |

### 4.9 `session archive <sessionId>` / 4.10 `session unarchive <sessionId>`
标记归档 / 恢复活动。工作区写锁。退出码 `2/4`。

### 4.11 `session compact <sessionId>`

| 参数 | 提示 | 默认 |

| `--dry-run` | 只显示计划 | — |

## 6. 数据库维护

> 写命令实际写入前获取工作区排他锁；备份/恢复点创建失败时不进入修改阶段。

### 6.1 `db check`
`--verbose` 显示每项详情。严格只读，断言零写入，无锁。退出码 `1/2/4`。校验 SQLite quick_check/integrity_check/foreign_key_check、schema、WAL、messages 与 state.db 双向一致性、JSONL 完整性。

### 6.2 `db repair` 🔴
只修复 `db check` 识别的可恢复损坏（JSONL 损坏尾行、消息索引漂移），不是 `rebuild` 别名。

| 参数 | 提示 |
| --- | --- |
| `--dry-run` | 只显示计划，不锁不备份不写 |
| `--yes` | 跳过确认；JSON 模式实际修复必填 |

执行时工作区写锁，先备份。退出码：`0` 成功/无问题/dry-run；`1` 不可修复/备份或修复失败；`2` JSON 实际修复缺 `--yes`；`4` 锁冲突；`130` 拒绝确认。测试台默认先 dry-run。

### 6.3 `db rebuild` 🔴
从 `messages/` 重建 Session 与消息索引。

| 参数 | 提示 |
| --- | --- |
| `--dry-run` | 只扫描报告 |
| `--confirm` | 实际执行必须（会覆盖现有数据） |

执行时工作区写锁，覆盖前存恢复点。退出码：`0` 全部恢复/dry-run；`1` 部分恢复/恢复点或重建失败；`2` JSON 实际执行缺 `--confirm`；`4` 锁冲突；`130` 拒绝确认。恢复后 Session 状态为 Recovered，Run/Grant/工具意图无法从文件恢复。

### 6.4 `db vacuum` 🔴
在线压缩，无 dry-run/确认参数，执行前备份，新文件完成后原子替换。工作区写锁。退出码：`0` 成功；`1` 数据库缺失/压缩失败；`4` 锁冲突。结果报告 `databasePath/beforeBytes/afterBytes/reclaimedBytes`。

### 6.5 `db backup`

| 参数 | 提示 | 默认 |
| --- | --- | --- |
| `--output` | 备份目标路径 | `{data-dir}/backups/{timestamp}.db` |
| `--include-messages` | 同时压缩 messages/ | 关 |

仅 SQLite 时不获取写锁；含 messages 时工作区写锁。目标已存在拒绝覆盖，失败清理不完整备份集。退出码 `1/2/4`。

### 6.6 `db migrate` 🔴

| 参数 | 提示 | 默认 |
| --- | --- | --- |
| `--to` | 目标 schema 版本 | Runtime 最新支持 |
| `--dry-run` | 只检查迁移路径 | — |

只允许向前迁移，拒绝降级/越界。dry-run 严格只读；实际迁移工作区写锁并先备份。退出码：`0` dry-run/成功/已是目标；`1` 缺失/恢复点或迁移失败；`2` 版本非法/降级/越界；`4` 锁冲突。

## 7. 存储维护

### 7.1 `storage check`
`--verify-hashes` 流式校验 SHA-256（耗时）。严格只读，无锁。汇总 JSONL `blob_ref`、SQLite `tool_intents.result_blob_*` 与 `blobs/*.blob`。任一扫描不完整报告 `referenceScanComplete=false`。退出码：`0` 无问题；`1` 完整性问题/扫描失败；`2` 路径非法。

### 7.2 `storage gc` 🔴

| 参数 | 提示 | 默认 |
| --- | --- | --- |
| `--dry-run` | 只读展示计划（与 `--confirm` 互斥） | — |
| `--older-than` | 只处理至少 N 天的孤立 Blob | `7` |
| `--confirm` | 建恢复点并执行 | — |

未 `--confirm` 默认 dry-run；`--older-than` 不允许负数；dry-run 与 confirm 同时出现返回 `2`。执行时工作区写锁，候选移入 `backups/storage-gc-*` 恢复点而非直接删除。退出码：`0` 计划可执行/清理成功；`1` 扫描不完整/恢复点或移动失败；`2` 龄期负数/互斥冲突；`4` 锁冲突。

## 8. 在线控制（ctl）

> 连接正在运行的 Runtime。握手 secret 只从 `MADORIN_AI_RUNTIME_SECRET` 读取，不作为参数、不写入 stdout/stderr/JSON/日志。未显式 `--instance` 时只解析当前工作区唯一实例。

### 8.1 `ctl status`
`--instance`。只读 Runtime 状态。Runtime 绑定。退出码 `2/3/5`。

### 8.2 `ctl sessions`
`--instance`。只读 Session 列表。退出码 `2/3/5`。

### 8.3 `ctl runs`
`--instance --session`。只读 Run 列表。退出码 `2/3/5`。

### 8.4 `ctl cancel <runId>`
`--instance --reason`。请求取消，成功仅表示 `cancelAccepted`，最终 `cancelled` 需另查。退出码 `2/3/5`。

### 8.5 `ctl credential update`

| 参数 | 提示 | 必填 |
| --- | --- | --- |
| `--run` | 等待凭据的 Run | 是 |
| `--provider` | Provider ID | 是 |
| `--api-key-env` | 新 API Key 的环境变量名 | 是 |
| `--instance` | 实例绑定 | 否 |
| `--profile` | Profile ID | 否 |
| `--expires-at` | 带时区 ISO 8601 过期时间 | 否 |

缺 `--run`/`--provider`/`--api-key-env` 返回 `2`。缺 secret 或握手失败 `3`；实例/PID/Pipe/连接问题 `5`；Runtime 拒绝 `1`。Secret 只经环境变量，绝不回显。

## 9. 向导校验清单（固定返回 2 的组合）

测试台在提交前本地预校验，命中即拦截并提示，避免无效执行：

- `run --input` 与 `--input-file` 同时出现
- `run --output-file` 未配合 `--input` 或 `--input-file`
- `run` 交互模式下使用 JSON/JSONL/`--no-stream`
- `run --json` 与非 JSON 的 `--output-format` 同时出现
- `serve` 缺少 `--workspace`
- `doctor --yes` 未配合 `--fix`
- `storage gc --dry-run` 与 `--confirm` 同时出现
- `session delete` 缺少 `--confirm`
- `ctl credential update` 缺少 `--run`/`--provider`/`--api-key-env`

> 预校验只是提速，不替代真实命令的服务端校验；最终以真实退出码为准。

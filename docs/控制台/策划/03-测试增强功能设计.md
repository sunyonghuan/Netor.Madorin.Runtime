> 上级文档：[00-总体策划](./00-总体策划.md) · [01-命令层次与菜单树](./01-命令层次与菜单树.md) · [02-命令详细说明](./02-命令详细说明.md) · [05-serve 宿主深度测试设计](./05-serve宿主深度测试设计.md)

本文设计四个**通用**测试增强能力：结果断言、用例录制与回放、数据夹具准备与清理、实时监控。它们既服务**次要层**（独立命令的进程调用采集结果），也为**重点层**（[05 文档](./05-serve宿主深度测试设计.md)的 serve 宿主交互）提供断言、录制、夹具地基。两类被测对象产出不同的结果载体：

| 层次 | 结果载体 | 断言维度 |
| --- | --- | --- |
| 次要（独立命令） | `ExecutionResult`（退出码 + stdout/stderr + JSON 信封） | 退出码、信封字段、文本、零写入 |
| 重点（serve 宿主） | `HostInteractionResult`（事件流 + GSN 水位 + 回调记录 + Run 状态） | 事件断言、水位单调、回调幂等（见[05 文档](./05-serve宿主深度测试设计.md)第 9 节） |

本文第 0–3 节以 `ExecutionResult` 为主线描述通用机制，并在各节标注 serve 场景如何复用；第 4 节的实时监控重点服务 serve。所有能力都不改动业务逻辑。

## 0. 公共基础：一次执行的采集结果

所有增强能力消费同一个执行结果对象 `ExecutionResult`：

| 字段 | 含义 |
| --- | --- |
| `command` | 命令组/命令，如 `session list` |
| `argv` | 实际传给进程的参数数组（Secret 已脱敏为环境变量名） |
| `exitCode` | 进程退出码 |
| `stdout` / `stderr` | 完整文本（分流采集） |
| `envelope` | 解析后的 JSON 信封（若命令输出 JSON）：`success/data/error/warnings/diagnosticId` |
| `startedAt` / `duration` | 时间戳与耗时 |
| `timedOut` / `canceled` | 超时或用户中断标记 |

`ProcessRunner` 负责重定向 stdin/stdout/stderr、施加超时、支持 Ctrl+C 取消（映射到退出码 `130`）。JSON 命令的 stdout 只含机器数据，诊断/进度在 stderr——采集时分开保留，避免污染信封解析。

## 1. 结果断言与退出码校验

### 1.1 目标
执行后自动判定“这次结果对不对”，把人工肉眼看屏幕升级为可复用的通过/失败判定。

### 1.2 断言类型

| 断言 | 说明 | 示例 |
| --- | --- | --- |
| 退出码 | 等于/属于集合 | `exitCode == 0`；`exitCode in {0,2}` |
| JSON success | 信封 `success` 布尔 | `success == true` |
| JSON 字段存在/等值 | 按 JSON 路径取值比较 | `data.status == "healthy"`；`error.code == "WorkspaceNotFound"` |
| stdout/stderr 包含 | 子串或正则 | stdout 匹配 `/reclaimedBytes/` |
| 无 ANSI | `--no-color`/非 TTY 下 stdout 不含控制码 | 正则断言无 `\x1b[` |
| 耗时上限 | `duration <= N ms` | 冒烟性能护栏 |
| **数据未变更（零写入）** | 执行前后对目标数据目录做文件哈希快照并比对 | 验证 `db check`/`storage check`/只读 `session/ctl` 真的没写数据 |

> “数据未变更”断言依赖夹具级的前后快照能力：执行前对 `--data-dir` 下相关文件（state.db、messages/、blobs/）取哈希清单，执行后重比对，任一文件变更即判失败。它跨越断言与夹具两层，落地时由 `Assertions` 调用 `Fixtures` 的快照工具（见第 3 节）。

**serve 宿主场景的追加断言维度**（作用于 `HostInteractionResult`，详见[05 文档](./05-serve宿主深度测试设计.md)第 9 节）：

| 断言 | 说明 |
| --- | --- |
| 事件出现 | 某 GSN 之前出现指定 `Phase`/状态/工具事件 |
| 水位单调 | `lastConfirmedGsn` 只增不减，且不超过已处理事件 |
| 回调幂等 | 同一 `callId` 的有副作用工具只执行一次（命中幂等表） |
| Run 终态 | `QueryRunAsync` 最终到达期望终态；计数满足已完成 ≤ 总数 |
| 绑定校验 | `InstanceBinding` 的实例/PID/协议与期望一致 |

### 1.3 预期基线来源
- **命令矩阵驱动的默认断言**：每条命令带一组“默认期望”（如只读命令期望 `exitCode==0` 且不写数据；`session delete` 缺 `--confirm` 期望 `exitCode==2`）。这些从[02 文档](./02-命令详细说明.md)的退出码表生成，选中命令即自动附带。
- **首次执行快照**：把某次结果保存为期望基线，后续回归对照差异（黄金对照）。对易变字段（时间戳、diagnosticId、随机实例 ID）支持掩码规则，避免误报。

### 1.4 交互流程
1. 命令执行完 → 展示 `ExecutionResult` 摘要（退出码高亮、信封 success、关键 data 字段）。
2. 自动运行默认断言，逐条显示 ✓/✗。
3. 用户可追加自定义断言，或“保存为基线”。
4. 结果连同断言判定写入执行历史。

### 1.5 执行历史
本地追加式记录（JSON Lines），每行一次执行：命令、argv（脱敏）、退出码、断言通过数/失败数、耗时、时间戳。提供筛选（命令组、通过/失败、时间段）和导出，用于人工验收留痕。

## 2. 用例录制与回放

### 2.1 目标
把一串手工验证过的命令固化成用例，一键批量回放，形成半自动冒烟回归。

### 2.2 用例模型 `TestCase`

```jsonc
{
  "name": "db-check-then-repair-dry-run",
  "description": "只读检查后走修复 dry-run，验证零写入",
  "steps": [
    {
      "command": "db check",
      "args": { "--verbose": true },
      "assert": [ { "exitCode": [0, 1] } ]
    },
    {
      "command": "db repair",
      "args": { "--dry-run": true },
      "assert": [ { "exitCode": 0 }, { "jsonPath": "data.status", "equals": "planned" } ]
    }
  ],
  "fixtures": { "before": "fixture:seeded-workspace", "after": "cleanup:remove-workspace" }
}
```

- `command` + `args`：直接映射到 argv，与向导产出一致。
- `assert`：复用第 1 节断言类型。
- `fixtures`：可选，引用第 3 节夹具，回放前/后自动执行。
- Secret 项只存环境变量名，绝不存明文。

### 2.3 录制
- **从当前执行录制**：向导执行成功后选“加入用例”，把命令、argv、当前断言追加到指定用例。
- **连续录制模式**：开启后每次执行自动入列，直到停止；适合把一条人工验证链一次录完。

### 2.4 回放
- 选择用例（或用例集）→ 顺序执行每个 step → 汇总每步断言结果 → 输出通过/失败报告。
- 选项：遇失败停止 / 继续跑完；隔离回放（每个用例独立夹具）。
- 回放报告可导出，作为一次冒烟回归的凭证。

### 2.5 变量与占位
支持在 args 里用占位符（如 `${sessionId}`、`${workspace}`），回放时从环境、上一步 `data` 字段或夹具产出解析。例如 `session show` 的 `sessionId` 取自前一步 `run` 的 `data.sessionId`。

> **约束**：从上一步 `data` 提取变量，要求该步**必须产出 JSON 信封**。`run` 默认 `text` 输出没有 `data`，因此被后续步骤引用的 `run` 步骤必须显式带 `--output-format json`（或 `--json`）。录制/编辑用例时若发现某步被 `${...}` 引用却未产出 JSON，测试台应告警并阻止保存，避免回放时静默取空。

### 2.6 两类步骤：命令步骤与 serve 宿主步骤
一个用例的 `steps` 可混合两种 `kind`，让“连接 serve → 提交 Run → 应答回调 → 断线重连 → 校验”这类重点场景也能录制回放：

| `kind` | 载体 | 典型步骤 | 断言维度 |
| --- | --- | --- | --- |
| `command`（默认） | 进程调用独立命令 | `db check`、`session list` | `ExecutionResult`（退出码/信封/文本/零写入） |
| `host` | Client SDK 宿主动作 | `connect`、`startRun`、`consumeEvents`、`answerCallback`、`reconnect`、`updateCredentials` | `HostInteractionResult`（事件/水位/回调幂等/终态） |

`host` 步骤的 `${...}` 占位可引用上一步的 `runId`/`sessionId`/`gsn`（SDK 直接返回结构化值，无需 JSON 输出格式约束）。`host` 步骤里的 secret 只引用环境变量名。serve 宿主步骤的语义与顺序以[05 文档](./05-serve宿主深度测试设计.md)为准，本节只定义其在用例中的编排壳。

## 3. 数据夹具准备与清理

### 3.1 目标
保证每轮测试从**已知状态**开始，尤其是危险命令（`db repair`/`rebuild`、`storage gc`、`session delete`）需要可控的初始数据，测完能干净还原。

### 3.2 夹具动作库

| 夹具 | 动作 | 实现 |
| --- | --- | --- |
| 全新工作区 | 建临时目录作为 `--workspace`，用完删除 | 纯文件操作 + 目标命令初始化 |
| 播种会话 | 用 `run --no-stream` 造 1~N 个会话/消息 | 调用真实命令，产出真实数据 |
| 播种孤立 Blob | 造无引用的 `.blob` 供 `storage gc` 测试 | 受控写入 blobs/（仅测试工作区）；文件名**必须**是内容的小写 64 位 SHA-256，否则 `storage gc` 不视为候选、夹具白造；如需触发“过龄”回收还要回设文件时间 |
| 备份还原点 | 测前 `db backup`，测后可还原 | 调 `db backup`；还原为文件替换 |
| 清空记忆 | 还原 memory.md 初始态 | 文件快照 + 还原 |
| 清理工作区 | 删除临时工作区与其 `.madorin` | 纯文件操作，仅限测试台建立的目录 |

### 3.3 安全边界（关键）
- 夹具**只操作测试台自己创建的临时工作区**，绝不触碰用户真实业务数据区。创建时记录归属标记（如目录内放 `.mconsole-owned` 哨兵文件），清理前校验哨兵存在才允许删除。
- 播种数据一律通过真实命令产生，不手写 SQLite/JSONL 内部结构（除“孤立 Blob”这类明确需要制造异常的场景，且限定在测试工作区）。
- 清理是危险动作：默认先列出将删除的路径并二次确认；批量/自动化模式下要求哨兵校验通过。

### 3.4 交互流程
1. 夹具菜单：选“准备” → 选夹具 → 产出一个可用的 `--workspace`/`--data-dir` 环境，登记到当前会话上下文，后续命令默认套用。
2. 测试完成：选“清理” → 显示归属校验与待删列表 → 确认后清理。
3. 与用例联动：用例的 `fixtures.before/after` 自动调用夹具动作，实现隔离回放。

## 4. serve 实例实时监控

### 4.1 目标
把一个运行中的 serve 实例做成自动刷新的状态看板，实时观察 Run/Session 变化和控制操作的效果。

### 4.2 数据来源：优先 Client SDK，ctl 作次要对照
测试台本身就是宿主、已持有该实例的 `RuntimeClient`（见[05 文档](./05-serve宿主深度测试设计.md)），因此看板数据**优先走 Client SDK 的只读查询**：`GetRuntimeStatusAsync`、`ListSessionsAsync`、`ListRunsAsync`。这与重点层一致，也避免为看板额外反复 spawn 子进程。

`ctl status/sessions/runs` 作为**次要对照通道**保留：用于验证“宿主经 SDK 看到的状态”和“运维经 ctl 看到的状态”一致，本身也是次要层的一条被测项。走 ctl 时遵循 secret 闭环（下条）。

### 4.3 serve 生命周期与 secret 闭环
- **启动/停止**：由 `ServeHost`（见 00 文档）管理后台 serve 进程，采集其 stdout/stderr。
- **健康探测**：启动后用 `GetRuntimeStatusAsync`（或 attach 时的 `InstanceBinding`）确认就绪，显示实例 ID、协议版本、PID。
- **Secret 闭环**：测试台生成/持有握手 secret。Client SDK 连接经重定向 stdin 传 secret；若额外用 `ctl` 对照，每次 `ctl` 调用也必须注入同一 secret，否则返回退出码 `3`。secret 只在进程环境/stdin 间传递，绝不显示、不入用例、不入历史。

### 4.4 看板视图
定时（可配间隔，如 2s）刷新：

```text
┌ Runtime 实例 a1b2c3… | 协议 1.1 | PID 12345 | 运行 00:02:14 ┐
│ 活动 Run: 3   已连接宿主: 2   最大并发: 4                    │
├ Sessions ──────────────────────────────────────────────────┤
│ s1  expert   active   2 msgs   "优化数据库查询"              │
│ s2  meeting  active   6 msgs   "方案评审"                    │
├ Runs ──────────────────────────────────────────────────────┤
│ run-1  s1  running   00:00:12                                │
│ run-2  s2  running   00:00:03                                │
└─────────────────────────────────────────────────────────────┘
[c] 取消 Run  [r] 手动刷新  [q] 返回
```

- 数据来源：`GetRuntimeStatusAsync` + `ListSessionsAsync` + `ListRunsAsync`（SDK），可选并列 `ctl` 对照列。
- 连接丢失时显示“连接丢失”并降频重试（SDK 侧由 `State`/`Completion` 反映；ctl 侧为退出码 `5`），不刷屏报错。

### 4.5 联动操作
- 在看板选中一个 Run 按 `c` → 走 SDK `CancelRunAsync(runId)` → 观察下次刷新的状态变化（成功仅表示 accepted，最终态靠后续查询确认）。次要层可对照 `ctl cancel`。
- 需要凭据续期时，跳到[05 文档](./05-serve宿主深度测试设计.md)第 8 节的 `CredentialPanel`（SDK `UpdateCredentialsAsync`）；次要层可对照 `ctl credential update`。

### 4.6 与其他能力联动
- 看板的每次查询/操作都可进执行历史与断言（如“取消后 N 秒内 run 状态变为 cancelled”，用第 1 节的事件/状态断言）。
- 可把“启动 serve → 提交 Run → 取消 → 校验”整条录成用例（含 serve 宿主步骤，见第 2.6 节）。

## 5. 落地优先级（对齐 00 文档第 7 节）

| 阶段 | 能力 | 依赖 |
| --- | --- | --- |
| P5 | 结果断言（`ExecutionResult` + `HostInteractionResult` 维度）+ 执行历史 | 次要层采集 + 重点层宿主循环（05） |
| P5 | 用例录制与回放（`command` + `host` 两类步骤） | 断言 + argv/宿主动作建模 |
| P5 | 数据夹具准备与清理 | 进程调用 + 安全哨兵 |
| P4→P6 | serve 实例实时监控看板（SDK 优先，ctl 对照） | `ServeHost` + Client 只读查询 |

> 断言与夹具虽排在 P5，但其中“零写入快照”“工作区夹具”在重点层 P1–P3 演练 serve 时就会被用到，可按需提前实现最小子集。四项都建立在同一套采集与定义之上：独立命令依赖 `CommandCatalog`，serve 步骤依赖 05 文档的宿主动作定义，避免与 CLI 契约或 SDK 契约漂移。

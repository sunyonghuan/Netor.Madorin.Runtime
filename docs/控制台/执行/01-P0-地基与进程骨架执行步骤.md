## 4. P0-03 配置模型与自有数据目录

当前进度：100%

配置文件建议字段：

```jsonc
{
  "runtimeExecutablePath": "",
  "defaultWorkspace": "",
  "defaultDataDir": "",
  "defaultLogLevel": "Information",
  "defaultNoColor": true,
  "defaultJson": true,
  "mconsoleHome": "~/.madorin-mconsole",
  "startupTimeoutSeconds": 30,
  "commandTimeoutSeconds": 120
}
```

执行步骤：

1. 定义 `MConsoleOptions`，只包含测试台自己的配置，不映射 Runtime 内部配置。

5. `appsettings.mconsole.json` 只放默认值，不放任何 secret。
6. 支持通过环境变量或命令行覆盖配置路径，但 secret 不进入配置。

完成标准：

- 启动时能创建测试台自有目录。
- 配置加载失败时有清晰错误。
- 配置输出或日志不包含 secret。

## 6. P0-05 一次性命令进程采集

当前进度：100%

核心对象：

```text
ExecutionResult
- command
- argv
- exitCode
- stdout
- stderr
- envelope
- startedAt
- duration
- timedOut
- canceled
```

执行步骤：

1. 实现 `ProcessRunner`，只服务一次性命令。
2. 使用 `System.Diagnostics.Process` 启动真实 `madorin`。
3. 永远重定向 stdout/stderr，并分流采集。
4. 支持可选 stdin 内容，例如 `memory add` 后续要用。
5. 支持超时；超时后尽量优雅取消，再强制结束。
6. 支持用户中断映射到退出码 `130`。
7. argv 记录必须脱敏；环境变量名可以记录，环境变量值不能记录。
8. stdout/stderr 采集不能互相污染，JSON 命令只从 stdout 解析。
9. 进程启动失败也要转成可展示的失败结果或明确异常。

完成标准：

- 能运行 `madorin version --json --no-color`。
- 能分别显示 stdout 和 stderr。
- 超时和取消有稳定标记。
- Secret 不出现在 `ExecutionResult.argv`。

执行记录：

```text
状态：完成
进度：100%
记录：stdout/stderr 分流、stdin、超时、取消、退出码和脱敏已实现。
```

## 7. P0-06 JSON 信封解析

当前进度：100%

信封字段：

```json
{
  "success": true,
  "data": {},
  "warnings": [],
  "diagnosticId": null
}
```

执行步骤：

1. 实现 `JsonEnvelope`，基于 `System.Text.Json`。
2. 只读取通用字段：`success`、`data`、`error`、`warnings`、`diagnosticId`。
3. `data` 和 `error` 保留为 `JsonElement` 或轻量包装，不建立业务强类型。
4. 解析失败时保留原始 stdout，不吞掉输出。
5. JSON 解析失败不能影响非 JSON 命令的退出码采集。
6. stderr 永远不参与 JSON 信封解析。

完成标准：

- `version --json` 可解析出 success。
- 非 JSON 输出不会误报为成功信封。
- 解析失败信息清晰。

执行记录：

## 8. P0-07 后台 serve 管理

当前进度：100%

组件：`ServeHost`

执行步骤：

1. `ServeHost` 管理 `madorin serve` 长驻进程，不复用 `ProcessRunner` 的一次性模型。
2. 启动前生成运行时 secret。
3. 按当前 CLI 冻结契约，通过受控 stdin 首行传入 secret 并立即关闭输入句柄；secret 不进入 argv 或环境变量。
4. `--workspace` 必须显式传入；缺失时在测试台层面拦截。
5. 支持 `--instance`、`--pipe-prefix`、`--data-dir`、`--log-dir`、`--max-runs`。
6. 持续采集 serve stdout/stderr，保留最近 N 行用于诊断。
7. 实现启动超时；超过 `startupTimeoutSeconds` 仍未就绪则停止进程并报错。
8. P0 的健康探测可以先用进程存活和可选 `ctl status` 对照；P1 后切到 Client SDK 优先。
9. 实现停止：优先优雅关闭，超时后结束进程。
10. 进程退出时记录 PID、退出码、退出时间、最后日志片段。

完成标准：

- 能启动一个后台 serve。
- 能停止该 serve。
- secret 不显示在控制台、日志、历史中。
- `serve` 缺少 workspace 时不会启动。

执行记录：

状态：完成
进度：100%
记录：owned serve 启停、有界日志、超时和受控 stdin secret 传递已实现并真实冒烟。

## 9. P0-08 REPL 最小会话管理

当前进度：100%

组件：`ReplSession`

执行步骤：

1. `ReplSession` 只管理 `madorin run` 无 `--input` 的交互模式。
2. 子进程常驻，stdin 按行写入，stdout/stderr 持续读取。
3. 不逐字渲染 token，不解析 ANSI 或光标控制。
4. `/exit`、`/quit` 或 EOF 后采集最终退出码。
5. REPL 内每次往返不生成 `ExecutionResult`，只记录会话流水。
6. 为 P4 的斜杠命令速查面板预留发送接口。

完成标准：

- 能启动 REPL。
- 能发送一行输入。
- 能退出并采集退出码。
- 不影响一次性命令采集模型。

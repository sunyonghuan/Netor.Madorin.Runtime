# P8 · 工作区本地数据与兼容迁移执行步骤

> 文档状态：完成  
> 当前进度：100%  
> 决策日期：2026-07-27  
> 目标：独立 CLI 的运行数据默认归属于工作区，并安全承接旧用户级哈希目录中的历史数据。

## 1. 决策与边界

独立 CLI 的默认路径契约调整为：

```text
用户级目录 ~/.madorin/
├── config.json
├── agents/
└── memory.md

工作区 <workspace>/.madorin/
├── config.json          # 可选，只保存工作区选择
├── memory.md            # 项目记忆
├── state.db             # Session、Run 和索引
├── messages/
├── blobs/
├── checkpoints/
├── staging/
├── replay/
├── locks/
└── logs/
```

约束：

1. Provider API Key、用户 Agent 和全局记忆继续保存在用户级目录。
2. 聊天、Session、数据库、消息、Blob、检查点、日志和运行锁默认保存在工作区。
3. `--workspace` 继续显式覆盖工作区；未提供时使用 CLI 启动时的当前目录。
4. `--data-dir` 继续显式覆盖运行数据目录；显式覆盖时不执行旧默认目录自动迁移。
5. `serve` 和宿主模式继续使用调用方明确提供的工作区与数据目录，不读取个人 CLI 的旧哈希数据。
6. 不自动把 API Key 写入工作区，不把工作区对话数据写回用户级配置目录。

## 2. 问题与根因

当前独立 CLI 把默认运行数据写到：

```text
~/.madorin/data/workspaces/<workspaceKey>/
```

这会引入以下问题：

- 工作区与数据分离，复制、移动和备份工作区时历史记录不会同行。
- 路径大小写、尾分隔符、盘符映射或启动目录变化可能导出不同的 `workspaceKey`。
- 二次进入需要先正确重建哈希关系，排查时无法从工作区直接定位数据。
- 删除工作区后，用户级目录容易残留无法识别来源的历史数据。
- CLI 双击作为便携应用运行时，用户无法在软件目录看到对应工作区状态。

P8 以 `<workspace>/.madorin` 作为唯一默认运行数据源，`workspaceKey` 只保留为实例标识或兼容迁移定位信息，不再决定新数据的默认位置。

## 4. P8-01 路径契约执行步骤

1. 以较新的独立 CLI 专项为现状基线，标出与早期架构修订冲突的用户级哈希数据设计。
2. 明确工作区是业务数据所有者，用户级目录是个人配置所有者。
3. 明确无参数启动只冻结一次 `startupDirectory`，运行中不随 `Environment.CurrentDirectory` 变化。
4. 保留 `workspaceKey` 的稳定算法，用于旧目录定位、诊断和兼容证据。
5. 明确工作区 `.madorin/config.json` 与运行数据共存，迁移不得覆盖配置、记忆或 Skills。

完成标准：所有实现和文档使用同一默认路径，不能同时出现两个“默认数据目录”。

## 5. P8-02 默认数据目录修改步骤

1. 将 `StandaloneRuntimeContext.Create` 的默认 `DataDirectory` 改为 `<normalizedWorkspace>/.madorin`。
2. 显式 `dataDirectory` 继续优先，保持绝对路径规范化和尾分隔符处理。
3. 增加只读的旧默认目录定位值，不把迁移策略塞入纯路径解析方法。
4. 检查 run、session、db、storage、doctor、skills 和 ctl 的数据目录解析是否一致。
5. 对仍直接拼接 `.madorin` 的命令确认其宿主/独立语义，避免误改 `serve`。

完成标准：新工作区首次运行后，数据库与消息目录只出现在工作区 `.madorin`；显式覆盖仍只写覆盖目录。

## 6. P8-03 旧数据安全迁移步骤

旧目录：

```text
~/.madorin/data/workspaces/<workspaceKey>/
```

新目录：

```text
<workspace>/.madorin/
```

迁移规则：

1. 仅独立 CLI 使用默认数据目录时检查旧目录；显式 `--data-dir`、`serve` 和宿主模式跳过。
2. 在工作区写锁保护下迁移，活动旧版本 Runtime 存在时不复制正在写入的 SQLite/WAL。
3. 允许新目录预先存在 `config.json`、`memory.md`、`skills/` 等非运行数据。
4. 若新目录已经包含 `state.db` 或非空运行数据目录，不自动合并两套历史，返回明确冲突诊断。
5. 跨盘迁移使用复制、逐文件长度与 SHA-256 校验、完成标记三阶段流程，不依赖 `Directory.Move`。
6. 迁移失败时删除本次未完成的暂存目录，不修改旧目录，不留下半迁移主目录。
7. 迁移成功后新目录成为唯一运行源；旧目录保留并写入迁移标记，供人工确认后清理。
8. 日志和错误不得包含 API Key、Prompt 或消息正文；只记录路径、文件计数、字节数和诊断码。

完成标准：旧 Session 可从新目录读取；中断、冲突和跨盘场景不丢失旧数据。

## 11. 风险与回退

| 风险 | 控制措施 |
| --- | --- |
| 工作区只读 | 启动前探测并返回工作区/数据错误，提示 `--data-dir` |
| 误提交聊天数据库 | 根仓库和模板统一忽略 `.madorin`，只在明确需要时放行选择配置 |
| SQLite/WAL 迁移时仍被写入 | 迁移与 Runtime 使用同一工作区写锁 |
| 新旧目录都有历史 | 禁止自动合并，报告冲突并保留两边 |
| 跨盘移动失败 | 使用暂存复制和 SHA-256 校验，不直接移动 |
| 新版本回退 | 保留旧目录和迁移标记，旧版本可显式 `--data-dir` 指向备份 |
| 网络共享锁/WAL 不可靠 | 发布说明限制网络工作区，或要求覆盖到受支持的本地数据目录 |

回退顺序：停止新 Runtime，恢复上一版本二进制，显式指定旧用户级数据目录；确认数据可读后再决定是否移除本地迁移结果。任何回退都不自动删除新旧数据。

## 3. 全局强制约束

这些约束来自策划文档和仓库级规则，所有阶段必须遵守。

### 3.1 C#/.NET 代码理解约束

- 第一次处理本仓库 C# 代码前，先确定仓库根目录，然后调用 CodeMap baseline 与 workspace。
- 需要理解符号、接口实现、调用关系、DI、配置、项目结构时，优先使用 CodeMap，不先用文本搜索猜语义。
- 修改任意 C# 文件后，刷新 CodeMap overlay，确保后续分析看到最新代码。

### 3.2 文件操作约束

- 新增、修改、删除、移动文件或目录前，先检查受影响目录中的 `README.md`。
- 如果目录有 `README.md`，必须先读并遵守。
- 大文件只做局部补丁，不整文件重写。
- 不回退用户已有改动，不使用破坏性 git 命令。

### 3.3 宿主依赖边界

- `HostClient/` 只能引用 `Madorin.AI.Runtime.Client` 和必要 Contracts。
- 不引用 Provider、Server、Persistence、SQLite、MAF/MEAI 实现。
- 不解析 Named Pipe 帧，不扫描 Runtime 内部数据目录，不访问 Runtime 内部 DI。
- 如果 SDK 不能验证某项行为，记录 SDK 暴露不足，不在测试台开后门。

### 3.4 Secret 安全

- API Key 和 Runtime 握手 secret 不进入命令行参数。
- Secret 不显示、不写历史、不写日志、不进入用例文件。
- secret 只由测试台运行时持有；`serve` 按当前 CLI 契约经受控 stdin 首行传入，`ctl` 如需环境变量只在子进程环境中注入且不记录值。
- 多实例时每个实例持有独立 secret，绝不跨实例共用。

### 3.5 进程模型

- `ProcessRunner` 只服务一次性命令。
- `run` 无 `--input` 的 REPL 使用 `ReplSession` 管理。
- `serve` 使用 `ServeHost` 管理。
- 不用一次性命令采集模型套 REPL 或 serve。

### 3.6 数据隔离

- 测试台自己的配置、用例、执行历史存放在自有目录，如 `~/.madorin-mconsole/`。
- 夹具创建的临时工作区必须有归属哨兵，例如 `.mconsole-owned`。
- 夹具清理只允许删除带归属哨兵的临时目录。
- 不触碰用户真实业务工作区，除非用户显式指定并确认。

- 三种 StartPolicy 都能验证。

- `noDataChange` 快照断言可用。

- B0 基线产物、SHA-256、SDK、最终 MSBuild 属性和 dirty diff 已固化。
- 候选版使用独立输出目录，不覆盖已通过 P0/P5/P6 的 B0 NativeAOT 产物。

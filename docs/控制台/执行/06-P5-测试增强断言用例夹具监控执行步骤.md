## 2. P5-01 断言模型

当前进度：100%

支持断言：

```text
exitCodeEquals
exitCodeIn
jsonSuccess
jsonPathExists
jsonPathEquals
stdoutContains
stderrContains
stdoutRegex
stderrRegex
noAnsi
durationLessThan
noDataChange
hostEventAppears
hostGsnMonotonic
hostCallbackIdempotent
hostRunTerminalState
hostBindingMatches
```

执行步骤：

1. 定义统一 `AssertionDefinition`。
2. 定义 `AssertionResult`，包含通过/失败、实际值、期望值、消息。
3. 对 `ExecutionResult` 实现退出码、JSON、文本、ANSI、耗时断言。
4. 对 `HostInteractionResult` 实现事件、水位、回调、终态、绑定断言。
5. 断言失败不抛未处理异常，统一返回失败结果。
6. 断言消息不包含 secret。

完成标准：

- 单个执行结果可运行多条断言。
- 命令断言和宿主断言共用报告格式。
- 失败原因能定位字段。

## 3. P5-02 默认断言生成

当前进度：100%

执行步骤：

1. 从 P4 `CommandCatalog` 读取命令风险和退出码期望。
2. 只读命令默认附加 `exitCode==0` 和可选 `noDataChange`。
3. 危险命令 dry-run 默认附加 `exitCode==0` 和 `noDataChange`。
4. 固定错误组合默认附加 `exitCode==2`，但这些通常已被 P4 拦截。
5. JSON 命令默认附加 `jsonSuccess==true`。
6. `ctl` 类命令根据场景附加 `exitCode in {0,3,5}` 的明确期望，不模糊判断。
7. 用户可追加自定义断言。

完成标准：

- 选中命令后自动带默认断言。
- 默认断言能被查看和禁用。
- 默认断言来源可追溯到 Catalog。

## 4. P5-03 执行历史

```text

argvOrActionArgs

```

执行步骤：

1. 创建追加式历史 writer。
2. argv 脱敏后写入。

6. 支持导出报告。
7. 写历史失败不能影响命令真实执行结果，但要提示。

完成标准：

- 每次执行都有历史记录。
- Secret 不进历史。
- 历史可筛选和导出。

## 6. P5-05 用例模型与录制

当前进度：100%

TestCase 支持两类 step：

```jsonc
{
  "name": "example",
  "steps": [
    { "kind": "command", "command": "db check", "args": {}, "assert": [] },
    { "kind": "host", "action": "startRun", "args": {}, "assert": [] }
  ],
  "fixtures": {
    "before": "fixture:seeded-workspace",
    "after": "cleanup:remove-workspace"
  }
}
```

执行步骤：

1. 定义 TestCase schema。
2. `command` step 映射到 P4 的 CommandCatalog。
3. `host` step 映射到 P1-P3 的宿主动作。
4. 从当前执行录制到用例。
5. 支持连续录制模式。
6. 录制时保存断言。
7. Secret 只保存环境变量名。
8. 被后续变量引用的 step 必须产出结构化数据。

完成标准：

- 命令执行可加入用例。
- 宿主动作可加入用例。
- 用例文件不存明文 secret。

## 8. P5-07 变量与占位解析

当前进度：100%

占位示例：

```text
${workspace}
${dataDir}
${sessionId}
${runId}
${gsn}
${step.previous.data.sessionId}
```

执行步骤：

1. 建立用例执行上下文。
2. 夹具产出 workspace/dataDir 后写入上下文。
3. command step 只能从 JSON 信封 `data` 中提取变量。
4. 如果某个 command step 被引用但没有 JSON 信封，阻止保存或回放。
5. host step 可直接从结构化返回值提取 runId/sessionId/gsn。
6. 占位无法解析时让 step 失败，不静默取空。
7. 变量值如果是 secret，禁止写入报告。

完成标准：

- 跨 step 变量可用。
- 缺失变量有明确错误。
- JSON 输出约束被执行。


执行步骤：

1. 创建临时工作区时写入 `.mconsole-owned` 哨兵。

8. 备份通过真实 `db backup`。
9. 还原使用文件替换，必须限定测试工作区。
10. 清理前展示将删除路径，自动模式也要哨兵通过。

完成标准：

- 夹具只操作测试台拥有的目录。
- 播种数据真实。

## 11. P5-10 serve 实时监控看板

当前进度：100%

数据来源优先级：

1. Client SDK：`GetRuntimeStatusAsync`、`ListSessionsAsync`、`ListRunsAsync`。
2. `ctl status/sessions/runs` 作为对照。

执行步骤：

1. 读取当前 RuntimeClient 绑定。
2. 定时刷新状态，默认间隔可设为 2 秒。
3. 展示 Runtime 实例 ID、协议、PID、运行时长。
4. 展示活动 Run、已连接宿主、最大并发。
5. 展示 Session 列表。
6. 展示 Run 列表。
7. 选中 Run 后支持 SDK `CancelRunAsync`。
8. 可选开启 ctl 对照列。
9. 走 ctl 时注入当前实例 secret。
10. 连接丢失时降频重试，不刷屏。
11. 看板查询和操作可写入历史。

完成标准：

- SDK 看板可刷新。
- ctl 对照不泄露 secret。
- 取消操作能从看板触发并观察后续状态。

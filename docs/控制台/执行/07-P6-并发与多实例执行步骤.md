## 2. P6-01 ServeHostPool 多实例生命周期

当前进度：100%

每个实例字段：

```text
id
workspace
dataDir
logDir
instanceId
pipePrefix
maxRuns
secretRuntimeOnly
ownedProcess
RuntimeClient binding
```

执行步骤：

1. 在 P0 `ServeHost` 上实现 `ServeHostPool`。
2. 每个实例生成独立 secret。
3. 每个实例使用唯一 `--instance`。
4. 每个实例使用唯一 `--pipe-prefix` 或后缀。

7. 每个实例持有独立 RuntimeClient。
8. 多实例游标按 `runtimeInstanceId` 分开保存。
9. 任一实例启动失败时标记该实例失败，不影响已启动实例的清理。

完成标准：

- 可以同时启动两个不同工作区 serve。
- 每个实例 secret 独立。
- 每个 RuntimeClient 固定绑定一个实例。

## 4. P6-03 并发启动与时间线采集

当前进度：100%

执行步骤：

1. 为 concurrentSteps 创建启动屏障。
2. 所有步骤准备好后同时释放启动。
3. 每个一次性命令使用独立 `ProcessRunner`。

- 并发步骤确实重叠执行。
- 输出不交织。
- 时间线可以解释锁冲突是否有效。

## 9. P6-08 场景 D/E/F：多工作区隔离

当前进度：100%

覆盖场景：

```text
D：N 工作区并发写
E：实例发现不串扰
F：跨实例取消路由
```

执行步骤：

1. 创建 N 个临时工作区，每个都有哨兵。
2. 每个工作区启动一个 serve。
3. 每个 serve 提交一个 Run。
4. 断言每个工作区只出现本实例数据变更。
5. 对每个工作区执行 `ctl status/sessions/runs`。
6. 未显式 `--instance` 时只允许解析当前工作区唯一实例。
7. 显式 `--instance` 时只命中目标实例。
8. 对实例 A 的 run 发 cancel。
9. 断言实例 B 的 Run 状态不受影响。
10. 如果不同实例出现同名 runId，也必须按实例绑定区分。

完成标准：

- 多工作区并发成功。
- ctl 不返回其他工作区实例。
- cancel 不串实例。

## 10. P6-09 场景 G/H：单实例并发 Run

当前进度：100%

覆盖场景：

```text
G：并发 Run 达上限
H：并发下取消与凭据更新
```

执行步骤：

1. 以 `--max-runs=N` 启动 serve。
2. 同时提交 `N + M` 个 Run。
3. 采集每个 Run 的状态时间线。
4. 断言任意时刻 running 数量不超过 N。
5. 记录超出上限的 Run 是排队还是被拒绝。
6. 行为如果未在契约中固定，记录实际稳定行为作为测试基线。
7. 对其中一个 Run 发 cancel。
8. 断言只有目标 Run 被取消。
9. 对等待凭据的目标 Run 执行凭据续期。
10. 断言其他 Run 不受凭据更新影响。

完成标准：

- max-runs 上限被遵守。
- 排队/拒绝行为稳定可记录。
- cancel 和 credential update 只影响目标 Run。

## 13. 实施对齐与验收证据

执行结果：

1. `ServeHostPool` 支持不同实例并行启动、独立随机 secret、唯一 instance/pipe、独立 data/log 目录和固定 `RuntimeClient` 绑定；启动失败携带退出快照，已启动实例仍能统一收敛。
2. `ConcurrencyScenarioValidator` 校验实例、工作区、并发步骤和超时上限，拒绝重复 ID、越界资源及未声明引用；剧本模型不含 secret 字段。
3. `ConcurrencyScenarioRunner` 为所有步骤建立统一释放屏障，每步使用独立 `ProcessRunner` 和输出缓冲，记录 ready/start/first-output-observed/exit 时间并在总超时后取消未完成进程。
4. `AggregateAssertionEngine` 已实现 `atMostOneExitZeroAmong`、`allOthersExitCode`、`allNoDataChange`、`noCrossWorkspaceWrites` 和 `timelineOverlapAtLeast`；失败结果包含相关 step ID。
5. 真实场景 A/B：同工作区第二 serve 与尾斜杠路径别名均返回退出码 4；失败前后数据目录 SHA-256 快照无变化。
6. 真实场景 C：持锁 serve 存在时，`db check`、`storage check`、`session list` 同时释放执行，均未被写锁错误阻塞且数据快照无变化。
7. 真实场景 D/E/F：两个工作区的 Runtime PID、instance binding 与 SDK client 各自独立；实例 A 定向取消前后实例 B 的 run ID 与状态未变化。
8. 真实场景 G/H：`max-runs=1` 的重复采样峰值为 0 或 1，始终不超过 1；三个并发提交中一个接受、两个稳定返回 RPC `-32003` 容量拒绝，实际策略为“拒绝而非排队”。凭据续期的跨重启隔离已由 P3 真实 E2E 覆盖，P6 不伪造当前无凭据请求的场景。
9. 收敛逻辑容忍 SDK 通道先断开，仍会停止所有 owned serve；目录删除继续受 P5 fixture root 和哨兵值双重约束。菜单 13 已接入完整 P6 验收链。

## 2. P3-01 持久化宿主恢复状态

当前进度：100%

需要持久化的数据：

```text
runtimeInstanceId
hostInstanceId
workspace
runtime PID
protocol version
lastConfirmedGsn
active runId/sessionId
callback idempotency table
pending tool results
```

执行步骤：

1. 在测试台自有目录创建恢复状态文件，不写入 Runtime 工作区。
2. 每个 Runtime 实例单独保存状态。
3. `lastConfirmedGsn` 每次确认成功后立即持久化。
4. 幂等表在工具结果返回 Runtime 前持久化。
5. 状态文件不存 secret。
6. 状态文件写入使用原子替换，避免测试台崩溃后写半截。
7. 启动时能列出可恢复的宿主会话。

完成标准：

- 测试台重启后能看到上次 Runtime 游标。
- 多实例状态不会合并。
- 幂等表可用于重连后的结果查询。

执行记录：

```text
状态：完成
进度：100%
记录：实现 HostRecoveryStateStore，按 runtimeInstanceId 哈希分文件保存 binding、协议、PID、Run/Session 和 lastConfirmedGsn，原子替换且禁止 GSN 回退；与 P1 RuntimeCursorStore、P2 ToolCallResultStore 共同组成恢复状态，均不保存 secret。
```

## 5. P3-04 恢复顺序实现

当前进度：100%

恢复顺序：

1. 用原实例信息重连。
2. 校验 PID、认证、实例、协议、能力。
3. 从持久化 `lastConfirmedGsn` 调用 `ReadEventsAsync`。
4. 按 `(runtimeInstanceId, gsn)` 去重。
5. 投影事件。
6. 投影成功后推进确认水位。
7. 查询 Run 终态。

执行步骤：

1. 实现恢复状态加载。
2. 实现重连后的 InstanceBinding 对比。
3. 实现事件去重集合。
4. 去重集合按 Runtime 实例隔离。
5. 对重放事件先查去重集合，再执行投影。
6. 工具事件重放时先查 P2 幂等表。
7. 投影成功后再确认。
8. 每一步都写入恢复时间线。

完成标准：

- 重放事件不会重复投影。
- 工具副作用不会重复执行。
- 水位只在处理成功后推进。

执行记录：

```text
状态：完成
进度：100%
记录：RecoveryEventConsumer 从持久 lastConfirmedGsn 读取，先校验 runtimeInstanceId，再按 GSN 去重、投影、SDK acknowledge、原子推进本地游标，最后识别目标 Run 终态。P2 幂等仓负责重放工具结果而不重执行。
```

## 10. P3-09 P3 验收用例

当前进度：100%

验收链：

1. P1 建立 RuntimeClient。
2. P2 准备一个会触发工具调用的 Run。
3. 工具调用返回并写入幂等表。
4. 延迟确认部分事件。
5. 主动断线。
6. 重连后从 lastConfirmedGsn 重放。

9. rehydrate/resume 后继续 Run。
10. 触发等待凭据状态。

- 工具副作用不因重放重复。
- 凭据续期后等待 Run 能恢复。
- Secret 全程不落明文。

## 2. P2-01 回调基础设施与注册

当前进度：100%

执行步骤：

1. 在 `RuntimeClientOptions.HostCallbacks` 中注册测试台回调对象。
2. 回调对象不要直接写控制台 UI，先进入回调协调器。
3. 定义统一的 `CallbackRequestEnvelope`，记录 RuntimeInstanceId、RunId、CallId、请求类型、到达时间。
4. 回调协调器把请求放入待处理队列。
5. 人工模式下，回调等待用户应答。
6. 策略模式下，回调按预设策略自动返回。
7. 所有回调异常都要转换为明确失败响应，不让异常逃逸终止事件循环。
8. 回调日志要脱敏。

完成标准：

- RuntimeClient 能带 callbacks 启动。
- 回调到来时能进入统一队列。
- UI 与 SDK 回调线程解耦。

执行记录：

```text
状态：完成
进度：100%
记录：实现 CallbackCoordinator，并通过 CreateCallbacks 把权限、审批、调用、查询、取消五类处理器注册到 RuntimeHostCallbacks。统一 envelope 不保存参数或 secret，异常转为保守响应。
```

## 6. P2-05 工具调用回调

当前进度：100%

请求类型：`ToolCallRequest`

执行步骤：

1. 展示工具名、参数、callId、RunId。
2. 判断工具是否有副作用。
3. 对同一 `(runtimeInstanceId, callId)` 查询幂等表。
4. 如果命中幂等表，直接返回首次持久化结果。
5. 如果未命中，进入人工执行或预设工具模拟。
6. 人工执行结果必须先写入幂等表，再返回给 Runtime。
7. 工具执行失败也写入幂等表，避免重放时重复副作用。
8. 结果中不写 secret。
9. 记录工具调用耗时。

完成标准：

- 工具调用能返回成功结果。
- 同一 callId 重复到达不会重复执行副作用。
- 失败结果也可被后续查询。

执行记录：

```text
状态：完成
进度：100%
记录：实现 ToolCallResultStore 和 ToolCallExecutionCoordinator。同一 (runtimeInstanceId, callId) 使用独立锁串行化，成功、失败、取消均先写临时文件并原子替换后再返回；结果文件以归属键 SHA-256 命名并校验内部归属。
```

## 7. P2-06 工具结果查询回调

当前进度：100%

请求类型：`ToolResultQueryRequest`

执行步骤：

1. 收到查询后按 `(runtimeInstanceId, callId)` 查幂等表。
2. 命中时返回已持久化结果。
3. 未命中时返回“未知结果”或协议允许的缺失响应。

6. 在 P3 重连演练中验证该能力。

完成标准：

- Runtime 能查询到已执行工具结果。
- 查询不会触发副作用。
- 查询结果和首次工具调用结果一致。

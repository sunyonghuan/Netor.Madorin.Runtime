# 路径权限检查问题分析

## 问题现象

**症状**：同一文件夹内，第一次删除操作成功，后续所有操作都报错：
```
The path is outside the allowed write roots.
```

## 根本原因分析

### 1. **路径比较逻辑不一致** ⚠️ 关键问题

系统中存在两个 `IsWithin` 方法，它们的大小写处理**不一致**：

#### `ToolGrantCalculator.cs:IsWithin` (权限计算)
```csharp
private static bool IsWithin(string root, string path)
{
    var relative = Path.GetRelativePath(Path.GetFullPath(root), Path.GetFullPath(path));
    return string.Equals(relative, ".", StringComparison.Ordinal)  // ❌ 始终区分大小写
        || (!Path.IsPathRooted(relative)
            && !string.Equals(relative, "..", StringComparison.Ordinal)
            && !relative.StartsWith($"..{Path.DirectorySeparatorChar}", StringComparison.Ordinal)
            && !relative.StartsWith($"..{Path.AltDirectorySeparatorChar}", StringComparison.Ordinal));
}
```

#### `BuiltinFsPathPolicy.cs:IsWithin` (权限验证)
```csharp
private static bool IsWithin(string root, string path)
{
    var comparison = OperatingSystem.IsWindows()
        ? StringComparison.OrdinalIgnoreCase  // ✅ Windows 不区分大小写
        : StringComparison.Ordinal;
    var relative = Path.GetRelativePath(root, path);
    return string.Equals(relative, ".", comparison)
        || (!Path.IsPathRooted(relative)
            && !string.Equals(relative, "..", comparison)
            && !relative.StartsWith($"..{Path.DirectorySeparatorChar}", comparison)
            && !relative.StartsWith($"..{Path.AltDirectorySeparatorChar}", comparison));
}
```

### 2. **权限交集计算可能错误缩小范围** ⚠️

`IntersectRoots` 方法在合并多个权限时：
```csharp
private static string[] IntersectRoots(string[] first, string[] second)
{
    var intersections = new HashSet<string>(PathComparer);
    foreach (var firstRoot in first)
    {
        foreach (var secondRoot in second)
        {
            if (IsWithin(firstRoot, secondRoot))
            {
                intersections.Add(Path.GetFullPath(secondRoot));
            }
            else if (IsWithin(secondRoot, firstRoot))
            {
                intersections.Add(Path.GetFullPath(firstRoot));
            }
        }
    }
    return intersections.Order(PathComparer).ToArray();
}
```

**问题**：
- 使用 `StringComparison.Ordinal`（区分大小写）判断路径包含关系
- 在 Windows 上，`C:\Temp` 和 `c:\temp` 应该相同，但会被认为不同
- 交集计算可能返回空数组，导致后续所有操作被拒绝

### 3. **PathComparer 与 IsWithin 不匹配**

```csharp
private static StringComparer PathComparer => OperatingSystem.IsWindows()
    ? StringComparer.OrdinalIgnoreCase  // Windows 不区分大小写
    : StringComparer.Ordinal;
```

- `PathComparer` 在 Windows 上不区分大小写
- 但 `IsWithin` 在 `ToolGrantCalculator` 中**总是区分大小写**
- 导致去重和包含判断使用不同的比较逻辑

## 可能的触发场景

### 场景 A：路径大小写变化
```
第一次：AllowedWriteRoots = ["E:\Netor.me\Project"]
第二次：新权限合并，路径变成 ["e:\netor.me\project"]
交集计算：IsWithin 认为两者不同 → 返回空集 → 所有操作被拒绝
```

### 场景 B：多次权限合并
```
权限1：AllowedWriteRoots = ["E:\Temp"]
权限2：AllowedWriteRoots = ["E:\Temp\SubDir"]
交集：应该是 ["E:\Temp\SubDir"]

如果路径大小写不一致：
权限1：["E:\Temp"]
权限2：["e:\temp\SubDir"]  
交集：IsWithin("E:\Temp", "e:\temp\SubDir") → false（区分大小写）
结果：空集 → 拒绝所有操作
```

## 跨平台问题

### Windows
- 文件系统不区分大小写
- `C:\Temp` == `c:\temp`
- 但 `IsWithin` 用 `Ordinal` 会认为不同

### Linux/macOS
- 文件系统区分大小写
- `/tmp/Test` != `/tmp/test`
- 当前逻辑对 Linux 是正确的

## 修复建议

### 修复 1：统一 IsWithin 实现（推荐）

将 `ToolGrantCalculator.IsWithin` 改为与 `BuiltinFsPathPolicy.IsWithin` 一致：

```csharp
private static bool IsWithin(string root, string path)
{
    var comparison = OperatingSystem.IsWindows()
        ? StringComparison.OrdinalIgnoreCase
        : StringComparison.Ordinal;
        
    var relative = Path.GetRelativePath(
        Path.GetFullPath(root), 
        Path.GetFullPath(path));
        
    return string.Equals(relative, ".", comparison)
        || (!Path.IsPathRooted(relative)
            && !string.Equals(relative, "..", comparison)
            && !relative.StartsWith($"..{Path.DirectorySeparatorChar}", comparison)
            && !relative.StartsWith($"..{Path.AltDirectorySeparatorChar}", comparison));
}
```

### 修复 2：路径规范化

在权限计算前，统一规范化所有路径：
```csharp
private static string NormalizePath(string path)
{
    var fullPath = Path.GetFullPath(path);
    return OperatingSystem.IsWindows() 
        ? fullPath.ToUpperInvariant()  // Windows 统一大写
        : fullPath;
}
```

### 修复 3：增加调试日志

在 `IntersectRoots` 和 `Resolve` 方法中添加日志，记录：
- 输入的根路径
- 计算的交集
- 被拒绝的路径及原因

## 测试用例

需要添加以下测试：

1. **大小写混合测试**（Windows）
   ```csharp
   AllowedWriteRoots = ["C:\\Temp"]
   RequestPath = "c:\\temp\\file.txt"  // 小写驱动器号
   预期：允许
   ```

2. **权限交集测试**
   ```csharp
   Grant1.AllowedWriteRoots = ["C:\\Project"]
   Grant2.AllowedWriteRoots = ["c:\\project\\src"]  // 不同大小写
   交集预期：["C:\\Project\\src"] 或 ["c:\\project\\src"]
   ```

3. **跨平台测试**
   - Linux：路径必须完全匹配（包括大小写）
   - macOS：同 Linux
   - Windows：不区分大小写

## 影响范围

- ✅ 读操作：受影响（`ResolveReadPath`）
- ✅ 写操作：受影响（`ResolveWritePath`）
- ✅ 删除操作：受影响
- ✅ 移动/复制：受影响

所有文件系统工具调用都会经过这个检查。

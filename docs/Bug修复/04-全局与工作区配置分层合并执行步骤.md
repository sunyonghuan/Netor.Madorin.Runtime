# 全局与工作区配置分层合并执行步骤

> 对应方案：[03-全局与工作区配置分层合并修复方案](./03-全局与工作区配置分层合并修复方案.md)
>
> 实施范围：仅独立 CLI 配置层；不修改 Client SDK、Contracts、Server、Provider Adapter 或宿主配置路径。
>
> 当前状态：实现、定向测试、完整构建、全量测试与独立 CLI 发布验证全部完成。

## 1. 配置契约与边界

- [x] 全局配置继续固定读取 `~/.madorin/config.json` 和 `~/.madorin/agents/*.json`。
- [x] 工作区配置只读取规范化工作区根下的 `.madorin/config.json`，不向父目录扫描，不自动创建文件或目录。
- [x] 工作区 Schema 只接受 `schemaVersion` 和 `selection.provider/model/agent`。
- [x] 缺失文件、JSON `null`、`{}`、缺失字段和字段 `null` 均表示继承。
- [x] 空白值、未知字段、非法 JSON 和不支持的 Schema 版本返回 `WorkspaceConfigurationInvalid`。
- [x] 反序列化前执行 64 KiB 上限检查；文件以共享只读方式打开。
- [x] 错误包含配置路径但不回显 JSON 正文或凭据。
- [x] 盘符根目录、包含空格及中文的工作区路径已覆盖。

## 2. 有效配置与选择

- [x] 新增 CLI 内部 `StandaloneConfigurationResolver` 和启动时配置快照。
- [x] Resolver 始终先严格加载并验证全局配置及全局 Agent，工作区配置不能掩盖全局错误。
- [x] Agent 优先级固定为：命令行 > 工作区 > 全局。
- [x] Provider 优先级固定为：命令行 > Agent 绑定 > 工作区 > 全局。
- [x] Model 优先级固定为：命令行 > Agent 绑定 > 工作区 > 全局。
- [x] 工作区显式 Agent/Provider 引用和最终 Provider/Model 组合经过校验。
- [x] 最终值携带 `commandLine`、`agent`、`workspace`、`global` 来源。
- [x] Resolver 不修改原始全局配置；REPL 持有启动时快照，不热更新配置文件。

## 3. CLI、REPL 与错误映射

- [x] `run` 和裸启动统一通过 Resolver 加载有效配置。
- [x] 文本模式全局配置缺失时仍进入原有首次配置向导。
- [x] JSON/JSONL 模式不启动交互向导，直接输出单一失败信封。
- [x] 配置及选择错误返回退出码 `2`。
- [x] 稳定错误码为 `ConfigurationNotFound`、`ConfigurationInvalid`、`WorkspaceConfigurationInvalid`、`WorkspaceSelectionNotFound`、`SelectionNotFound`。
- [x] REPL 列表继续来自全局 Provider/Agent 目录；工作区只影响初始 Selection。
- [x] `/provider`、`/model`、`/agent`、`/new` 不重新读取或写回工作区配置。
- [x] 欢迎界面显示最终 Provider、Model、Agent 和规范化工作区。

## 4. 展示与诊断

- [x] 不传 `--workspace` 时，`config show` 和 `config validate` 保持原有全局输出。
- [x] 显式传入 `--workspace` 时，文本输出显示全局路径、工作区路径、工作区配置存在状态及最终值来源。
- [x] 工作区模式 JSON 增加 `globalConfigPath`、`workspaceConfigPath`、`workspaceConfigExists` 和 `effectiveSelection`。
- [x] `doctor --workspace` 增加 `workspace-config` 和 `effective-selection` 检查。
- [x] 工作区配置缺失显示 `skipped`，不导致 Doctor 失败。
- [x] 无效 Schema、超限文件、无效引用和无效最终选择均可诊断，且不泄漏配置正文或凭据。

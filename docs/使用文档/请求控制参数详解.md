# 请求控制参数详解

> Expert 模式下对模型生成行为的精细控制

## 概述

`ExpertRequestControl`（简称 RequestControl）允许你在每次 Run 时覆盖默认的采样行为，而无需修改 Agent 的 System Prompt。

它适用于：
- 需要稳定输出的场景（低温度 + seed）
- 结构化输出（JSON / JSON Schema）
- 不同阶段使用不同创造力（规划用低温度，创意用高温度）
- 严格控制 token 消耗

## 完整字段列表

### 核心采样参数

| 字段               | 类型      | 默认 | 范围          | 说明 |
|--------------------|-----------|------|---------------|------|
| `Temperature`      | double?   | 1.0  | [0.0, 2.0]    | 采样温度。越低越确定，越高越随机 |
| `TopP`             | double?   | 1.0  | (0.0, 1.0]    | 核采样阈值。只考虑累计概率前 p 的 token |
| `TopK`             | int?      | -    | ≥ 1           | 只考虑概率最高的 K 个 token（部分 Provider 支持） |
| `MaxTokens`        | int?      | -    | ≥ 1           | 最大生成 token 数 |

### 惩罚与停止

| 字段                  | 类型       | 默认 | 范围       | 说明 |
|-----------------------|------------|------|------------|------|
| `FrequencyPenalty`    | double?    | 0    | [-2.0, 2.0] | 基于频率的惩罚，减少重复 |
| `PresencePenalty`     | double?    | 0    | [-2.0, 2.0] | 基于是否出现过的惩罚，鼓励新话题 |
| `StopSequences`       | string[]?  | -    | -          | 遇到这些字符串立即停止生成 |
| `Seed`                | int?       | -    | -          | 随机种子，用于可复现的生成（支持的 Provider） |

### 结构化与格式

| 字段               | 类型     | 说明 |
|--------------------|----------|------|
| `ResponseFormat`   | string?  | `"text"`（默认）或 `"json"` |
| `ResponseSchemaJson` | string? | 当使用结构化输出时的 JSON Schema（部分 Provider 支持） |

### 运行控制

| 字段          | 类型    | 说明 |
|---------------|---------|------|
| `Stream`      | bool?   | 是否使用流式响应。同步 HTTP 接口会强制为 `false` |
| `TimeoutMs`   | int?    | 本次 Run 的整体超时（毫秒） |
| `ReasoningEffort` | string? | 部分模型的思考强度控制（如 OpenAI o1 系列） |

## 最佳实践

### 1. 不同阶段用不同温度

```csharp
// 规划阶段
new ExpertRequestControl { Temperature = 0.2, MaxTokens = 2000 }

// 创意生成阶段
new ExpertRequestControl { Temperature = 0.9 }
```

### 2. 需要可复现结果时使用 Seed

```bash
madorin run --seed 42 --temperature 0.0 --input "..."
```

### 3. 控制成本

```csharp
new ExpertRequestControl
{
    MaxTokens = 1500,
    Temperature = 0.3
}
```

### 4. 结构化输出

推荐配合 `ResponseFormat = "json"`，并在 Prompt 中明确要求 JSON 结构。

部分 Provider 支持传入完整 JSON Schema（通过 `ResponseSchemaJson`）。

### 5. 同步场景必须设置超时

```http
POST /v1/run
X-Timeout-Seconds: 120
```

或在 `RequestControl.TimeoutMs` 中设置。

## 与 Agent 配置的关系

- Agent 中配置的 `Temperature` 是**默认值**
- `RequestControl` 中的同名字段会**覆盖** Agent 配置
- 推荐：Agent 里只放业务提示词，采样参数交给调用方通过 RequestControl 控制

## 常见问题

**Q: 设置了 Seed 还是不稳定？**  
A: 只有支持 seed 的 Provider + 模型才会真正确定性。OpenAI 部分模型、DeepSeek 部分模型支持较好。

**Q: TopP 和 Temperature 同时设置会怎样？**  
A: 大多数 Provider 同时生效，效果是叠加的。通常建议只强烈控制其中一个。

**Q: 同步接口还能拿到中间的 delta 吗？**  
A: 不能。同步接口只返回最终聚合后的 `Output`。如需中间过程，请使用流式 + 自己缓冲。

# 请求控制参数详解

> Expert 模式下对模型生成行为的精细控制

## 概述

`ExpertRequestControl`（简称 RequestControl）允许你在每次 Run 时覆盖默认的采样行为，而无需修改 Agent 的 System Prompt。

它适用于：
- 需要稳定输出的场景（低温度 + seed）
- 结构化输出（JSON / JSON Schema）
- 不同阶段使用不同创造力（规划用低温度，创意用高温度）
- 严格控制 token 消耗

## 完整字段列表（与源码 1:1）

`ExpertRequestControl` 实际定义了 **16 个字段**（全部可空）。

| 字段               | 类型                       | 说明（与源码一致） |
|--------------------|----------------------------|--------------------|
| `MaxTokens`        | int?                       | 最大生成 token 数 |
| `Temperature`      | double?                    | 采样温度 [0.0, 2.0] |
| `TopP`             | double?                    | 核采样 (0.0, 1.0] |
| `TopK`             | int?                       | Top-K（部分 Provider） |
| `StopSequences`    | string[]?                  | 停止序列 |
| `ToolUseMode`      | string?                    | auto / any / none / required:xxx |
| `ContentFilter`    | string?                    | default / strict / permissive |
| `ResponseFormat`   | string?                    | text / json |
| `Metadata`         | Dictionary<string,string>? | 仅追踪用，不发给模型 |
| `Stream`           | bool?                      | 流式偏好（同步接口强制 false） |
| `EnableThinking`   | bool?                      | 要求输出思考过程 |
| `PresencePenalty`  | double?                    | [-2.0, 2.0] |
| `FrequencyPenalty` | double?                    | [-2.0, 2.0] |
| `Seed`             | int?                       | 确定性种子 |
| `TimeoutMs`        | int?                       | 整体超时（毫秒） |
| `RetryPolicy`      | string?                    | default / none / aggressive |

**重要说明**（对应源码，2026-10-06 核对）：
- **中央映射**（MafSkillsAgentFactory.ApplyRequestControl）实际写到 `ChatOptions` 的字段只有 8 个：
  `Temperature`、`MaxTokens`、`TopP`、`TopK`、`StopSequences`、`FrequencyPenalty`、`PresencePenalty`、`Seed`。
- 其余字段（ToolUseMode、ContentFilter、Metadata、RetryPolicy、EnableThinking、Stream、TimeoutMs、ResponseFormat 等）在更高层使用（编排器、HTTP 同步端点、Selection）。
- 源码中**不存在** `ResponseSchemaJson` 和 `ReasoningEffort` 字段。
- 结构化输出请用 `ResponseFormat = "json"` + 在提示词里描述 JSON 结构。
- 思考过程控制请用 `EnableThinking`。

**说明**：
- `EnableThinking` 主要影响支持思考过程输出的模型（Anthropic、部分 OpenAI o1 类模型）。
- 即使 Provider 支持某字段，具体模型也可能有额外限制（例如某些模型强制 temperature=1）。

## 最佳实践

### 1. 不同阶段用不同温度

```csharp
// 规划阶段
new ExpertRequestControl { Temperature = 0.2, MaxTokens = 2000 }

// 创意生成阶段
new ExpertRequestControl { Temperature = 0.9 }
```

### 2. 需要可复现结果时使用 Seed

```bash
madorin run --seed 42 --temperature 0.0 --input "..."
```

### 3. 控制成本

```csharp
new ExpertRequestControl
{
    MaxTokens = 1500,
    Temperature = 0.3
}
```

### 4. 结构化输出

推荐配合 `ResponseFormat = "json"`，并在 Prompt 中明确要求 JSON 结构。

目前 `ExpertRequestControl` 没有独立的 schema 字段。更严格的结构化输出请通过提示词完整描述 JSON 结构 + `ResponseFormat = "json"` 实现。

### 5. 同步场景必须设置超时

```http
POST /v1/run
X-Timeout-Seconds: 120
```

或在 `RequestControl.TimeoutMs` 中设置。

## 与 Agent 配置的关系

- Agent 中配置的 `Temperature` 等是**默认值**
- `RequestControl` 中的同名字段会**覆盖** Agent 配置（仅对本次 Run 生效）
- 推荐：Agent 里只放业务提示词，采样参数交给调用方通过 RequestControl 控制

## 常见问题

**Q: 设置了 Seed 还是不稳定？**  
A: 只有支持 seed 的 Provider + 模型才会真正确定性。OpenAI 部分模型、DeepSeek 部分模型支持较好。

**Q: TopP 和 Temperature 同时设置会怎样？**  
A: 大多数 Provider 同时生效，效果是叠加的。通常建议只强烈控制其中一个。

**Q: 同步接口还能拿到中间的 delta 吗？**  
A: 不能。同步接口只返回最终聚合后的 `Output`。如需中间过程，请使用流式 + 自己缓冲。

**Q: ToolUseMode、ContentFilter、RetryPolicy 等字段怎么用？**  
A: 目前主要通过 SDK（`ExpertRequestControl` 对象）设置，CLI 暂未暴露全部高级字段。

# 场景推演与预期结果

[返回验证总览](./README.md)。本文件按设计基线推演行为；没有执行 CLI。`example`、示例模型及媒体地址均为受控说明，不宣称真实服务支持。

## 1. 推演方法

| 项目 | 口径 |
| --- | --- |
| 处理顺序 | 取得有效关联 ID、检查结构与路径 → 合并 argv → 确定任务/模型 → 校验源值 → 等价转换 → 丢弃剩余不支持项 → 默认值 → 目标校验 → Provider 映射。 |
| 文档可判定 | 在表中明确列出的 metadata 前提下，可以根据设计推导输出类型、状态、退出码和副作用边界；不表示实现通过。 |
| 待决 | 无法仅凭当前文档唯一确定实现；关联[问题清单](./03-问题与决策清单.md)。 |
| 待实现验证 | 文档已经给出行为，但必须有代码、工具链或真实平台后才能证明执行效果。 |
| 路径假设 | cwd 为授权根；请求 JSON 放在根内的 `requests/`，文件内相对路径从该目录解析。下表正常路径均位于授权根内。 |

## 2. 输入、转换与预检

| ID | 场景与前提 | 按现有设计推导的预期结果 | 文档结论 / 依据 |
| --- | --- | --- | --- |
| S01 | 请求 JSON 含中文、换行、引号和补充平面字符；长度与大小未超声明上限。 | 字符串原样进入有效参数；码点按 Unicode 标量计数，不翻译或截断。 | 文档可判定；2.3、2.9、3.1、3.6。 |
| S02 | 两张 `reference` 图片生成一张图片；所选 `image-edit` 任务支持两图。 | 保留附件 ID、顺序和用途，进入编辑映射；不能自动缩成一张输入。 | 文档可判定；2.2、2.3、2.7。 |
| S03 | 两张 `reference` 图片生成视频；所选 `image-to-video` 任务明确支持该角色和数量。 | 映射到该模型的多图参考视频接口；不解释成时间轴，也不自动当首尾帧。 | 文档可判定；2.2、2.3。实际厂商证据见映射表。 |
| S04 | `first-last-frame` 提供首尾帧；目标只有普通参考图能力。 | 不改任务；目标不支持该任务则失败，不能将末帧用途降级后声称满足原任务。 | 文档可判定；2.2、2.7、2.8。 |
| S05 | 文件 `prompt=A`，argv 显式 `--prompt B`；其他字段未显式覆盖。 | 采用 B；默认值不能覆盖文件，附件和对象按整体替换处理。被覆盖的 A 不进入输入回显。 | 文档可判定；2.3、2.9。 |
| S06 | 文件已有附件数组，argv 提供一个 `--attachment`。 | 数组整体替换成 argv 数组；不是追加文件附件。路径分别按实际来源确定基准。 | 文档可判定；2.3。 |
| S07 | 文件和 argv 都提供同一个有效请求 ID。 | 接受该 ID；响应原样回传。不同值时返回 `invalid_parameter`，采用有效 argv ID 关联错误。 | 文档可判定；3.0。 |
| S08 | JSON 无效，但 argv 提供单个合法请求 ID。 | 参数错误仍回传 argv ID；没有合法 argv ID 时不能扫描坏 JSON 猜 ID，返回 `response_id=null`。 | 文档可判定；3.0、3.7。 |
| S09 | 文件直接携带 `api_key` 或 `api_url`，即使 argv 已另行提供。 | 拒绝文件认证/连接配置且不回显原值；不能按覆盖或兼容丢弃绕过。 | 文档可判定；2.3、2.8。 |
| S10 | 文件有未知根字段；或只有 `parameters` 中出现无支持、无转换规则的未知项。 | 未知根字段失败；后者仅记录丢弃路径，不回显未知值。 | 文档可判定；2.8。 |
| S11 | argv 有未知选项；或已知生成选项当前模型不支持且无转换规则。 | 未知选项失败；已知生成选项按兼容规则处理。不适用的控制选项仍失败。 | 文档可判定；2.1、2.4、2.8。 |
| S12 | 目标支持 `size`，规则将 `width=1024,height=1024` 转成 `size=1024x1024`。 | 一项成功转换，源字段不计丢弃；有效参数只保留目标尺寸表达。 | 文档可判定；2.7。 |
| S13 | S12 同时显式提供 `size=512x512`；或只给 `width`。 | 冲突或缺少声明必需组合均失败；不能丢弃问题字段后继续。 | 文档可判定；2.7。 |
| S14 | 只有比例 `16:9`，目标仅支持像素尺寸，且没有固定对应规则。 | 不猜分辨率；若无原生支持及等价用法则丢弃该可选生成项。 | 文档可判定；2.7。丢弃后意图是否可接受由调用方判断。 |
| S15 | 某支持项或转换源类型非法；另有完全不支持的生成项。 | 支持项的非法值报错；不能借另一项可丢弃来跳过错误。 | 文档可判定；2.7、2.8。 |
| S16 | 文件大小超过 metadata 上限；重复 JSON 键；未知请求版本。 | 拒绝，不截断、不自动选取重复键中的某一个。已取得有效 argv ID 时继续回传。 | 文档可判定；2.3、3.0。 |
| S17 | 附件 `source` 同时含 `path`、`uri`；附件 ID 重复；受支持角色数量超上限。 | 均失败；不靠删除附件来满足约束。 | 文档可判定；2.3、2.8、3.1。 |
| S18 | 不支持的附件角色指向授权根外；或输出祖先链接指向根外。 | 路径越界先失败，不能因附件最终会被丢弃而绕过边界。 | 文档可判定；2.3、2.8。链接竞态防护待实现验证。 |
| S19 | 有效 `--try-run`，API Key 为占位值，附件为本地路径。 | 只读 JSON 和路径元数据，正式映射器输出逻辑媒体引用；不读媒体、不联网、不写文件。 | 文档可判定；2.9。占位值仍固定脱敏。 |
| S20 | S19 改变 `--verbose`；其他有效输入相同。 | 业务请求、Provider 映射、产物和正式响应业务结果相同；try-run 的 `input_parameters.execution.verbose` 与 `effective_parameters.execution.verbose` 按开关分别回显，stderr 仍为空。 | 设计已修订；待实现验证。 |
| S21 | 提示词在进入 CLI 之前已变成另一串合法 Unicode。 | UTF-8 往返仍可能为 true；只能核对接收值和码点，不能据此保证原始中文正确。 | 文档可判定；2.9。 |
| S22 | API Key、签名 URI 或标记敏感的嵌套字段进入预检。 | 固定脱敏，不生成可还原秘密的码点、长度或预览值；未识别/被丢弃项只记录路径。 | 文档可判定；2.7、2.9、3.6。 |

## 4. 完整请求与预检响应示例

本节是对字段完整性的人工推演，不是运行结果。假定示例技能默认模型为 `example-image-v1`，任务 `image-edit` 支持两个 HTTPS reference、输出数量 1、`size=1024x1024`，实现 `dimensions_to_size`，其他生成项无支持且无转换。所有路径均在授权根内。

### 4.1 请求文件

文件为 `requests/edit.json`；调用参数另行提供 `--request-id req-doc-001`、`--api-key dry-run-placeholder`、`--try-run`。API 地址采用该示例技能声明的默认地址。

```json
{
  "schema_version": "1.0",
  "task": "image-edit",
  "prompt": "融合两张参考图，保留中文招牌\n写上：\"春天\"。",
  "attachments": [
    { "id": "front", "role": "reference", "source": { "uri": "https://example.test/front.png" } },
    { "id": "side", "role": "reference", "source": { "uri": "https://example.test/side.png" } }
  ],
  "parameters": { "width": 1024, "height": 1024, "num_images": 1, "unmapped_option": "ignored example" },
  "execution": { "output_dir": "./artifacts" }
}
```

### 4.2 完整预检信封与字符串检查的展示方式

为避免将一长串所有字符串的码点人工抄写成另一个错误来源，下列报文使用一个更小的直接输入场景核对完整信封：同一示例技能支持 `text-to-image`，直接模式仅显式传 `--request-id r1 --prompt 中 --output-dir o --api-key dry-run-placeholder --try-run`，不传文件。示例本地默认模型为 `example-image-v1`。只有输入回显中的非敏感字符串进入 unicode_checks；有效参数补入的默认字符串不进入。

```json
{
  "schema_version": "1.0",
  "response_id": "r1",
  "status": "validated",
  "mode": "try_run",
  "provider": "example",
  "model": "example-image-v1",
  "input_parameters": {
    "request_id": "r1",
    "prompt": "中",
    "execution": { "output_dir": "o", "try_run": true },
    "api_key": "<redacted>"
  },
  "effective_parameters": {
    "schema_version": "1.0",
    "request_id": "r1",
    "task": "text-to-image",
    "model": "example-image-v1",
    "prompt": "中",
    "attachments": [],
    "parameters": { "num_images": 1 },
    "provider_parameters": {},
    "execution": { "output_dir": "o", "timeout": 300, "no_wait": false, "try_run": true, "verbose": false, "output_format": "json" },
    "api_url": "https://api.example.test/v1",
    "api_key": "<redacted>"
  },
  "credential_presence": { "api_key": true },
  "request_preview": { "model": "example-image-v1", "prompt": "中", "n": 1 },
  "unicode_checks": [
    { "parameter": "/request_id", "display_value": "r1", "unicode_codepoints": ["U+0072", "U+0031"], "utf8_roundtrip": true },
    { "parameter": "/prompt", "display_value": "中", "unicode_codepoints": ["U+4E2D"], "utf8_roundtrip": true },
    { "parameter": "/execution/output_dir", "display_value": "o", "unicode_codepoints": ["U+006F"], "utf8_roundtrip": true }
  ],
  "errors": [],
  "ignored_parameters": [],
  "converted_parameters": [],
  "side_effects": { "network_request": false, "output_files_written": false, "directories_created": false }
}
```

请求预览中的字段是示例 Provider 的私有请求形状，不是公共 DTO 的新增字段。正式多图场景必须使用实际 Provider 的媒体引用/实体化机制，不能照搬本示例中的纯文本请求体。

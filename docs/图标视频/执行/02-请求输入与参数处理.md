## 3. 输入处理顺序

| 顺序 | 处理 | 关键约束 |
| --- | --- | --- |
| 0 | 识别命令并启动预算 | 记录单调 t0，后续文件 timeout 确定仍从此起算；不得在媒体准备或提交时重新计时。 |
| 1 | 提取关联 ID | 先取得命令级及文件顶层 ID；合法 ID 后续失败仍回传；不能扫描坏 JSON 猜 ID。 |
| 2 | 解析 argv | 校验命令、选项和值；凭证仅内存使用，不能写日志或请求对象文件。 |
| 3 | 加载文件 | 校验 cwd 边界、大小、UTF-8 和 JSON；生成文件目录仅为内部相对路径基准，query/download 只加载任务上下文。按设计第 5 节确定/追溯预算。 |
| 4 | 合并来源 | 直接显式值覆盖普通同字段；对象及附件数组整体替换；`request_id` 两来源必须逐字相同。 |
| 5 | 路由选择 | 按合并后的显式 task、metadata 默认和唯一候选选择 task；model 按 `--model` → 文件 model → 任务默认 → 唯一候选选择。最终值无效则立即失败；被覆盖的旧模型不校验或回显。 |
| 6 | 校验源值 | 已支持或有转换规则的项必须解析类型、范围和组合；未知 argv 选项不能进入丢弃分支。 |
| 7 | 转换 | 只应用已声明可靠规则；先校验源、再转换、再校验目标；不同结果写同一目标时报错。 |
| 8 | 过滤 | 剩余无原生支持且无等价转换的生成项和附件角色才记录丢弃；协议/控制项不能过滤。 |
| 9 | 默认与目标校验 | 补确定性默认，校验最终 task/model/参数/附件限制；不猜 Provider 未声明默认。 |
| 10 | 生成有效对象 | 提供 P3 统一输出和 P4 Provider 映射所需的 `input_parameters`、`effective_parameters`、记录和来源信息。 |

## 4. 路径、附件与秘密

| 范围 | 实施要求 |
| --- | --- |
| 授权根 | 宿主启动进程时固定 cwd；请求文件、argv 路径、附件本地路径和输出目录都必须规范化并按路径组件核对，不能只做字符串前缀比较。 |
| 链接处理 | 读取媒体、创建输出目录和写文件前重新解析现存祖先的符号链接/重解析点；目标越界立即失败。 |
| try-run | 仅可查路径和链接元数据；不读媒体字节，不验证真实读写权限，不创建目录。 |
| 附件 | `id` 唯一，角色、数量、MIME 和单文件上限由任务声明；`path`/`uri` 恰有一个。不能把本地路径当远端 URL。 |
| 简写 | 参考图、图片 URL、首尾帧按方案映射；不能与 `--attachment` 混用，不能使用过滤后的数组索引代替附件 ID。 |
| 认证 | 请求 JSON、`parameters`、Provider 扩展和产物中禁止 API 地址、Key、令牌及其他认证设置；本地缺失/格式错误和远端拒绝分属不同错误码。 |
| 任务恢复 | task_context 只保存恢复状态，API 基础地址和认证仍 argv；带授权意义的 polling_url 仅按设计第 2.10 节在结构化恢复字段和受限文件往返，不输出诊断/回显。 |
| 回显 | 用户来源路径按安全写法回显，不暴露内部绝对路径；敏感字段固定 `<redacted>`，不输出长度、码点或可逆摘要。 |

## 5. 转换与过滤记录样例规则

| 记录 | 路径基准 | 需保证 |
| --- | --- | --- |
| `converted_parameters[].source_parameters` | 合并后、转换过滤前输入；附件保留原始索引 | 使用稳定规则 ID，记录源语义，不输出源秘密。 |
| `converted_parameters[].target_parameters` | `effective_parameters` | 记录实际生效目标；目标值经过目标 Schema 校验。 |
| `ignored_parameters[].parameter` | 合并后、转换过滤前输入 | RFC 6901 转义；已转换子字段和未使用子字段分开，附件用原始索引。 |
| `unicode_checks[].parameter` | 实际 `input_parameters` | 过滤后回显坐标；附件必要时保留 `id` 关联，排除敏感值和签名 URI。 |

禁止把以下情况写为 `ignored_parameters`：非法 JSON/请求版本、未知控制字段、无效 task/model、认证本地格式、路径越界、支持项非法值、转换冲突、已声明组合缺项和未知 argv 选项。

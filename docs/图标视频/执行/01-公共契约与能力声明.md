## 3. 契约交付清单

下表是实现覆盖索引，不另起一套字段定义；完整类型、必需性和说明以方案相应表格为准。

| 对象 | 必须覆盖的组成 | 实现注意事项 | 方案位置 |
| --- | --- | --- | --- |
| 统一生成请求 | `schema_version`、`request_id`、`task`、`model`、`prompt`、`attachments`、`parameters`、`provider_parameters`、`execution`。 | 文件内不接受连接或认证配置；直接模式内部补请求版本。 | 第 2.3 节 |
| 附件 | `id`、`role`、恰有一个 `path` 或 `uri` 的 `source`。 | 唯一 ID、顺序和角色语义保留；不增加自由文本附件结构或 base64 文件入口。 | 第 2.3 节 |
| 能力描述 | `SkillMetadata`、`commands`、`authentication`、`models.tasks`、参数定义和附件限制。 | 本地模型清单不是账号远端可用性保证；嵌套对象/数组须有具体 Schema 和中文字段说明。 | 第 3.1、3.2 节 |
| 转换 / 过滤 | `parameter_conversions`、`converted_parameters`、`ignored_parameters`。 | 稳定规则 ID、RFC 6901 路径；记录中不保存未知值或秘密原值。 | 第 2.7、2.8 节 |
| 版本信息 | `VersionInfo`。 | CLI 语义版本与 JSON 契约版本独立；`runtime` 表示实际运行产物类型。 | 第 3.3 节 |
| 本地产物 | `GenerateResponse`、`artifacts`、`provider_metadata`、逐槽位 `errors`。 | 产物包含请求 `index`、相对路径、实际 MIME/格式/字节数和适用媒体信息。 | 第 3.4、3.8 节 |
| 远端任务 | `TaskResponse`、`TaskContext`、任务上下文必需性和内嵌 Schema。 | `task_id` 是任务句柄，`provider_metadata.request_id` 仅追踪；恢复对象保存原任务/模型/全部槽位和必要私有状态。 | 第 2.10、3.1、3.5 节 |
| 取消控制 | stdin UTF-8 单行 cancel 对象。 | 三个固定字段、调用 ID 一致、帧上限、EOF/非法消息与单终态规则按设计，不新增公共 cancel 命令。 | 第 2.11 节 |
| 试运行 | `TryRunResponse`、`unicode_checks`、`credential_presence`、校验 `errors`、`side_effects`。 | 预览可为 null；三个副作用标志固定 false；敏感值不得通过码点泄漏。 | 第 3.6 节 |
| 公共失败 | 失败信封、task_id、task_context、公共 `error` 和安全 `provider_error`。 | 已知任务/完整上下文保留，无值为 null；provider_error 仅 code/安全 message，未知受理不承诺安全重试。 | 第 3.7 节 |

## 4. Schema 与版本实施规则

| 事项 | 执行要求 |
| --- | --- |
| 公共结构 | 根字段、`execution`、附件及 `source` 拒绝未知字段；`parameters` 和 Provider 参数保留未知项供转换与过滤，不能在公共 Schema 提前全盘拒绝。 |
| 分层校验 | 值 Schema 校验参数值，`source_schema` 校验转换前源输入，`validation_schema` 校验转换后的有效对象；Schema 不注入默认值，也不执行转换。 |
| 支持子集 | 完整覆盖方案第 3.1 节列出的类型、结构、范围、数量、组合和条件关键字；允许 `description`、布尔 `sensitive` 注解。拒绝未列关键字和 `$ref`，不通过下载 Schema 补能力。 |
| 数值与文本 | integer 使用整数词法；number 有限且不溢出。Schema 字符串长度按 Unicode 码点而非 UTF-16 单元计数。 |
| 版本分离 | 生成请求、CLI 响应、TaskContext、stdin 控制各自初版字符串 `1.0`；发布清单和记录初版整数 `1`，各自独立维护。 |
| 能力一致性 | 默认任务/模型须存在且兼容；参数 argv 名与请求路径冲突须拒绝，只有方案规定的附件入口/简写例外。 |
| 公开能力 | 本阶段可用受控夹具验证契约，但夹具不是实际技能能力；P4/P5 完成后才把对应实现列入可发布 metadata。 |

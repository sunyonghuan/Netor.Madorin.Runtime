## 4. 全阶段不可变约束

| 主题 | 必须保留的规则 | 方案依据 |
| --- | --- | --- |
| 名称 | `skill-<provider>-<capability>`；技能 ID、无扩展名程序名、清单名、技能目录名和 YAML `name` 一致；项目不插入 `Skills` 段。 | 第 1、7 节 |
| 输入与认证 | 生成支持统一 JSON 文件并保留直接参数；地址和认证只 argv。查询/下载按声明增加 `--task-context-file`，上下文不是连接配置或生成文件。 | 第 2.1、2.3、2.10 节 |
| 模型选择 | 主程序跨 CLI 生成显式传 `--model`；通用文件建议省略模型、调用 ID 和输出目录。模型按 argv、文件、兼容默认选择，非空且无控制字符即原样提交；目录从目标 API 获取，不设置静态模型白名单；查询/下载恢复原模型。 | 第 2.1 至 2.3、2.9、2.10 节 |
| 关联与恢复 | `response_id` 原样等于有效 `request_id`；远端任务 `task_id` 与 `provider_metadata.request_id` 追踪分离，失败保留已知任务和完整上下文，不提供幂等承诺。 | 第 2.10、3.0、3.4、3.5、3.7 节 |
| 参数保留 | 原生支持优先，再做已声明的可靠等价转换，最后才丢弃；非法源值、目标冲突、协议与控制错误不能转为丢弃。 | 第 2.7、2.8 节 |
| 预检 | 正式生成与 try-run 共用处理管线和 Provider 映射器；try-run 仅可读取请求 JSON 及路径元数据，不联网、不读媒体、不写文件。 | 第 2.9、3.6 节 |
| 安全 | cwd 为授权根；文件相对路径基准不扩大授权范围。秘密递归脱敏，不出现在诊断、预览、码点或发布包内。 | 第 2.3、2.9、6 节 |
| 输出与状态 | stdout 只有一个 UTF-8 JSON；远端成功不等于本地落盘，超时/取消不被部分成功覆盖。 | 第 3 至 5 节 |
| 诊断与取消 | verbose 不改变生成请求/业务结果，try-run 如实回显控制值且 stderr 为空；stdin 仅接取消帧，总时限从识别命令起覆盖全部阶段，最多额外 5 秒清理。 | 第 2.9、2.11、5 节 |
| 发布 | 完整技能发布到 `skills/<skill_name>/`，CLI 只放 `runtime/<RID>/`；逐项暂存替换，不覆盖无关技能，不把 RID 可选等同于跨平台通过。 | 第 7 节 |

## 5. 进度与证据维护

| 记录项 | 维护规则 |
| --- | --- |
| 任务状态 | 阶段任务表用 `[×]` 表示未完成，`[√]` 表示已完成；未开始、执行中、待确认原因写入本阶段执行记录。 |
| 完成条件 | 对应工作已经交付且本阶段完成门禁满足才勾选。只编写实现、只生成模板或只做模拟检查不能替代相应验证证据。 |
| 进度计算 | 每阶段 6 项任务，按已完成项计算百分比；总览累计 48 项。更新阶段标题、阶段表和总览，不能只改其中一处。 |
| 不适用项 | 保留原任务 ID，写明对应技能、方案依据和确认结果；该项所要求的能力边界已落实后才可结项，不直接删任务凑进度。 |
| 批次范围 | 在 P0 登记本批全部技能。每项任务覆盖本批适用技能后才能勾选，部分技能完成时仅记录明细。 |
| 证据内容 | 记录实际修改路径、命令或检查方式、结果、覆盖范围和未验证项；不把计划命令写成已执行证据。 |
| 未解决事项 | 写清问题、影响阶段及需要谁确认。缺少平台或账号时如实保留待验证项，不宣称全部完成。 |
| 续接入口 | 从首个未完成且依赖已满足的任务继续；先读最新方案、阶段记录及受影响目录 README。 |

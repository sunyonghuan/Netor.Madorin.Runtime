# 动态模型目录与模型白名单修正

依据：[最新设计方案](../策划/技能CLI设计方案.md)第 2.2.1、3.1、3.2 节。用户确认模型由目标 API 返回，CLI 不应以写死名称限制新模型。本批修正 OpenAI、Grok 及公共模型目录能力，不修改宿主 Runtime 或发布脚本。

## 问题与修正

| 项目 | 原问题 | 本批交付 |
| --- | --- | --- |
| 目录来源 | list-models 返回源码内置模型，误作为可用目录。 | 使用本次 API 地址和凭证访问 GET models；原样保留服务 ID，不按名称筛选，错误不静态回退。 |
| 模型校验 | 新的 gpt-image-2 在本地被拒绝，未提交服务。 | 只校验模型非空且无控制字符，支持部署名、别名及未来 ID；argv → 文件 → 兼容默认，原样传递。 |
| 协议能力 | metadata.models 混淆本地实现和远端模型事实。 | metadata 离线返回 models=[]、顶层 tasks 与 model_discovery；目录模型 tasks=null 表示服务未提供可靠能力。 |
| 调用边界 | 本地未知模型被当作不支持。 | 生成不强制目录预查询，不因目录缺项阻止提交；远端拒绝按实际响应映射，不换模型或重发。 |
| 公共复用 | 各项目容易重复模型白名单逻辑。 | Core 中 ModelIds、ModelListOptions、ModelCatalogResponse 复用 ID 结构、连接预算和目录规范化；HTTP 与认证细节留在 Provider。 |
| 文档 | 设计和执行任务要求本地模型清单校验。 | 同步设计、agents.md、根/专项/项目 README、技能源说明、协议引用和 S23、S40–S42 场景；旧批次记录注明已被修订。 |

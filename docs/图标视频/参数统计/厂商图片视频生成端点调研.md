# 各厂商图片/视频生成 API 端点调研

## 调研目的
确认各大模型供应商的图片、视频生成 API 端点地址和参数结构，判断是否能统一到 Provider 模式。

## 现有 Provider 能力声明
当前 `ProviderCapabilities` 定义中：
- `Vision`: 支持图片输入（理解图片）
- 无 `ImageGeneration`/`VideoGeneration` 字段

## 待调研厂商清单

### 1. OpenAI
- **文本对话**: `/v1/chat/completions`
- **图片生成**: `/v1/images/generations`
  - 模型: `dall-e-3`, `dall-e-2`
  - 参数: prompt, size, quality, style, n
  - 文档: https://platform.openai.com/docs/guides/image-generation
- **视频生成**: ❌ 暂不支持

### 2. Anthropic
- **文本对话**: `/v1/messages`
- **图片生成**: ❌ 不支持
- **视频生成**: ❌ 不支持

### 3. Azure OpenAI
- **文本对话**: `/openai/deployments/{deployment-id}/chat/completions?api-version=...`
- **图片生成**: `/openai/deployments/{deployment-id}/images/generations?api-version=2024-10-21`
  - 模型: `gpt-image-*` 系列（dall-e-3 已于 2026-03-04 退役）
  - 参数: 与 OpenAI 类似
  - 文档: https://learn.microsoft.com/en-us/rest/api/azureopenai/images/generate
- **视频生成**: ❌ 暂不支持

### 4. Google Gemini
- **文本对话**: OpenAI 兼容端点或原生端点
- **图片生成**: Vertex AI Imagen API 或 Gemini 3.1 Flash Image
  - 端点: Vertex AI 特定端点（**非 OpenAI 兼容**）
  - 注意: Imagen 4 将于 2026-08-17 关闭，迁移至 Gemini 3.1 Flash
  - 文档: https://ai.google.dev/gemini-api/docs/image-generation
- **视频生成**: 待查

### 5. 阿里云（Aliyun）
- **文本对话**: OpenAI 兼容端点
- **图片生成**: **通义万相** - **多个独立 API**
  - 文生图: `https://dashscope.aliyuncs.com/api/v1/services/aigc/text2image/image-synthesis`
  - 图像编辑、局部重绘、涂鸦作画等**多个独立端点**
  - **参数结构**: 与 OpenAI **完全不同**，使用阿里云特定参数
  - 文档: https://help.aliyun.com/zh/model-studio/wan-image-generation-api-reference
- **视频生成**: 待查

### 6. 火山方舟（Volcanoark）
- **文本对话**: OpenAI 兼容端点
- **图片生成**: **Seedream 模型**
  - 通过火山引擎方舟平台 **API v3** 调用
  - **参数结构**: 与 OpenAI **不同**
  - 需要 `ARK_API_KEY` 认证
- **视频生成**: **Seedance 2.0/2.5 模型**
  - 支持文生视频、图生视频
  - **异步任务模式**：提交任务后需轮询获取结果
  - 支持多模态输入

### 7. 腾讯云
- **文本对话**: 混元对话 API
- **图片生成**: **混元生图** - **多个版本，不同端点**
  - 极速版: `aiart.tencentcloudapi.com`
  - 轻量版: `hunyuan.tencentcloudapi.com`
  - 标准版: 分为**提交任务**和**查询任务**两个接口
  - **参数结构**: 腾讯云 API 3.0 规范，与 OpenAI **完全不同**
  - 文档: https://cloud.tencent.com/document/product/1729/105969
- **视频生成**: 待查

### 8. DeepSeek
- **文本对话**: OpenAI 兼容端点
- **图片生成**: ❌ 不支持
- **视频生成**: ❌ 不支持

### 9. Kimi
- **文本对话**: OpenAI 兼容端点
- **图片生成**: ❌ 不支持
- **视频生成**: ❌ 不支持

### 10. GLM (智谱)
- **文本对话**: OpenAI 兼容端点
- **图片生成**: **CogView-4**
  - 端点: `https://open.bigmodel.cn/api/paas/v4/images/generations`
  - 模型: `cogview-4`
  - 参数: prompt, size, model
- **视频生成**: **CogVideoX**
  - 端点: `https://open.bigmodel.cn/api/paas/v4/videos/generations`
  - 模型: `cogvideox` 系列
  - 支持文生视频、图生视频

## 调研结论

### 核心发现

1. **端点地址完全异构**
   - OpenAI/Azure: `/v1/images/generations` 或 `/openai/deployments/{id}/images/generations`
   - 阿里云: `https://dashscope.aliyuncs.com/api/v1/services/aigc/text2image/image-synthesis`
   - 腾讯云: `aiart.tencentcloudapi.com` 或 `hunyuan.tencentcloudapi.com`
   - 智谱: `https://open.bigmodel.cn/api/paas/v4/images/generations`
   - 火山方舟: 方舟平台 API v3
   - Google: Vertex AI 专有端点

2. **参数结构差异巨大**
   - OpenAI: `{ prompt, model, size, quality, style, n }`
   - 阿里云: 使用阿里云特定参数结构（与 OpenAI 完全不同）
   - 腾讯云: 腾讯云 API 3.0 规范（签名、认证机制不同）
   - 火山方舟: ARK_API_KEY 认证，参数结构独立

3. **协议兼容性假象**
   - **文本对话兼容 ≠ 图片/视频兼容**
   - 阿里云、火山方舟、智谱虽然文本对话支持 OpenAI 协议，但图片/视频生成使用完全独立的 API
   - 即使同样声称"兼容 OpenAI"，图片生成端点也各不相同

4. **任务模式差异**
   - **同步模式**: OpenAI, Azure OpenAI, 智谱 CogView
   - **异步模式**: 腾讯云（提交任务 + 查询任务分离），火山方舟视频生成（需轮询）

5. **能力覆盖**
   - 支持图片生成: OpenAI, Azure OpenAI, 阿里云, 腾讯云, 智谱, 火山方舟, Google
   - 支持视频生成: 智谱 CogVideoX, 火山方舟 Seedance
   - 不支持: Anthropic, DeepSeek, Kimi

### 对架构方案的影响

**Provider 内部路由方案的致命问题**：
- ❌ 无法在一个 `OpenAIProviderAdapter` 内部路由阿里云、火山方舟、腾讯云的图片生成
- ❌ 即使创建 `AliyunProviderAdapter`，其文本对话走 OpenAI 兼容端点，但图片生成需要完全不同的 HTTP 客户端配置、认证方式和参数结构
- ❌ 阿里云的"万相"有多个独立端点（文生图、图像编辑、局部重绘），无法用单一端点表达

**技能模式（独立 CLI）的优势验证**：
- ✅ 每个平台的图片/视频生成封装为独立技能 CLI
- ✅ 技能内部处理该平台特有的端点、参数、认证、异步轮询
- ✅ 主程序通过统一的技能接口调用，无需知道具体协议细节
- ✅ 新增平台（如火山方舟视频生成）只需添加新技能，主程序零修改

### 推荐方案

**采用技能模式（独立 CLI 程序）**，原因：
1. 图片/视频生成的端点、参数、认证完全异构，无法归一化
2. 异步任务模式（轮询）在某些平台是必需的，无法用同步接口统一
3. 单次生成耗时长（几秒到几分钟），进程启动开销可忽略
4. 扩展性：新增平台无需修改主程序

**下一步**：
- 在 `agents.md` 中新增"技能契约"章节，规定技能 CLI 的输入/输出格式、错误码、取消协议
- 设计第一个技能 CLI 作为模板（建议从 OpenAI DALL-E 开始）
- 定义技能元数据格式与发现机制

### 🎯 核心发现汇总

**参数覆盖率**:
- ✅ `prompt` (100%)
- ✅ 尺寸控制 (100%, 三种模式: size / aspect_ratio / width+height)
- ✅ `negative_prompt` (44% - Stability AI, 阿里云, 腾讯云, Replicate)
- ✅ `seed` (55% - Stability AI, 阿里云, 腾讯云, Replicate, BFL FLUX)
- ✅ `reference_images` (55% - Stability AI, xAI, 阿里云, Replicate, BFL FLUX)
- ✅ `num_images` (66%)

**认证方式**:
- Bearer Token (88% - OpenAI, Azure, 智谱, Stability, xAI, 阿里云, Replicate)
- TC3 签名 (腾讯云)
- X-Key (BFL)

**任务模式**:
- 同步: 55% (OpenAI, Azure, 智谱图片, Stability, 阿里云可选, 腾讯云极速/轻量)
- 异步: 45% (智谱视频, xAI 视频, 阿里云可选, 腾讯云标准, Replicate, BFL FLUX)

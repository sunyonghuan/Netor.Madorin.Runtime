# 快手可灵 / 可图执行计划

## 1. 计划定位

本计划用于接入快手可灵 AI 开放平台的图片与视频生成协议，依据：

- [图片/视频技能 CLI 统一架构与协议方案](./技能CLI设计方案.md)
- [快手可灵/可图参数参考](../参数统计/10-快手-可灵可图.md)
- [图片/视频技能 CLI 执行总览](../执行/README.md)
- [Multimedia 工作目录约束](../../../src/Multimedia/README.md)

本计划只登记执行顺序、核对门禁、交付物和验证要求，不改变公共 CLI 契约，也不授权自动调用付费 API、修改 Runtime 或发布技能包。

参考文档只作为接入线索。模型名称、端点、认证、请求字段、任务状态、错误码和价格，以 2026-11-10 核对的现行官方文档为准。参数统计稿中的 `kling-3.0-omni`、`/api/v1/videos/{job_id}`、`quality=4K`、`native_audio` 和简单 Bearer 静态密钥假设均已失效，不能直接进入实现。

## 2. 官方核对与能力边界

核对日期：2026-11-10。文档站点为 [可灵 AI 开放平台](https://klingai.com/document-api)。页面正文由站点打包的现行接口模块提供，不以参数统计稿代替。

| 主题 | 现行结论 |
| --- | --- |
| 调用域名 | 中国区 `https://api-beijing.klingai.com`；新加坡 `https://api-singapore.klingai.com`。旧域名 `https://api.klingai.com` 已变更。CLI 默认中国区根地址，调用方可用 `--api-url` 覆盖。 |
| 认证 | 新系统使用 API Key，请求头 `Authorization: Bearer <API Key>`。Access Key / Secret Key 的 JWT 只适用于模型放在 `model_name` 参数中的旧版接口。本批只实现 API Key，不在 CLI 内签发 JWT，也不把密钥写入请求文件。 |
| 模型目录 | 官方文档索引未给出通用模型目录端点。`list-models` 返回 `provider_error`，不回退静态清单。模型 ID 原样提交，不做本地白名单。 |
| 图片 | 现行图像生成仍是旧版设计：`POST /v1/images/generations`，查询 `GET /v1/images/generations/{id}`。默认模型 `kling-v3`。 |
| 视频 | 现行 Kling 4.0 是新版设计：模型在路径中。文生视频 `POST /text-to-video/kling-4.0`，图生视频 `POST /image-to-video/kling-4.0`。查询为 `GET /tasks?task_ids=`，不能按 ID 猜测旧路径。 |
| 公开异步 | 图片和视频都返回可跨进程查询的系统任务 ID，因此两边 `supports_async=true`。没有官方取消端点。 |
| 结果媒体 | 成功响应只给临时 URL，约 30 天后清理。官方未公布主机白名单。下载不把 URL 当产物。 |

图片和视频的路径、状态词和响应结构不能共用，拆成 `skill-kling-image` 与 `skill-kling-video`。可图不是独立 Provider，图片能力仍使用可灵开放平台。

### 2.1 本批纳入

| 能力 | 任务 | 结论 |
| --- | --- | --- |
| 文生图 | `text-to-image` | 纳入。同步提交、异步查询，下载 `task_result.images[].url`。 |
| 文生视频 | `text-to-video` | 纳入。按 Kling 4.0 路径和 `prompt` / `settings` / `options` 结构实现。 |
| 单图生视频 | `image-to-video` | 纳入。只接收一个首帧；远程 HTTPS 原样提交，本地文件只在正式执行读取并编码。 |
| 查询与下载 | `query`、`download` | 纳入。图片和视频都要求任务上下文。 |

### 2.2 本批不纳入

官方存在但本批明确拒绝或留待后续的能力：多关键帧、Omni 参考、主体、音色、口型、视频延长、动作控制、特效、虚拟试穿、图片扩图、图片编辑、回调 webhook、自定义 `external_task_id`、AK/SK JWT、静态模型目录、Runtime 集成和正式发布。

`width` / `height` 不能转换成 `aspect_ratio` 或 `resolution`。未知公共字段直接失败，不静默丢弃。

## 3. 阶段计划

### P0：基线、范围和官方协议核对

**目标**：确认可灵现行契约，并决定拆分项目。

**工作项**：

- 复核 `src/Multimedia/` 现有项目、公共库和发布入口，复用公共生命周期，不复制基础设施。
- 记录官方域名、认证、图片旧版接口、视频新版接口、查询、错误码和媒体限制。
- 标记参数统计稿失效项。
- 分别决定图片任务、视频任务、图生视频、公开异步和部分成功。

**门禁**：未确认字段不得写入 metadata 已支持声明；不能用内部轮询冒充公开异步，也不能把旧版 `succeed` 与新版 `succeeded` 混用。

**交付物**：协议记录、字段证据、问题与决策、批次路径登记。

### P1：项目组织和公共契约登记

**目标**：建立 `Madorin.AI.Kling.Image` 与 `Madorin.AI.Kling.Video`。

**工作项**：

- 技能名、程序名、AssemblyName、发布清单和技能目录分别为 `skill-kling-image`、`skill-kling-video`。
- 引用 `Madorin.AI.Multimedia.Core`。登记源生成 JSON、metadata、请求 Schema 和 Provider 私有 DTO。
- `list-models` 只实现“校验连接参数后返回不支持”，不嵌入模型数组。

**门禁**：不修改 Runtime、根解决方案或无关构建配置。

### P2：请求输入、任务选择和参数映射

**目标**：文件、argv 和 try-run 共用同一映射器。

**工作项**：

- 合并统一请求文件与显式 argv，保留来源和 request ID 一致性。
- 任务按显式值、默认值、本地唯一已实现任务选择。模型按 argv、文件、兼容默认选择，原样提交。
- 图片映射 `prompt`、`negative_prompt`、`resolution`、`n`、`aspect_ratio` 和显式水印。
- 视频映射 `prompt`、`duration`、`resolution`、文生视频 `aspect_ratio`，以及单张首帧。
- 可灵私有字段只放 `provider_parameters.kling`。
- try-run 离线，不读媒体，不建目录，不写文件，递归脱敏密钥和签名 URL。

**门禁**：metadata、Schema、校验器和 Provider DTO 逐项一致。

### P3：CLI 命令、响应和错误归一

**目标**：两个技能都提供 `metadata`、`list-models`、`generate`、`query`、`download`、`version`。

**工作项**：

- stdout 只输出一个 UTF-8 终态 JSON。
- `response_id` 原样等于有效 `request_id`。系统任务 ID 与官方 `request_id` 追踪分开。
- 按官方 HTTP 状态和业务码映射认证、余额、内容策略、限流和其他错误。
- verbose 只影响正式 stderr。try-run 的 stderr 为空。

### P4：Provider 执行和媒体产物

**目标**：图片和视频各自从提交到本地完整产物闭环。

**工作项**：

- Bearer 认证、根地址拼接和可取消 HTTP。
- 图片提交旧版端点；视频按模型 ID 拼入现行路径，不把未知模型改写到 `/v1/videos/*`。
- 只下载无用户信息的 HTTPS，关闭自动重定向，最多手动跟随 3 跳，校验容器后落盘。
- 文件名从 `image_001` 或 `video_001` 起，冲突不覆盖。槽位在调用前确定。

**门禁**：远端成功不等于本地产物成功。

### P5：异步、超时和取消

**目标**：按官方任务 ID 实现跨进程恢复。

**工作项**：

- 图片上下文恢复 `GET /v1/images/generations/{task_id}`。
- 视频上下文恢复 `GET /tasks?task_ids={task_id}`。不保存 API 地址、密钥、提示词或通用令牌。
- `query` 只查状态，`query --wait` 等待终态，`download` 不重新生成。
- 总预算从识别命令起算。取消后停止正常业务并清理临时文件，最多额外 5 秒。
- 受理状态未知时不自动重发。远端取消声明为不支持。

### P6：技能资源和发布准备

**目标**：源码、说明和发布清单与实现一致。

**工作项**：完成技能说明、请求 Schema、协议引用、包装脚本和发布清单。更新协议记录、执行记录和 README。不手工修改根 `skills/`。

### P7：统一验证

按协议推进记录约定，本阶段不运行构建、测试、AOT、发布或真实 API。全部协议处理完成后再统一验证。交付时必须把未验证项写成未验证。

## 5. 风险与停止条件

- 视频模型不在新版路径中：原样提交给现行路径，由远端拒绝，不猜测旧端点。
- 图片参考图、人脸参考和主体参考的模型限制未在本批逐项实现：传入这些字段或附件时失败。
- 结果 URL 主机或重定向无法形成白名单：仍不把 URL 列为产物；只接受无用户信息的 HTTPS 并限制跳转。这是显式记录，不是官方主机保证。
- 真实 API、额度、密钥、AOT 或目标平台缺失：源码可以落盘，但不能写成已验证。

## 6. 计划完成标准

计划完成不代表技能已实现。结项前必须分别有证据：

1. 官方字段与实现逐项对应。
2. metadata、Schema、校验、映射和技能文档一致。
3. try-run 无网络、无媒体读取、无文件写入。
4. 公开异步与跨进程恢复一致。
5. 构建、测试、AOT、真实 API 和发布按实际执行分别报告。
6. 记录和技能源文件不含密钥、真实媒体或本机绝对路径。


## 7. 本批执行结论（2026-11-10）

现行官方文档与参数统计稿冲突，实现以协议记录为准。

- 图片与视频拆成 `skill-kling-image`、`skill-kling-video`。两边都能用系统任务 ID 跨进程查询，但状态词和查询路径不同。
- 纳入文生图、文生视频和单首帧图生视频。多关键帧、Omni、参考图编辑和 JWT 不纳入。
- 默认模型分别为 `kling-v3` 与 `kling-4.0`。模型 ID 原样提交，不设白名单。
- 没有通用模型目录端点，`list-models` 返回 Provider 错误。
- 源码已落盘。构建、测试、AOT、发布和真实 API 均未执行。

# 智谱 CogView / CogVideoX 执行计划

## 1. 计划定位

本计划用于接入智谱 AI 的图片与视频生成协议，依据：

- [图片/视频技能 CLI 统一架构与协议方案](./技能CLI设计方案.md)
- [智谱 CogView / CogVideoX 参数参考](../参数统计/03-智谱-CogView-CogVideoX.md)
- [图片/视频技能 CLI 执行总览](../执行/README.md)
- [Multimedia 工作目录约束](../../../src/Multimedia/README.md)

本计划只登记执行顺序、核对门禁、交付物和验证要求，不改变公共 CLI 契约，也不授权自动调用付费 API、修改 Runtime 或发布技能包。

参考文档已经完整阅读。该文档作为接入线索使用；其中模型名称、请求字段、视频端点、响应结构、支持范围、错误码、价格和“同步/异步”判断，必须以实施前核对的现行智谱官方文档和可复现的协议证据为准，不能直接视为已确认契约。

## 2. 初始范围与待决项

### 2.1 候选能力

| 能力 | 初始任务 | 参考文档线索 | 计划中的准入条件 |
| --- | --- | --- | --- |
| 图片生成 | `text-to-image` | CogView-4，`POST /api/paas/v4/images/generations` | 官方确认模型 ID、认证、请求字段、响应媒体获取方式和图片限制。 |
| 视频文生 | `text-to-video` | CogVideoX，`POST /api/paas/v4/videos/generations` | 官方确认模型 ID、请求字段、任务状态、结果获取和时长/分辨率限制。 |
| 视频图生 | `image-to-video` | `image_url` 参考图 | 仅在官方确认输入是 URL 还是本地上传/文件对象、图片限制及任务语义后纳入。 |

初始实现不承诺图片编辑、首尾帧、音频、seed、negative prompt、style、webhook 或其他未核实能力。若图片和视频协议的生命周期、认证及错误结构无法安全共用，可在 P0 门禁中拆为两个技能项目；不能为目录对齐预建空壳项目。

### 2.2 关键待决项

1. 官方当前模型 ID 是否仍为 `cogview-4`、`cogview-3-plus`、`cogvideox` 或其他部署名。
2. 图片和视频端点是否仍使用参考文档中的 `/v4/images/generations` 与 `/v4/videos/generations`，以及 `api-url` 应表示根地址还是完整端点。
3. `Authorization: Bearer` 的实际要求、错误响应中的 code/message/request 追踪字段及限流语义。
4. 图片 `size`、`n`、`quality`、`response_format`、`user` 的现行支持范围、默认值和组合约束；不能因字段名类似 OpenAI 就自动复用语义。
5. 视频是否真实支持 `duration`、`fps`、`resolution`、`image_url`，以及这些字段的单位、枚举、默认值和模型级限制。
6. 视频生成是同步返回媒体 URL，还是提交任务后返回任务 ID；若异步，是否有跨进程可恢复的查询与下载协议、上下文所需字段及远端取消能力。
7. 响应媒体 URL 的有效期、允许主机、重定向规则、MIME/容器格式及下载后的完整性验证方式。
8. 是否存在可用的官方模型目录 API。没有目录接口时，`list-models` 必须如实返回 Provider 错误或按方案记录“不支持”，不能返回静态模型清单。

## 3. 阶段计划

### P0：基线、范围和官方协议核对

**目标**：形成智谱批次的事实基线，并决定是否采用单一 `ImageVideo` 项目或拆分项目。

**工作项**：

- 复核现有 `src/Multimedia/` 项目、公共库、测试夹具、发布基础设施和受影响目录 README。
- 阅读并记录智谱官方图片、视频、认证、模型、错误、任务状态和媒体下载文档，记录 URL 与核对日期。
- 用字段表逐项登记端点、HTTP 方法、请求字段、类型、必需性、默认值、范围、模型限制、响应字段、状态值和错误映射。
- 标记参考文档与官方文档的冲突、未确认字段和只能通过实际请求确认的行为。
- 确认能力边界：图片任务、视频任务、图生视频、公开异步、批量输出和部分成功分别作出“纳入/不纳入/待确认”结论。

**门禁**：未确认的字段不得进入 metadata 的“已支持”声明；未确认的异步恢复能力不得声明 `supports_async=true`。

**交付物**：智谱协议记录、字段证据表、问题与决策清单、批次源码与文档路径登记。

### P1：项目组织和公共契约登记

**目标**：按实际已授权能力建立最小技能项目结构。

**工作项**：

- 按最终能力选择项目名 `Madorin.AI.Zhipu.ImageVideo` 或拆分的 `Madorin.AI.Zhipu.Image` / `Madorin.AI.Zhipu.Video`。
- 统一使用 `skill-zhipu-image-video` 或拆分后的规范技能名；项目 AssemblyName、程序名、发布清单和技能目录保持一致。
- 引用 `Madorin.AI.Multimedia.Core`，不复制公共生命周期、路径授权、严格 JSON 或产物处理实现。
- 登记源生成 JSON 类型、metadata、请求 Schema、Provider 私有 DTO 和发布资源清单。
- 只在确认模型目录接口存在时实现真实 `list-models`；否则记录明确的 Provider 错误行为，不嵌入静态模型列表。

**门禁**：不修改 Runtime、根解决方案或无关构建配置；不因项目初始化预建未授权业务代码。

**交付物**：项目文件、职责目录、资源目录、发布清单初稿和协议记录更新。

### P2：请求输入、任务选择和参数映射

**目标**：让文件输入、直接 argv 和 try-run 共享同一套智谱映射器。

**工作项**：

- 实现统一请求文件与直接参数合并，保留来源、覆盖顺序和 request ID 一致性。
- 实现任务选择和模型选择：显式值优先，模型原样传递；不设置本地模型白名单或按名称猜任务。
- 根据官方证据映射公共参数：图片尺寸/数量/质量，视频时长/帧率/分辨率，以及确实支持的参考图输入。
- 将智谱私有字段放入 `provider_parameters.zhipu`，不提升为公共根字段。
- 对 `width + height`、`size`、视频单位或枚举仅实现有证据的等价转换；无法等价转换的字段记录 `ignored_parameters`，非法源值和目标冲突必须失败。
- 生成 metadata 任务 Schema、参数限制、默认值、附件限制、转换规则和能力声明。
- 复用正式 Provider 映射器实现离线 try-run，确保不联网、不读媒体、不创建目录、不写文件，并递归脱敏认证和签名 URI。

**门禁**：metadata、Schema、校验器、转换器和 Provider 请求 DTO 字段必须逐项一致；try-run 预览不能使用另一套简化映射。

**交付物**：请求处理、metadata、Schema、映射器、try-run 预览和定向离线夹具。

### P3：CLI 命令、响应和错误归一

**目标**：完成本地命令边界与统一公共响应。

**工作项**：

- 实现 `metadata`、`list-models`、`generate`、`version`；只有官方确认公开异步恢复后才增加 `query`、`download`。
- 统一输出单个 UTF-8 终态 JSON，正确维护 `response_id`、媒体类型、任务 ID、Provider 追踪 ID、转换/丢弃记录和错误结构。
- 规范化 HTTP、认证、参数、模型不可用、限流、服务端错误、下载失败和损坏媒体错误。
- 确认 list-models 失败时不静态回退；模型目录只有 ID 时返回未知任务能力。
- 保持 verbose 仅影响正式 stderr，try-run stderr 为空；任何密钥、签名 URL、提示词和原始响应体不得进入诊断。

**门禁**：所有已识别合法 request ID 的失败也回传同值；未知模型由远端如实拒绝，不在本地猜测或回退。

**交付物**：CLI 路由、响应模型、错误映射、脱敏策略和命令级夹具。

### P4：Provider 执行和媒体产物

**目标**：完成一条图片和一条视频能力从请求到本地完整产物的闭环。

**工作项**：

- 实现 Bearer 认证、基础地址/端点拼接和可取消 HTTP 调用。
- 按官方协议发送图片与视频请求，不把本地附件路径直接作为远端 URL；若图生视频需要上传或远端 URI，按官方方式实现并受预算和取消控制。
- 根据实际响应处理同步媒体 URL、异步提交、轮询状态和终态错误；不重发受理状态未知的创建请求。
- 对媒体下载执行 HTTPS、允许主机/路径、重定向、内容长度、MIME、容器和完整解码/解析校验。
- 只将完整验证并落盘的文件写入输出目录，使用 `image_001` 或 `video_001` 起始命名，冲突不覆盖；产物 `index` 在调用前确定。
- 确认图片输出格式策略；若 Provider 仅返回固定格式，不通过扩展名伪造其他格式。

**门禁**：远端成功不等于本地产物成功；损坏、截断、错误 MIME、越界 URL、取消和超时均按公共失败语义处理。

**交付物**：Provider 客户端、HTTP 假服务夹具、轮询/下载映射、产物校验和错误路径记录。

### P5：异步、超时和取消决策

**目标**：根据官方恢复能力决定公开异步还是仅内部等待。

**工作项**：

- 若视频仅能在一次进程内轮询，保持 `supports_async=false`，不提供 `no-wait`、`query` 或 `download`。
- 若官方提供可跨进程恢复的任务 ID、查询接口和下载信息，完整实现 `TaskContext`、上下文严格校验、`query`、`download`、独立预算和取消边界。
- 任务上下文不得保存 API 基础地址、API Key、提示词、附件内容或通用令牌；任务专属恢复 URL 仅按方案允许的受限字段传递。
- 使用从命令识别起点开始的单调总预算，覆盖请求、上传、提交、轮询、下载和落盘；取消后停止正常业务并清理临时文件，最多额外 5 秒。
- 分别验证超时、有效取消帧、错 ID/坏帧、EOF、不重复提交和终态仲裁。

**门禁**：没有完整恢复证据就不声明公开异步；取消或超时不能被 `partial` 覆盖。

**交付物**：异步能力决策、TaskContext Schema/实现（如适用）、轮询状态表、取消与预算测试夹具。

### P6：技能资源和发布准备

**目标**：使源码、文档和发布清单与真实实现一致。

**工作项**：

- 完成 `skill/SKILL.md`、`references/request.schema.json`、官方协议引用、参数映射说明和错误/异步边界说明。
- 完成 `publish.json`、`publish.ps1` 和脚本透传检查；确认技能名、程序名、AssemblyName、Version、SkillContractVersion 一致。
- 更新协议推进记录、阶段执行记录、受影响 README 和文件清单，区分已实现、离线验证、假 Provider 验证、真实 API、AOT 和平台发布状态。
- 发布前检查技能包不含密钥、任务文件、媒体、调试文件、本机绝对路径或未替换模板。

**门禁**：没有完整验证和授权不得执行正式发布，不手工修改根 `skills/` 代替发布流程。

**交付物**：完整技能源文件、发布清单、协议记录和发布前检查结果。

### P7：统一验证与交付收口

**目标**：按专项统一测试门禁收集可复现证据。

**验证范围**：

- 受影响项目构建、分析器检查和源生成 JSON 注册。
- 文件/argv 合并、严格 JSON、路径授权、模型选择、任务选择、转换/过滤和脱敏 try-run。
- 图片/视频请求字段映射、模型目录、成功/错误响应、超时、取消、损坏媒体、下载 URL 和文件冲突。
- 异步协议的提交、跨进程上下文恢复、查询、下载、任务失败和唯一终态，仅在该能力实际纳入时执行。
- 发布清单发现、技能包结构、脚本 stdin/stdout/stderr 透传、版本和 RID 校验。
- 真实 API、Native AOT、目标平台运行和正式技能发布分别记录；缺少账号、平台或工具链时保留待验证项。

**交付物**：实际命令与结果、测试覆盖表、协议推进记录、执行记录和最终能力边界。

## 5. 风险与停止条件

- 官方文档与参考文档冲突：暂停实现受影响字段，先记录差异和需要确认的契约。
- 视频接口实际为异步但缺少可恢复上下文：只实现同进程内部等待，不公开异步命令。
- 参考文档列出 `image_url` 但官方要求上传或不同字段：不把本地路径伪装为 URL，重新确定附件方案。
- 官方没有模型目录 API：`list-models` 不伪造成功清单；按协议记录 Provider 错误或不支持行为。
- 响应只给临时 URL 且主机/重定向无法形成白名单：停止下载实现，不能将 URL 直接列为产物。
- Provider 的图片或视频字段需要新增公共语义：停止实现，先更新设计契约并取得确认。
- 真实 API、付费额度、密钥、Native AOT 工具链或目标平台缺失：源码和离线证据可继续，但最终交付明确标注未验证。

## 6. 计划完成标准

计划本身完成不代表技能已实现。智谱批次只有在以下条件分别有证据后才可结项：

1. 官方协议字段、端点、认证、状态和媒体限制已记录并与实现逐项对应。
2. 实际纳入的图片/视频任务在 metadata、Schema、校验、Provider 映射和技能文档中一致。
3. try-run 无网络、无媒体读取、无文件写入；正式执行能验证完整本地产物和失败边界。
4. 公开异步能力声明与跨进程恢复实现一致，不以内部轮询冒充公开异步。
5. 定向测试、构建、AOT、真实 API、平台运行和发布状态按实际执行情况分别报告。
6. 协议记录、执行记录、README、技能资源和发布清单不含秘密、真实媒体或本机绝对路径。


## 7. P0 执行结论（2026-11-10）

现行官方文档与参考文档冲突，后续实现以协议记录为准，不按参考文档的同步视频响应或旧模型名继续。

- 图片与视频拆成 `skill-zhipu-image`、`skill-zhipu-video`。图片是同步 CogView；视频可用官方任务 ID 跨进程查询。
- 纳入文生图、文生视频和单图生视频。首尾帧官方存在，本批不纳入。
- 默认模型分别为 `cogview-4` 与 `cogvideox-3`。模型 ID 仍原样提交，不设白名单。
- 没有通用模型目录端点，`list-models` 返回 Provider 错误。
- 官方未公布结果主机白名单。下载不把 URL 当产物，只接受无用户信息的 HTTPS 并限制重定向；这是相对第 5 节停止条件的显式记录，不是官方主机保证。
- 详细字段、失效项和源码路径见 [协议记录](../协议推进记录/04-zhipu-cogview-cogvideox.md)。

# 扩展与运维补充

> 当前生效版本：Madorin.AI.Runtime V1
>
> 本文涵盖反向 RPC、Handshake 认证、MConsole 工具、Provider 协议查询、AOT 发布配置和测试指南等补充主题。

## 1. Reverse RPC 机制

Reverse RPC 允许 Runtime 在工具执行过程中反向调用宿主侧的功能，用于执行 `host.*` 和 `mcp.*` 前缀的工具。

### 1.1 核心类型

| 类型 | 位置 | 职责 |
| --- | --- | --- |
| `ReverseRpcToolExecutor` | `Madorin.AI.Runtime.Server` | 将 `host.*` 和 `mcp.*` 工具调用转为反向 JSON-RPC 请求发送给宿主 |
| `ReconnectableDuplexRpcPeer` | `Madorin.AI.Runtime.Server` | 可重连的双向 RPC 代理，宿主断线后自动路由到新的已认证连接 |
| `IDuplexRpcPeer` | `Madorin.AI.Runtime.Transport.Abstractions` | 双向 JSON-RPC 对等端抽象，继承 `IControlChannel` |

### 1.1.1 宿主 / MCP 工具 ID 校验（`ToolCatalogStore`）

写入工具目录时，宿主侧 ToolId 须匹配：

```text
^(host|mcp)\.[A-Za-z0-9][A-Za-z0-9_.-]*$
```

即命名空间为 `host` 或 `mcp`，其后为一段点分标识（如 `host.skill.search`、`mcp.filesystem.read`）。  
**不再**要求 `mcp.<server>.*` 的三段强制形态；错误文案为 `must use host.* or mcp.*`。

### 1.2 传输通道

Runtime 与宿主之间通过三种通道通信：

| 通道 | 接口 | 职责 |
| --- | --- | --- |
| 控制通道 | `IControlChannel` | 请求/响应式 JSON-RPC，`SendAsync` 发送请求并等待响应 |
| 事件通道 | `IEventChannel` | 事件流，`ReadAllAsync` 从指定游标读取事件，`AcknowledgeAsync` 确认已消费的全局序列号 |
| Blob 通道 | `IBlobChannel` | 二进制传输，`OpenReadAsync` 读取 Blob，`WriteAsync` 写入并返回 `blobId` |

`IDuplexRpcPeer` 继承 `IControlChannel` 并扩展了请求处理器注册（`SetRequestHandler`）和带超时的请求发送（`SendRequestAsync`），是反向 RPC 的双向抽象。

### 1.3 连接弹性

`ReconnectableDuplexRpcPeer` 通过 `peerResolver` 回调获取当前已认证的 peer 实例。宿主断线重连后，peer 实例被替换，后续反向 RPC 自动路由到新连接，无需上层感知。发送请求时以 50 ms 间隔轮询 peer 可用性，超时场景抛出 `TimeoutException`。

## 2. Handshake 认证

宿主连接 Runtime `serve` 模式时通过 Handshake 协议完成身份验证。

### 2.1 核心类型

`HandshakeHandler`（`Madorin.AI.Runtime.Server.Auth`）实现 V1 质询/响应原语，不传输共享密钥本身。

### 2.2 认证流程

1. 宿主生成随机 Nonce（`CreateNonce`，nonceC），Runtime 也生成自己的 Nonce（nonceS）
2. Runtime 使用共享密钥、Runtime 实例 ID 和双方 Nonce 计算响应值（`ComputeRuntimeResponse`），随 `HandshakeServerHello` 发送
3. 宿主验证该响应值（`VerifyRuntimeResponse`）
4. 宿主反过来通过 Session Proof 自证身份：宿主计算 `ComputeSessionProof`，Runtime 验证 `VerifySessionProof`

密钥传输方式：通过重定向的 stdin 传入，不通过 CLI 参数或环境变量暴露。

### 2.3 时间容差

`RuntimeServerOptions.HandshakeClockSkew` 控制时间戳验证的时钟偏差容差，默认 30 秒。带时间戳的变体 `ComputeRuntimeResponse` / `VerifyRuntimeResponse` 接受 `timestampUnixMilliseconds` 参数，在容差范围内视为有效。

### 2.4 宿主租约监控

`RuntimeServerOptions.HostLeaseTimeout` 定义宿主租约超时时间，默认 45 秒。Runtime 后台任务 `MonitorHostLeasesAsync` 持续监控已断开的宿主租约，超时后取消该宿主拥有的 Run 并断开 Session。

## 3. MConsole 工具

`tools/Madorin.AI.Runtime.MConsole` 是一个交互式控制台和测试工具，独立于主 Runtime 分发。

### 3.1 子系统

| 子系统 | 目录 | 职责 |
| --- | --- | --- |
| Menu | `Menu/` | 命令目录、参数向导、斜杠命令面板、危险命令防护 |
| Hosting | `Hosting/` | Runtime 进程定位、`serve` 宿主管理、REPL 会话 |
| HostClient | `HostClient/` | Client SDK 封装、事件消费、Run 编排 |
| Callbacks | `Callbacks/` | 回调协调、工具调用执行、权限管理 |
| Recovery | `Recovery/` | 凭据更新、重连演练、Session 恢复 |
| Security | `Security/` | 密钥脱敏 |
| Monitoring | `Monitoring/` | Runtime 运行时监控 |
| Testing | `Testing/` | 断言引擎、基线存储、文件树快照、执行历史 |
| Concurrency | `Concurrency/` | 并发场景运行、多宿主池 |
| Diagnostics | `Diagnostics/` | 7 级渐进冒烟测试 |
| Configuration | `Configuration/` | 选项加载、路径管理 |

### 3.2 冒烟测试级别

MConsole 内置 P0–P6 共 7 个渐进冒烟测试级别，每级有独立的 Runner 和 Report 类型：

| 级别 | 类 | 说明 |
| --- | --- | --- |
| P0 | `P0SmokeRunner` | 基础连通性验证 |
| P1 | `P1SmokeRunner` | 扩展基础验证 |
| P2 | `P2SmokeRunner` | 进阶功能验证 |
| P3 | `P3SmokeRunner` | 深度功能验证 |
| P4 | `P4SmokeRunner` | 复杂场景验证 |
| P5 | `P5SmokeRunner` | 高负载场景验证 |
| P6 | `P6SmokeRunner` | 全栈压力验证 |

## 4. `provider protocols` 命令

CLI 命令 `madorin provider protocols` 列出当前 Runtime 支持的所有 Provider 协议名称。

```powershell
madorin provider protocols
```

输出示例：

```text
Supported Provider protocols:
- OpenAI
- Anthropic
- OpenAI Compatible
- DeepSeek
- Kimi
- Aliyun
- Azure OpenAI
- Gemini
- GLM
- Custom
- Ollama
```

加 `--json` 输出 JSON 格式：

```json
{
  "command": "provider protocols",
  "protocols": ["OpenAI", "Anthropic", "OpenAI Compatible", "DeepSeek", "Kimi", "Aliyun", "Azure OpenAI", "Gemini", "GLM", "Custom", "Ollama"]
}
```

协议定义由 `StandaloneProviderProtocolCatalog` 维护，每个协议包含名称、显示名、是否推荐、默认 Base URL、默认模型等信息。

## 5. AOT Trimmer Profiles

`publish/` 目录包含 Native AOT 发布时使用的 RD.xml（Root Descriptor）文件，控制哪些程序集在裁剪时保留动态访问能力。

| 文件 | 保留程序集 | 用途 |
| --- | --- | --- |
| `rd.xml` | `Microsoft.Agents.AI`、`Microsoft.Agents.AI.Abstractions`、`Microsoft.Agents.AI.OpenAI`、`Microsoft.Extensions.AI`、`Microsoft.Extensions.AI.Abstractions` | 完整发布，保留 Agents SDK |
| `rd.no-agents-openai.xml` | `Microsoft.Agents.AI`、`Microsoft.Agents.AI.Abstractions`、`Microsoft.Extensions.AI`、`Microsoft.Extensions.AI.Abstractions` | 不含 Agents OpenAI 适配 |
| `rd.extensions-only.xml` | `Microsoft.Extensions.AI`、`Microsoft.Extensions.AI.Abstractions` | 最小发布，仅保留 Extensions.AI 抽象层 |

所有 RD.xml 文件将目标程序集标记为 `Dynamic="Required All"`，确保反射和动态代码生成在 AOT 环境下正常工作。

Release 构建要求零 IL trimming 警告和零 AOT 警告。构建采用确定性输出和中央包管理。

## 7. 构建与发布

### 7.1 日常构建

```powershell
dotnet build .\Madorin.AI.Runtime.slnx -c Debug
```

### 7.2 测试

```powershell
dotnet test .\Madorin.AI.Runtime.slnx -c Debug --no-build
```

### 7.3 Native AOT 发布

```powershell
dotnet publish .\src\Madorin.AI.Runtime.Cli -c Release -r win-x64 --self-contained true
```

Native AOT 编译在带 RID 的 publish（如上例 `-r win-x64 --self-contained true` 的自包含发布）时才真正生效，输出独立的可执行文件，无需安装 .NET 运行时；普通的 Release 构建并不等于启用 AOT。

### 7.4 构建特性

- **确定性构建**：相同输入产生相同输出
- **中央包管理**：`Directory.Packages.props` 统一管理 NuGet 包版本
- **源生成 JSON 上下文**：协议类型使用 `JsonSerializerContext` 源生成，确保 AOT 兼容和协议稳定性

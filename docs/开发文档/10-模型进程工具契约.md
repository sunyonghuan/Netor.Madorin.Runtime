# 模型进程工具契约

> 当前生效版本：Madorin.AI.Runtime V1
>
> 本文描述 Runtime 暴露给模型的进程执行工具 `mcli_process`。工具在显式白名单约束下启动可执行文件，不调用命令 Shell。

## 1. 工具

| Tool ID | Description | 风险 | 主要权限 |
| --- | --- | --- | --- |
| `mcli_process` | `Runs an allowed executable.` | 进程 | `process.execute`，受可执行文件白名单约束 |

## 2. 请求参数

```json
{
  "fileName": "dotnet",
  "arguments": ["build", "-c", "Release"],
  "workingDirectory": "/home/user/project",
  "environment": { "DOTNET_CLI_TELEMETRY_OPTOUT": "1" },
  "stdin": "input data"
}
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `fileName` | string | 是 | 可执行文件名或绝对路径 |
| `arguments` | string[] | 否 | 命令行参数，最多 128 个，每个不超过 8192 字符 |
| `workingDirectory` | string | 否 | 工作目录，必须在 `workspaceRoot` 内且落在 `AllowedReadRoots` 内；默认为 `workspaceRoot` |
| `environment` | object | 否 | 额外环境变量，键必须在白名单内 |
| `stdin` | string | 否 | 标准输入内容，UTF-8 编码后不超过 1 MB |

## 3. 响应格式

```json
{
  "exitCode": 0,
  "stdout": "Build succeeded.\n",
  "stderr": "",
  "stdoutTruncated": false,
  "stderrTruncated": false
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `exitCode` | integer | 进程退出码 |
| `stdout` | string | 标准输出（UTF-8） |
| `stderr` | string | 标准错误（UTF-8） |
| `stdoutTruncated` | boolean | 标准输出是否被截断 |
| `stderrTruncated` | boolean | 标准错误是否被截断 |

输出使用 UTF-8 编码，无效字节被替换而非抛异常。

## 4. 输出限制

| 约束 | 值 |
| --- | --- |
| 单流上限 | 1 MB |
| 两流合计上限 | 1 MB |
| 截断行为 | 超过上限后停止收集但继续排空流，对应流的 `*Truncated` 标记为 `true` |

单流上限与合计上限的数值都是 1 MB，但二者约束的对象不同：合计上限由 stdout、stderr **共享**同一个 1 MB 预算，单流上限则限制**单个流**自身最多收集 1 MB。由于共享预算与单流上限同为 1 MB，合计上限总是先于（或恰好等于）单流上限触发：两流合计一旦累计到 1 MB，剩余预算归零，后续任何一个流都会被截断。单流上限只有在某个流独占全部预算时才可能达到，而那一刻合计预算同样已耗尽，因此它不会比合计上限更早触发。换言之，合计 1 MB 是实际生效的紧约束，单流 1 MB 是每个流各自的上界。两个流各自独立记录 `stdoutTruncated` / `stderrTruncated`，只有被截断的那个流会被标记。

进程本身继续运行到正常退出或被取消，截断只影响收集到的输出内容。

## 5. 可执行文件白名单

`mcli_process` 不会自动拼接或解释 Shell 命令，但可以启动显式允许列表中的命令行工具和脚本入口。

### 5.1 Shell 解释器

以下程序名不再被进程执行器统一拒绝；它们是否可以启动，仍由白名单决定：

```text
bash, cmd, fish, powershell, pwsh, sh, zsh
```

如果 AI 需要执行脚本，应将对应解释器作为 `fileName`，并通过参数显式传递脚本路径和脚本参数；Runtime 不自动重写或拼接 Shell 命令。

### 5.2 名称解析

- **绝对路径**：必须在白名单的绝对路径列表中，经过 `Path.GetFullPath` 规范化后精确匹配。
- **纯文件名**：必须在白名单的名称列表中，Runtime 在自身 `PATH` 环境变量中查找。Windows 下无扩展名时自动尝试无扩展名文件和 `.exe`；命中的候选文件不再限制扩展名，因此可以交由显式启动的命令解释器处理 `.cmd`、`.bat`、`.ps1` 等脚本入口。
- **相对路径**（包含 `/`、`\` 或 `:`）：拒绝。

### 5.3 可执行文件固定

拒绝 UNC、`/dev/`、`/proc/`、`/sys/` 等特殊路径发生在名称规范化（`NormalizeRequestedExecutable`）阶段，针对原始请求路径，早于白名单匹配和句柄固定；对符号链接解析后才指向 `/dev/` 等目标的情况不再重复覆盖。

通过白名单匹配、解析到实际路径后，Runtime 按以下顺序固定：

1. 解析符号链接到最终目标。
2. 验证目标文件存在且不是目录。
3. 最后打开文件句柄（`SafeFileHandle`）保持引用。

执行期间文件句柄保持打开，确保执行的是固定的文件。

## 6. 环境变量

进程启动时**清空全部继承的环境变量**，只注入以下内容：

1. 白名单中的变量从 Runtime 环境继承当前值。
2. `environment` 参数中的变量覆盖或新增（必须在白名单内）。

白名单由 Grant 的 `AllowedEnvironmentVariables` 决定，超过 128 个变量时拒绝。变量名不能包含 `=` 或空字符。

## 7. 工作目录

- 默认使用当前 `workspaceRoot`。
- 显式指定的目录必须在 `workspaceRoot` 内，并经过路径策略校验。
- 还必须落在 Grant 的 `AllowedReadRoots` 范围内，否则抛出“outside the allowed read roots”而拒绝执行。
- 拒绝 `..`、UNC、符号链接等不安全路径。

## 8. 进程生命周期

- 使用 `UseShellExecute = false`、`CreateNoWindow = true`。
- 标准输入写入后立即关闭（发送 EOF）。
- 取消时调用 `process.Kill(entireProcessTree: true)` 终止整个进程树。
- 进程异常或取消时仍尝试等待退出完成后再返回。

## 9. 边界

`mcli_process` 不提供：

- Shell 展开（通配符、管道、重定向、变量替换）。
- 后台执行或守护进程。
- 交互式终端或 PTY。
- 进程间通信或信号发送。

需要 Shell 能力时，由宿主在 `AllowlistedProcess`、`SandboxedShell` 或 `UnrestrictedShell` 权限级别提供专用工具，参见《05-安全与数据运维》第 1 节。

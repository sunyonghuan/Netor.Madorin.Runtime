# 模型记忆工具契约

> 当前生效版本：Madorin.AI.Runtime V1（工具目录 `CatalogVersion` 为 `3.0.0`）
>
> `mcli_memory_*` 只管理两个固定 Markdown 文件。记忆正文会在 Agent 启动时原样注入；工具只用于读取和修改文件。旧 ToolId（`mcli_memory_append` / `update` / `delete`）仍可作为内部别名执行，但不广告给模型。

## 1. 工具

| Tool ID | Description | Scope |
| --- | --- | --- |
| `mcli_memory_read` | `Reads every line of global or project memory with line numbers and a hash.` | `global`、`project` |
| `mcli_memory_write` | `Appends, replaces, or deletes lines. Pass operation=append\|update\|delete.` | `global`、`project` |

固定文件：

```text
global  -> ~/.madorin/memory.md
project -> <workspace>/.madorin/memory.md
```

`scope` 是必填参数，只能是 `global` 或 `project`。不支持 `effective`，也不接受文件路径。

单个记忆文件有 32 KB（`32 * 1024` 字节）硬上限。读取时文件超限抛异常，写入后内容超限同样抛异常并拒绝提交。

## 2. 读取

`mcli_memory_read` 返回目标文件的完整行数组、总行数和 SHA-256：

```json
{
  "scope": "project",
  "lineCount": 3,
  "lines": [
    { "line": 1, "text": "# Memory" },
    { "line": 2, "text": "- Use .NET 10." },
    { "line": 3, "text": "- Run tests before release." }
  ],
  "hash": "..."
}
```

行号从 `1` 开始。空行也占一行，`startLine` 和 `endLine` 都包含在操作范围内。

目标文件不存在时，`read` 返回 `hash` 为 `null`、`lineCount` 为 `0`、`lines` 为空数组。

## 3. 修改

`mcli_memory_write` 用 `operation` 区分三种写：

- `append` 的 `lines` 是要追加的完整 Markdown 行。
- `update` 用 `lines` 替换 `startLine..endLine`，支持一行替换多行或多行替换一行。
- `delete` 删除 `startLine..endLine`，支持连续多行删除。
- `update` 和 `delete` 要求非空 `expectedHash`；哈希不匹配时拒绝写入，模型必须重新读取。
- `append` 的 `expectedHash` 可为 `null`：目标文件不存在时可传 `null` 通过（用于首次写入），文件已存在时仍须传入与当前内容匹配的哈希。
- 每个 `lines` 元素只能包含一行，不能包含换行符。
- 工具不自动添加标题、项目符号、空行或其他 Markdown 格式。
- 写入成功只影响下一次 AgentInvocation；当前已注入上下文不改变。

成功返回 `{ "written": true, "operation": "append|update|delete", "lineCount": <int>, "hash": "...", "appliesFrom": "nextInvocation" }`。`appliesFrom` 恒为 `nextInvocation`。

广告给模型的写工具风险等级为 `Write`，始终需要用户审批。内部别名 `mcli_memory_delete` 仍按 `Destructive` 校验。

所有写操作需要用户审批。普通文件工具不能通过路径访问这两个记忆文件。

记忆修改与普通文件修改共用当前 Runtime 的进程内工作区写锁。锁范围覆盖读取当前记忆、`expectedHash` 校验、生成新内容和原子替换；读取不加锁。新版本不再创建或获取 `memory.md.lock`，也不会清理旧版本遗留的同名 `.lock` 文件。独立 CLI 或测试未显式传入共享锁时，`MemoryFileService` 会创建自己的进程内锁。

全局记忆位于用户目录，可能被不同工作区的 Runtime 或人工编辑同时修改，因此不承诺跨进程强一致。出现哈希冲突时必须重新读取后再提交。

## 4. 边界

`mcli_memory_*` 不负责语义搜索、向量检索、自动提取、复杂记忆分层或跨项目知识管理。这些能力由宿主提供的记忆工具负责。

# 事件协议参考

> 当前生效版本：Madorin.AI.Runtime V1，协议 1.1
>
> 本文列出 Runtime 向宿主或 CLI 发出的所有事件类型、信封结构和消息类型常量。宿主集成时按本文消费事件流。

## 1. 事件信封

每个事件都包装在 `RuntimeEventEnvelope` 中：

```json
{
  "runtimeInstanceId": "inst-abc123",
  "gsn": 42,
  "runId": "run-xyz",
  "runSequence": 7,
  "messageType": "output.delta",
  "timestamp": "2026-08-07T10:30:00.000Z",
  "payload": { ... }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `runtimeInstanceId` | string | Runtime 实例标识，重启后变化 |
| `gsn` | long | 全局序列号，单调递增，用于确认和去重 |
| `runId` | string | 产生该事件的 Run |
| `runSequence` | long | 该 Run 内的局部序列号 |
| `messageType` | string | 消息类型常量，见下文 |
| `timestamp` | DateTimeOffset | 事件时间戳；CLR 类型为 `DateTimeOffset`，序列化为 ISO-8601 字符串 |
| `payload` | JsonElement | 事件正文，结构随 `messageType` 变化 |

消费事件后通过 `AcknowledgeEventsAsync(lastConfirmedGsn)` 确认。重连时从 `lastConfirmedGsn + 1` 开始重放，以 `(runtimeInstanceId, gsn)` 去重。

## 2. Run 生命周期事件

### 2.1 `run.accepted`

Run 被 Runtime 接受并排队。

```json
{ "sessionId": "sess-1", "runId": "run-1" }
```

### 2.2 `run.stage.changed`

Run 状态变化。`status` 取值见下表。

```json
{
  "runId": "run-1",
  "status": "Running",
  "mode": "expert",
  "phase": "tool-loop",
  "currentStep": null,
  "completedUnits": 3,
  "totalUnits": null,
  "updatedAt": "2026-08-07T10:30:00Z",
  "error": null
}
```

| RunStatus | 含义 |
| --- | --- |
| `Accepted` | 已接受，等待执行 |
| `Preparing` | 准备上下文和投影 |
| `Running` | 正在执行模型推理 |
| `WaitingForTool` | 等待工具执行结果 |
| `WaitingForApproval` | 等待用户审批 |
| `WaitingForCredentials` | 等待凭据刷新 |
| `Persisting` | 持久化结果 |
| `Completed` | 正常完成 |
| `Failed` | 失败 |
| `Cancelled` | 已取消 |
| `Interrupted` | 被中断 |

`mode`、`phase`、`currentStep`、`completedUnits`、`totalUnits`、`updatedAt`、`error` 均为可选字段，只在相关状态变化时填充。Work 模式下 `currentStep` 和进度信息更丰富。

### 2.3 `run.completed`

Run 正常完成。

```json
{ "runId": "run-1", "sessionId": "sess-1" }
```

### 2.4 `run.failed`

Run 失败。

```json
{
  "runId": "run-1",
  "sessionId": "sess-1",
  "error": {
    "code": "provider.timeout",
    "category": "transient",
    "message": "The provider did not respond within the timeout.",
    "isRetryable": true,
    "providerDetails": null,
    "diagnosticId": "diag-abc"
  }
}
```

### 2.5 `run.cancelled`

Run 被取消。

```json
{ "runId": "run-1", "sessionId": "sess-1" }
```

## 3. Invocation 事件

每次模型调用（可能一个 Run 内有多次）产生 Invocation 事件。

### 3.1 `invocation.started`

模型调用开始，附带完整的调用快照。

```json
{
  "invocationId": "inv-1",
  "snapshot": {
    "invocationId": "inv-1",
    "agentId": "default",
    "providerId": "openai",
    "modelId": "gpt-5",
    "promptHash": "sha256:...",
    "globalMemoryHash": "sha256:...",
    "projectMemoryHash": "sha256:...",
    "toolCatalogVersion": "2.0.0",
    "projectionVersion": "v1",
    "startedAt": "2026-08-07T10:30:00Z",
    "parentInvocationId": null,
    "workStepId": null,
    "workPlanVersion": null,
    "contextProjection": null,
    "skillCatalogVersion": "1.0",
    "skillNames": ["code-review"],
    "skillContentHashes": ["sha256:..."],
    "skillSourceIds": ["builtin"],
    "skillMaterializedPaths": [".madorin/skills/code-review"]
  }
}
```

`parentInvocationId` 在 Work 模式的子智能体调用时有值。`workStepId` 和 `workPlanVersion` 在 Work 模式步骤执行时有值。`contextProjection` 为可选的上下文投影快照（结构见 §5.1 的字段），未发生投影调整时为 `null`。`skillContentHashes`、`skillSourceIds`、`skillMaterializedPaths` 与 `skillNames` 一一对应，分别记录技能内容哈希、来源标识和物化路径。

### 3.2 `invocation.completed`

模型调用正常完成。

```json
{ "invocationId": "inv-1" }
```

### 3.3 `invocation.failed`

模型调用失败。

```json
{
  "invocationId": "inv-1",
  "error": { ... }
}
```

`error` 结构同 `run.failed`。

## 4. 流式内容事件

### 4.1 `output.delta`

文本增量。

```json
{ "invocationId": "inv-1", "delta": "Hello, " }
```

### 4.2 消息类型常量（无类型化 record 载荷）

以下四个是 `MessageTypes` 中定义的消息类型常量/流式信号，Runtime 侧**没有**对应的类型化事件 record（`Events/` 目录不含这些类），因此不构成与上文 `output.delta`（`TextDeltaEvent`）等同的载荷契约。宿主消费时应按 `messageType` 字符串识别，`payload` 结构不作类型化保证：

| 消息类型常量 | 含义 |
| --- | --- |
| `reasoning.delta` | 推理/思考增量（仅在支持 Reasoning 的 Provider 和模型下产生） |
| `tool.call.delta` | 工具调用请求增量（流式工具调用场景） |
| `tool.call.completed` | 工具调用完成 |
| `usage.updated` | Token 用量更新 |

### 4.3 `delta.dropped`

重连重放时部分增量已被丢弃（因为已确认过的不再重发）。

```json
{ "runId": "run-1", "fromRunSequence": 5, "toRunSequence": 12 }
```

表示 `runSequence` 5 到 12 之间的增量不再重放。

## 5. 上下文投影事件

### 5.1 `context.projection.adjusted`

上下文投影发生变化（消息裁剪、摘要压缩等）。

```json
{
  "invocationId": "inv-1",
  "droppedMessageCount": 20,
  "includedMessageCount": 80,
  "estimatedTokens": 95000,
  "estimateSource": "tiktoken",
  "strategy": "sliding-window",
  "retainedItems": ["msg-50", "msg-51"],
  "tokenLimit": 128000,
  "summarizedUnitCount": 15
}
```

| 字段 | 说明 |
| --- | --- |
| `strategy` | 投影策略名称 |
| `droppedMessageCount` | 被丢弃的消息数 |
| `includedMessageCount` | 保留的消息数 |
| `estimatedTokens` | 估算 Token 数 |
| `estimateSource` | Token 估算来源 |
| `retainedItems` | 保留的关键项标识 |
| `tokenLimit` | Token 上限 |
| `summarizedUnitCount` | 被摘要压缩的单元数 |

### 5.2 `provider.projection.adjusted`（消息类型常量，无类型化 record 载荷）

Provider 侧的投影调整（如 Prompt Caching 命中信息）。这是 `MessageTypes` 中的消息类型常量，`Events/` 目录中没有对应的类型化事件 record，`payload` 结构不作类型化保证。与之相对，§5.1 的 `context.projection.adjusted` 有类型化 record（`ContextProjectionAdjustedEvent`）。

## 6. 凭据事件

### 6.1 `credentials.refresh.request`

Runtime 请求宿主刷新凭据（例如 API Key 过期）。

```json
{
  "runId": "run-1",
  "providerId": "openai",
  "reason": "Authentication failed: API key expired."
}
```

宿主收到后应调用 `UpdateCredentialsAsync` 提供新凭据。Runtime 不会在事件中暴露凭据值。

### 6.2 `credentials.update`

宿主主动更新凭据（请求方向，非事件）。

## 7. RuntimeError 结构

失败事件中的 `error` 字段统一使用 `RuntimeError`：

```json
{
  "code": "provider.timeout",
  "category": "transient",
  "message": "The provider did not respond within the timeout.",
  "isRetryable": true,
  "providerDetails": null,
  "diagnosticId": "diag-abc"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | string | 错误码 |
| `category` | string | 错误分类（`transient`、`permanent`、`policy` 等） |
| `message` | string | 人可读描述 |
| `isRetryable` | boolean | 是否可以重试 |
| `providerDetails` | JsonElement? | Provider 原始错误细节 |
| `diagnosticId` | string | 诊断标识，用于日志关联 |

# 模型文件工具契约

> 当前生效版本：Madorin.AI.Runtime V1（工具目录 `CatalogVersion` 为 `3.0.0`）
>
> 本文描述 Runtime 暴露给模型的文件和目录工具。工具描述保持简短英文，参数和结果使用 JSON Schema。旧 ToolId（`mcli_fs_list`、`mcli_fs_stat`、`mcli_fs_append`、`mcli_fs_mkdir`）仍可作为内部别名执行，但不广告给模型。

## 1. 工具目录

| Tool ID | 功能 | 风险 | 主要权限 |
| --- | --- | --- | --- |
| `mcli_fs_inspect` | `mode=list` 列出目录，`mode=stat` 返回路径元数据 | 敏感读取 | `filesystem.read` |
| `mcli_fs_read` | 按行读取文本文件 | 敏感读取 | `filesystem.read` |
| `mcli_fs_write` | `mode` 为 `create` / `overwrite` / `append` / `mkdir` | 写入 | `filesystem.write`；`overwrite` 与 `append` 需要 `overwrite` |
| `mcli_fs_edit` | 原子执行多项行编辑 | 写入 | `filesystem.read` + `filesystem.write`，且始终需要 `overwrite` |
| `mcli_fs_search` | 在文本文件中搜索 | 敏感读取 | `filesystem.read` |
| `mcli_fs_copy` | 复制文件或目录 | 写入 | `filesystem.read` + `filesystem.write` |
| `mcli_fs_move` | 移动文件或目录 | 破坏性 | `filesystem.write` + `filesystem.destructive` |
| `mcli_fs_delete` | 删除文件或目录 | 破坏性 | `filesystem.write` + `filesystem.destructive` |

工具展示给模型的描述使用短句，例如：

```text
Reads a text file by line range.
Applies line edits to a text file.
Copies a file or directory.
```

## 2. 文本编码

`mcli_fs_read`、`mcli_fs_search`、`mcli_fs_edit` 以及 `mcli_fs_write` 的 `create` / `overwrite` / `append` 必须传入 `encoding`。`mkdir` 不需要编码。

`mcli_fs_read` 和 `mcli_fs_search` 的可用值为：

`auto`、`utf-8`、`utf-16le`、`utf-16be`、`gb2312`、`gbk`、`gb18030`、`ascii`、`latin1`。

`mcli_fs_write` 文本模式和 `mcli_fs_edit` 的可用值不含 `auto`：

`utf-8`、`utf-16le`、`utf-16be`、`gb2312`、`gbk`、`gb18030`、`ascii`、`latin1`。

写入、追加和编辑不能使用 `auto`，必须明确指定目标编码。读取结果会返回实际编码、Code Page、BOM、换行风格、总行数和 SHA-256。

`auto` 只在 BOM、ASCII 或明确可判断为 UTF-8 时自动识别；无法可靠判断时返回错误，模型应改用明确编码重试，不能静默替换字符。

## 3. 行编辑规则

- 行号从 `1` 开始，读取支持 `startLine` 和 `endLine`。
- `mcli_fs_read` 返回带行号的内容，例如 `12| return value;`。
- `mcli_fs_edit` 支持 `replace`、`delete`、`insertBefore` 和 `insertAfter`。
- 编辑必须传入 `expectedHash`，文件发生并发修改时拒绝提交。
- 多项编辑一次性校验并原子写入，失败时不留下半成品。
- `mcli_fs_write` 的 `append` 要求目标文件已存在，`expectedHash` 运行期必填且不可为空（64 位十六进制），并始终需要覆盖权限；无法用于首次创建文件。
- `mcli_fs_write` 的 `expectedHash` 在 Schema 中未列为必填，但 `overwrite` 已存在文件时运行期强制要求传入并校验；`create` 和 `mkdir` 不需要。

同一 Runtime 内，`write`（含 append/mkdir）、`edit`、`copy`、`move` 和 `delete` 与记忆修改共用一把进程内工作区写锁。取得锁后会重新解析路径、打开文件并校验当前内容，因此不同 Run、Session 和 Agent 的修改整体串行；`read`、`inspect` 和 `search` 不获取该锁，仍可并行读取。写入继续使用临时文件和原子替换，`expectedHash` 负责在等待锁后识别已经变化的内容。

这把锁不创建锁文件，也不阻塞外部编辑器。跨进程层面只由 Runtime 的工作区实例锁保证同一工作区只启动一个 Runtime；人工编辑或其他工作区 Runtime 的修改不属于强一致范围。

## 4. 路径和权限

- 所有路径必须位于当前 `workspaceRoot` 和有效 Grant 的允许范围内。
- 拒绝 `..`、UNC、设备路径、备用数据流、符号链接、目录联接点和 `.madorin`。
- 新建文件、目录和非覆盖复制可以申请当前 Run 权限。
- 覆盖、追加、编辑、移动和删除默认只允许当前 Call，并需要相应风险权限。
- 递归目录复制会检查链接、条目数量并累计总字节数，超过 64 MB 时拒绝；递归目录删除只检查链接和条目数量，不校验总字节数。
- 审计只记录规范化路径摘要、参数哈希、权限和结果，不记录完整文件内容。

## 5. 二进制文件

Runtime 不提供二进制内容的 Base64 读写工具。`mcli_fs_inspect` 的 `mode=stat` 可以识别文件类型，`mcli_fs_copy`、`mcli_fs_move` 和 `mcli_fs_delete` 可以安全处理二进制文件；文本读取和行编辑遇到二进制或不匹配编码时必须失败。

只有业务明确需要模型修改图片、压缩包或其他二进制格式时，才单独设计带大小上限、媒体类型和权限的二进制工具。

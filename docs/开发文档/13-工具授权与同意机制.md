# 工具授权与同意机制

> 当前生效版本：Madorin.AI.Runtime V1
>
> 本文描述 Runtime 的工具授权体系：Grant（权限声明）、Approval（用户同意）和 Gateway（统一调度）。三层机制协作，控制模型在 Run 中可以调用哪些工具、以什么权限执行。

## 1. 概述

工具授权控制模型在给定 Run 中可以调用的工具集合和执行权限。体系分为三层：

- **Grant（授权）**：声明式权限边界，定义可读路径、可写路径、可执行文件白名单、网络策略等。
- **Approval（同意）**：对高风险操作的运行时用户确认，宿主通过回调参与决策。
- **Gateway（网关）**：统一调度入口，协调授权检查、参数校验、执行分发和审计记录。

三层关系：Gateway 在每次工具调用时检查 Grant，Grant 不足时通过 Approval 向宿主请求扩展或用户确认，最终决策为 Granted、Denied 或 NeedsApproval。

## 2. 工具风险等级

`ToolRiskLevel` 枚举定义工具的风险分类，用于授权决策和审计。

| 级别 | 枚举值 | 含义 |
| --- | --- | --- |
| `Low` | 0 | 低风险读取操作 |
| `SensitiveRead` | 1 | 敏感读取（文件内容、搜索结果） |
| `Write` | 2 | 写入操作 |
| `Destructive` | 3 | 破坏性操作（移动、删除） |
| `Process` | 4 | 进程执行 |
| `PowerShell` | 5 | PowerShell/Shell 执行 |
| `Network` | 6 | 网络访问 |

Grant 的 `MaximumRisk` 字段设定该授权允许的最高风险等级。工具定义的风险等级超过 `MaximumRisk` 时，授权决策为 Denied 或 NeedsApproval。

## 3. ToolGrant 结构

`ToolGrant` 是不可变记录，描述一次 Run 的有效授权范围。

```csharp
public sealed record ToolGrant(
    string GrantId,
    string RunId,
    string WorkspaceRoot,
    string[] AllowedReadRoots,
    string[] AllowedWriteRoots,
    bool AllowOverwrite,
    bool AllowMove,
    bool AllowDelete,
    string[] AllowedExecutables,
    bool AllowPowerShell,
    NetworkPolicy NetworkPolicy,
    DateTimeOffset ExpiresAt,
    bool AllowDelegation,
    string[] DelegatedAgentIds,
    string[]? AllowedToolIds = null,
    string[]? AllowedCallIds = null,
    ToolRiskLevel? MaximumRisk = null,
    string[]? AllowedEnvironmentVariables = null,
    string? AgentId = null,
    string? ParentGrantId = null,
    string? RootGrantId = null,
    string[]? DelegationChain = null,
    string? ApprovalRequestId = null,
    string[]? AllowedSkillScriptKeys = null,
    string? SkillCatalogVersion = null);
```

核心字段分组：

| 分组 | 字段 | 说明 |
| --- | --- | --- |
| 标识 | `GrantId`、`RunId`、`WorkspaceRoot` | 授权唯一标识、绑定的 Run 和工作区根路径 |
| 路径范围 | `AllowedReadRoots`、`AllowedWriteRoots` | 可读/可写的目录根，路径必须在其范围内 |
| 写入权限 | `AllowOverwrite`、`AllowMove`、`AllowDelete` | 分别控制文件覆盖、移动、删除 |
| 进程权限 | `AllowedExecutables`、`AllowPowerShell` | 可执行文件白名单和 Shell 执行开关 |
| 网络策略 | `NetworkPolicy` | HTTP 工具的网络访问约束，详见 [09-模型HTTP工具契约](./09-模型HTTP工具契约.md) |
| 过期 | `ExpiresAt` | 授权到期时间 |
| 委托链 | `AllowDelegation`、`DelegatedAgentIds` | 是否允许子智能体委托，以及被委托的 Agent ID 列表 |
| 工具过滤 | `AllowedToolIds`、`AllowedCallIds` | 允许调用的工具 ID 和调用 ID 白名单 |
| 风险上限 | `MaximumRisk` | 该授权允许的最高 `ToolRiskLevel` |
| 环境变量 | `AllowedEnvironmentVariables` | 进程工具可访问的环境变量白名单 |
| 层次结构 | `AgentId`、`ParentGrantId`、`RootGrantId`、`DelegationChain` | 授权来源 Agent、父授权、根授权和委托链 |
| 技能 | `AllowedSkillScriptKeys`、`SkillCatalogVersion` | 允许执行的技能脚本键和对应的目录版本 |

## 4. 授权决策流程

每次工具调用经过以下决策链：

```text
ToolInvocation
    ↓
ToolGateway.ExecuteAsync()
    ↓ 参数校验 + 查找执行器
ToolAuthorizationService → ToolAuthorizationDecision
    ↓
┌─ Granted → 直接执行
├─ Denied  → 返回错误
└─ NeedsApproval → ToolConsentCoordinator
        ↓
   ┌─ NeedsPermission → ToolPermissionRequest → 宿主 tool.permission.request 回调
   └─ NeedsApproval   → ApprovalRequest       → 宿主 approval.request 回调
        ↓
   获得 Grant → 重新执行
```

决策结果为 `ToolAuthorizationDecision` 枚举：

| 值 | 含义 |
| --- | --- |
| `Granted` | 当前 Grant 满足工具所需权限 |
| `Denied` | 权限不足且不可扩展 |
| `NeedsApproval` | 需要宿主或用户确认后扩展权限 |

当决策为 `NeedsApproval` 时，`ToolConsentCoordinator` 会根据待处理结果类型走两条**独立**路径，分别构造不同的请求类型发给宿主：

| 路径 | 构造的请求类型 | 宿主回调 | 语义 |
| --- | --- | --- | --- |
| NeedsPermission | `ToolPermissionRequest` | `tool.permission.request` | 需要为工具补一个 Grant（权限扩展） |
| NeedsApproval | `ApprovalRequest` | `approval.request` | 需要用户对高风险操作显式同意 |

两者互不替代：Permission 路径关注授权范围的扩展，Approval 路径关注用户对具体操作的确认。下文 §5 分别描述这两种请求的形状。

关键组件：

| 组件 | 职责 |
| --- | --- |
| `ToolGateway` | 统一调度入口：参数校验、授权检查、执行分发、审计记录 |
| `ToolGrantCalculator` | 静态工具类，计算多个权限上下文的最小特权交集 |
| `ToolConsentCoordinator` | 协调同意流程：构造权限请求、发送宿主回调、获取扩展授权后重新执行 |
| `ToolAuthorizationService` | 检查工具调用是否在当前 Grant 范围内 |

## 5. 同意请求结构（Permission 与 Approval）

`ToolConsentCoordinator` 按 §4 的两条路径构造两种不同的请求类型：NeedsPermission 走 `ToolPermissionRequest`，NeedsApproval 走 `ApprovalRequest`。

### 5.1 ToolPermissionRequest 结构

NeedsPermission 路径下，`ToolConsentCoordinator` 构造 `ToolPermissionRequest`，通过 `tool.permission.request` 回调发送给宿主。

```csharp
public sealed record ToolPermissionRequest(
    string ApprovalRequestId,
    string AgentId,
    string? ParentAgentId,
    string ToolId,
    string CallId,
    string ArgumentsHash,
    string Risk,
    string RequestedScope,
    string Reason,
    string? CorrelationId = null,
    string? RunId = null,
    string? ToolCatalogVersion = null,
    string[]? RequestedCapabilities = null,
    string? SessionId = null,
    string? InvocationId = null,
    string? ParentInvocationId = null,
    string? WorkStepId = null,
    string? PlanVersion = null);
```

| 字段 | 说明 |
| --- | --- |
| `ApprovalRequestId` | 请求唯一标识，对 `RunId` + `CallId`（以换行连接）做 SHA-256 派生，并加 `permission-` 前缀（NeedsPermission 路径）；NeedsApproval 路径的 `ApprovalRequest` 用同样算法但加 `approval-` 前缀 |
| `AgentId` | 请求授权的 Agent |
| `ParentAgentId` | 委托场景下的父 Agent |
| `ToolId` | 请求调用的工具 ID |
| `CallId` | 本次调用的唯一标识 |
| `ArgumentsHash` | 工具参数的哈希值，宿主可据此展示摘要 |
| `Risk` | 工具风险等级字符串 |
| `RequestedScope` | 请求的权限范围描述 |
| `Reason` | 需要授权的原因说明 |
| `WorkStepId` / `PlanVersion` | Work 模式下关联的步骤和计划版本 |

宿主通过 `tool.permission.response` 回调返回 `ToolPermissionResponse`，包含 Grant 或拒绝决定。

### 5.2 ApprovalRequest 结构

NeedsApproval 路径下，`ToolConsentCoordinator` 构造的是独立的 `ApprovalRequest`（而非 `ToolPermissionRequest`），通过 `approval.request` 回调发送给宿主请求用户确认。

```csharp
public sealed record ApprovalRequest(
    string CorrelationId,
    string ApprovalRequestId,
    string CallId,
    string RunId,
    string AgentId,
    string? ParentAgentId,
    string ToolId,
    string ArgumentsHash,
    ToolRiskLevel Risk,
    string TargetSummary,
    string Reason,
    string? SessionId = null,
    string? InvocationId = null,
    string? ParentInvocationId = null,
    string? WorkStepId = null,
    string? PlanVersion = null);
```

与 `ToolPermissionRequest` 的关键差异：

| 字段 | 说明 |
| --- | --- |
| `ApprovalRequestId` | 请求唯一标识，派生算法同上，前缀为 `approval-` |
| `Risk` | 工具风险等级，类型为 `ToolRiskLevel` 枚举（非字符串） |
| `TargetSummary` | 规范化的操作目标摘要（如路径），供宿主向用户展示；`ApprovalRequest` 不携带 `RequestedScope` / `RequestedCapabilities` |
| `CorrelationId` | 关联标识（必填，位于首位） |

宿主通过 `approval.response` 回调返回 `ApprovalResponse`，包含用户决定和可选的收窄 Grant。

## 6. 工具执行目标

`ToolExecutionTarget` 枚举定义工具的执行位置：

| 值 | 含义 | 执行方式 |
| --- | --- | --- |
| `Builtin` | Runtime 内置工具 | Runtime 进程内直接执行，如 `mcli_fs_*`、`mcli_http`、`mcli_process` |
| `Host` | 宿主工具 | 通过 Reverse RPC 发送给宿主执行 |
| `Mcp` | MCP 协议工具 | 通过 MCP 协议路由到外部服务器执行 |

工具目录中的每个工具都标注了 `ExecutionTarget`，Gateway 据此分发到对应的执行器。

## 7. 工具调用状态

`ToolCallStatus` 枚举表示工具调用的持久化执行状态：

| 值 | 含义 |
| --- | --- |
| `Pending` | 已创建意图，尚未开始执行 |
| `Running` | 正在执行中 |
| `Succeeded` | 执行成功 |
| `Failed` | 执行失败 |
| `Cancelled` | 已取消 |
| `Unknown` | 状态不明（例如宿主断开后未收到结果） |

状态转换：`Pending → Running → Succeeded / Failed / Cancelled`。`Unknown` 在宿主断开且无法确认结果时产生，需要人工干预或重试。

> 注意：`ToolCallStatus` 无 `Sent` 值。持久化层另有一个独立的 `ToolIntentStatus` 枚举（`Pending`/`Sent`/`Succeeded`/`Failed`/`Cancelled`/`Unknown`），其中 `Sent` 表示"意图已发往宿主但结果未回"，用于断连恢复。二者的语义区别与映射见 [14-断点恢复与会话重建](./14-断点恢复与会话重建.md) §5.2、§6.3。

## 8. 审计

每次工具调用产生一条 `ToolAuditRecord`，记录到 SQLite 数据库。

```csharp
public sealed record ToolAuditRecord(
    string AuditId,
    string CallId,
    string RunId,
    string SessionId,
    string InvocationId,
    string? ParentInvocationId,
    string AgentId,
    string? ParentAgentId,
    string ToolId,
    string ToolCatalogVersion,
    int Risk,
    string ArgumentsHash,
    string TargetSummary,
    string? GrantId,
    string RootGrantId,
    string? ApprovalRequestId,
    string[] DelegationChain,
    string Status,
    string? ResultHash,
    string DiagnosticId,
    DateTimeOffset CreatedAt,
    string? WorkStepId = null,
    string? PlanVersion = null,
    DateTimeOffset? CompletedAt = null,
    long? DurationMilliseconds = null);
```

审计记录设计原则：

- `TargetSummary`：规范化路径摘要，不包含文件内容。
- `ArgumentsHash`：参数哈希，不存储原始参数。
- `ResultHash`：结果哈希，不存储原始结果。
- `DelegationChain`：完整的委托链，可追溯权限来源。
- `DiagnosticId`：诊断标识，与日志系统关联。

审计记录不记录文件内容、参数明文或结果正文，只保留足够的信息用于事后追溯和合规审计。

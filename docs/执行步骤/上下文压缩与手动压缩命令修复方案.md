## 1. 调研结论

当前实现不是“完全没有压缩代码”，而是存在三类断点：

1. **手动压缩命令链路存在，但宿主只传递了 `strategy=summary`。**
   - 桌面端 `CompactRuntimeAsync` 调用 `IConversationTurnService.CompactAsync`。
   - Service 层调用 `IRuntimeGateway.CompactSessionAsync`。
   - Gateway 启动 `madorin-cli session compact <sessionId> --strategy summary`。
   - `provider`、`model`、`keep-last-tokens` 等宿主设置没有传递。

2. **Runtime 的压缩缓存没有进入普通 Invocation 的上下文构造链路。**
   - `session compact` 会写入 `ConversationCompactCacheV1`。
   - 普通 Expert/Meeting/Work 执行仍然从 canonical history 重新构造 ContextProjection。
   - 因此“压缩命令成功”不等于“下一次对话一定使用压缩后的投影”。

3. **宿主 Memory Settings 目前只完成 UI 和偏好保存，没有完成 Runtime 注入。**
   - `Compaction.ModelId`、`Compaction.VendorId`、`Compaction.SegmentSize`、`Compaction.RawTailSize` 等键只在 `MemorySettingsViewModel` 中被读写。
   - Workstation 其他层没有发现这些配置键的消费点。
   - Runtime 的 `SessionCompactionOptions` 也没有 `SegmentSize`、`RawTailSize`、`MaxDisplaySegments` 等对应字段。

## 2. 目标与非目标

### 2.1 目标

- 修复手动 `session compact` 命令当前的失败链路，并输出可诊断的错误信息。
- 让宿主明确传递压缩 Provider、压缩 Model 以及窗口参数。
- 明确区分：
  - 手动持久化压缩；
  - 每次 Invocation 的动态上下文投影；
  - Meeting 的轮次摘要；
  - Work 的确定性上下文缩减。
- 让压缩结果是否被下一次对话复用具有明确、可测试的语义。
- 保留 canonical history append-only 约束，不通过修改历史 JSONL 实现压缩。

### 2.2 非目标

- 不删除或重写 canonical history。
- 不把宿主 UI 的展示参数直接伪装成 Runtime 的 Token 参数。
- 不让压缩模型调用继承普通 Agent 的工具权限。
- 不在本轮引入新的 Provider SDK 或改变已有 Provider 协议。
- 不通过吞掉 CLI 标准输出/标准错误来“隐藏”失败。

## 3. 修复原则

1. **先修命令可执行，再接入配置，再接入自动复用。**
2. **所有跨进程参数使用强类型请求对象，不继续扩展字符串拼接参数。**
3. **ProviderId、VendorId、ModelId、ProviderModelId 必须明确区分并记录映射。**
4. **压缩缓存必须带完整的投影条件和源历史指纹，条件不匹配时只能视为缓存未命中。**
5. **自动压缩模型必须是 tool-free、可取消、可审计的独立调用。**
6. **任何上下文裁剪都必须保留 Tool Call/Tool Result 原子性。**

### 4.6 设计并实现压缩缓存的安全复用 : 80%

- Work：继续根据 Plan/Step/Dependency 快照重建投影，不直接复用通用 Session compact cache。
- 若当前模式没有安全复用条件，结果必须返回明确的 `cacheMissReason`，而不是显示“压缩已生效”。

## 6. 风险与回退方案

### 风险一：当前手动压缩失败原因尚未拿到原始错误

先执行 4.1，不在没有 ExitCode/stdout/stderr 的情况下改 Provider、工作目录或配置加载逻辑。

### 风险二：压缩设置的单位含义不明确

不把 `SegmentSize` 或 `RawTailSize` 直接映射成 Token。先完成 4.4 的语义冻结；在此之前只接入已经有明确契约的 `ProviderId`、`ModelId`、`KeepLastTokens`。

### 风险三：缓存被错误复用

默认回退为每次 Invocation 重新投影。只有完成 cache key、策略哈希和失效条件后，才开启普通 Invocation 的缓存复用。

### 风险四：真实 Provider 不支持摘要模型

摘要失败时按模式策略回退：

- Expert：TailWindow；
- Meeting：MeetingSummaryFallbackStrategy；
- Work：确定性缩减；
- 手动强制 Summary：返回明确失败，不伪造成功结果。

### 风险五：跨仓库版本不同步

先更新 Contracts/协议，再更新 Runtime，再更新 Workstation Gateway，最后更新 Desktop；每一阶段均运行对应仓库测试，禁止只编译 Desktop。

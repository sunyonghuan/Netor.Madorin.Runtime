# 协议变更：并发故障隔离与宿主状态闭环

## 基本信息

- 变更编号：`PROTOCOL-20260726-01`
- 引入程序版本：V1 维护批次 07A
- 引入协议版本：`1.1`（不升级主版本）
- 数据库 Schema：`15 -> 16`
- 变更类别：兼容追加 + 持久化一致性修复
- 计划移除版本：无

## 变更表面

- DTO 字段：`RunQueryResult`、`RunListItem`、`RunStatusChangedEvent` 追加可空进度、模式、错误和时间字段，保留现有主构造函数。
- JSON-RPC 方法/消息类型/能力/事件通道：无新增；`run.stage.changed` 继续使用既有 Envelope、GSN、ACK 和 RunSequence。
- 错误：复用 `RuntimeError` 脱敏结构；新增客户端本地 `RuntimeProcessExitedException`，不进入 Runtime JSON-RPC 错误码表。
- Schema：`runs` 增加 `phase`、`current_step`、`completed_units`、`total_units`、`last_run_sequence NOT NULL DEFAULT 0`、`error_json`。
- CLI：`ctl runs` 当前人工投影继续只输出既有字段，命令矩阵和 CLI JSON 契约不变。

## 兼容性判定

- 新代码读取旧 JSON：支持，新增字段为 `null`/`0`。
- 旧代码读取新 JSON：支持，未知可选字段忽略。
- 新 Client 到旧 Runtime：仍可用既有方法和字段；新字段缺失按兼容规则处理。
- 旧 Client 到新 Runtime：支持，新增字段不影响既有响应。
- 是否升级协议主版本：否。没有删除、重命名、必填化字段，也没有改变 GSN、ACK、终态语义。

## 迁移、快照与回退

- v15 到 v16 为事务化前向迁移，迁移失败回滚；不提供降级迁移。
- 升级前沿用已有备份。代码回退时恢复 v15 数据目录。
- 快照覆盖 `RunQueryResult`、`RunListItem`、`RunStatusChangedEvent` 的旧字段、新字段和未知字段忽略行为。
- Outbox replay 复用持久化 `created_at`，不重写事件时间。

## 安全与敏感数据

进度列不写入 Prompt、文本 Delta、工具参数或凭据。结构化错误只保存脱敏 `RuntimeError` 与 DiagnosticId；日志只记录异常类型和 DiagnosticId。

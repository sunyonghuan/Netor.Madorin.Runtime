# Madorin CLI 自动化与故障排查

> 适用版本：Madorin.AI.Runtime V1，协议 1.1，SQLite Schema 15
>
> 前置阅读：[01-概念与导航](./01-概念与导航.md)。本文面向脚本化调用 CLI 的自动化程序，以及排查启动/运行故障的使用者。

## 1. 机器可读输出

自动化一律使用 `--json`（或 `run` 的 `--output-format json|jsonl`），不解析面向人的文本。约定：

- JSON/JSONL 模式下 stdout **只含机器数据**；进度、诊断、日志一律写 stderr。
- 非 TTY 或 `--no-color` 时不输出 ANSI 控制码。
- 不要把 stderr 合并进 stdout 再解析 JSON。

### 1.1 统一 JSON 信封

成功：

```json
{
  "success": true,
  "data": { },
  "warnings": [],
  "diagnosticId": null
}
```

失败：

```json
{
  "success": false,
  "error": {
    "code": "WorkspaceNotFound",
    "message": "...",
    "isRetryable": false,
    "diagnosticId": "diag_xxx"
  },
  "warnings": [],
  "diagnosticId": "diag_xxx"
}
```

业务字段只出现在 `data`；失败时恢复点等可操作上下文也可能保留在 `data`。

独立 CLI 配置层使用以下稳定错误码，均返回退出码 `2`：

| 错误码 | 含义 |
| --- | --- |
| `ConfigurationNotFound` | 全局配置不存在，机器模式不会启动交互向导 |
| `ConfigurationInvalid` | 全局配置或 Agent 目录无效 |
| `WorkspaceConfigurationInvalid` | 工作区配置超限、Schema/JSON/字段无效或不可读 |
| `WorkspaceSelectionNotFound` | 工作区显式引用或工作区有效选择无效 |
| `SelectionNotFound` | 命令行覆盖后的最终选择无效 |

### 1.2 流式 JSONL

`run --output-format jsonl` 每行都是一个完整 JSON 对象。终态行必须能仅凭该行的 `success` 与 `data`/`error` 判断成功或失败，不依赖前后行。
## 2. 退出码

固定退出码，自动化据此分支：

| 退出码 | 含义 |
| ---: | --- |
| 0 | 成功，或 dry-run/检查完成且结果健康 |
| 1 | 通用错误、检查发现不健康状态或部分恢复 |
| 2 | 参数或配置错误 |
| 3 | 认证错误 |
| 4 | 工作区、数据目录或排他锁错误 |
| 5 | Runtime 连接错误（`ctl` 无法连接到目标实例） |
| 130 | 用户拒绝确认或主动中断 |

判定规则：

- **同时**检查进程退出码和 JSON 信封的 `success`，不要只看其一。
- 不要仅搜索人类输出文本；不要把“创建了恢复点”误判为维护成功。
- 任何 `partial`、`diagnosticId` 或 `warnings` 都应进入运维记录。
- `退出码 1` 可能是“部分恢复”而非彻底失败，需结合 `data` 判断后续动作。

## 3. 非交互确认矩阵

危险操作在非交互/JSON 场景必须显式确认，否则拒绝执行（多为退出码 2）。各命令用**各自**的确认参数，不通用：

| 操作 | 非交互确认 |
| --- | --- |
| `doctor --fix` | `--yes`（且 `--yes` 只能与 `--fix` 合用） |
| `db repair` | `--yes` |
| `db rebuild` | `--confirm` |
| `storage gc` | `--confirm` |
| `session delete` | `--confirm` |

补充约束：

- dry-run 不得与实际确认混用，例如 `storage gc --dry-run --confirm` 作为参数错误拒绝。
- 拒绝交互确认返回退出码 130。
- `ctl credential update` 必须同时给 `--run`、`--provider`、`--api-key-env`。

### 3.1 模型工具不接受自动确认

`--yes` 和各维护命令的 `--confirm` 只确认表中对应的 CLI 维护操作，不会为模型工具创建 Grant。独立 CLI 在 JSON/JSONL、stdin/stdout 重定向、输出文件或其他非交互场景不会输出 Consent 提示；需要新权限的工具调用按 fail closed 终止，自动化程序不得等待或尝试解析提示文本。

需要模型调用本地工具时，应在真实文本终端中交互运行，由用户逐次选择授权；需要无人值守执行时，由宿主通过 Client SDK/Reverse RPC 实现权限和审批回调，并自行持久化宿主策略。两条路径不能同时为同一个 Run 提供权限权威。

## 4. 常见参数错误（固定返回退出码 2）

- `run --input` 与 `--input-file` 同时出现。
- `run --output-file` 未配合 `--input` 或 `--input-file`。
- `run` 在交互模式下使用 JSON、JSONL 或 `--no-stream`。
- `run --json` 与非 JSON 的 `--output-format` 同时出现。
- `serve` 缺少 `--workspace`。
- 工作区 `.madorin/config.json` 包含未知字段、空白值、无效引用或超过 64 KiB。
- `session delete` 缺少 `--confirm`。
- `storage gc --dry-run` 与 `--confirm` 同时出现。
- `ctl credential update` 缺少 `--run`、`--provider` 或 `--api-key-env`。
## 5. Secret 与凭据在自动化中的传递

- API Key 只通过无回显输入、受控环境变量或宿主凭据更新接口传入；CLI 不提供 `--api-key <value>`。
- `ctl credential update` 用 `--api-key-env <envVar>` 从环境变量读取新密钥，不作为命令行明文参数。
- `ctl` 连接运行中 Runtime 所需的握手 secret 从环境变量 `MADORIN_AI_RUNTIME_SECRET` 读取，不作为参数，也不写入 stdout、stderr、JSON 或日志。
- 日志、诊断包和工单中持续对 Key、Prompt、工具参数和业务内容脱敏。

## 6. 故障排查

### 6.1 双击启动窗口秒退

多为配置、工作区或 Provider 检查失败。从终端运行 `madorin` 查看完整错误和退出码；按退出码定位：`2` 配置/参数、`3` 认证、`4` 工作区/数据。先跑 `madorin config validate --workspace <path>` 和 `madorin doctor --workspace <path>`。

### 6.2 工作区配置错误（退出码 2）

运行 `madorin config validate --workspace <path> --json`，根据稳定错误码区分全局配置、工作区 Schema 和最终引用问题。工作区文件只允许 `schemaVersion` 与 `selection.provider/model/agent`；缺失文件是正常的全局回退，空白字符串不是继承。错误输出只应包含文件路径和结构化原因，不应包含配置正文或 API Key。

`MADORIN_CONFIG_DIR` 只覆盖全局配置根，不是工作区配置路径。若它被错误设置为项目目录，CLI 会把该目录当作完整全局配置目录并要求其中存在有效的 `config.json` 和 `agents/`；取消该环境变量或改回正确的全局配置目录，不能用它指向 `<workspace>/.madorin`。

### 6.3 版本或产品名不符

`madorin version --json` 的 `data.product` 应为 `Madorin.AI.Runtime`、`data.protocolVersion` 应为 `1.1`。不符说明 PATH 指向了错误的二进制或发布包不完整，重新安装（见 [02-安装与初始化](./02-安装与初始化.md)）。

### 6.4 Provider 认证或连通失败（退出码 3）

确认 `config show`（脱敏）中 Provider 端点、模型正确；密钥用 `config edit` 重新以安全输入写入。运行中 Runtime 的凭据过期用 `ctl credential update` 续期。

### 6.5 工作区锁冲突（退出码 4）

同一规范化工作区默认只有一个写实例。处理顺序：

1. `madorin ctl status --workspace <path>` 核对持锁实例和绑定。
2. 停止向该实例分配新 Run，等待活动 Run 完成或按业务策略取消。
3. 由拥有该 Runtime 的终端、服务管理器或 Client 生命周期正常关闭进程。
4. 确认退出后重新执行。

不要直接删除锁文件，不要按进程名批量结束 Runtime，也不要终止其他工作区或其他 Client 拥有的实例。

### 6.6 ctl 无法连接（退出码 5）

实例文件缺失/损坏、PID 失效、Pipe 品牌或实例不匹配、连接失败都会返回 5；缺 secret 或握手失败返回 3。确认目标 Runtime 仍在运行、`--instance` 与实际实例一致、`MADORIN_AI_RUNTIME_SECRET` 已设置。

### 6.7 数据库或存储告警

不要通过删除 `state.db` 或清空 `.madorin` 来消除告警。按只读检查 → 定向修复的顺序处理，完整故障处置流程见 [05-安全与数据运维](./05-安全与数据运维.md) 的“故障处置顺序”。

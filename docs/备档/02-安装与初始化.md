# Madorin CLI 安装与初始化

> 适用版本：Madorin.AI.Runtime V1，协议 1.1，SQLite Schema 14
>
> 当前发布基线：Windows x64 Native AOT。其他平台的正式安装制品在阶段 8 验收。
>
> 前置阅读：[01-概念与导航](./01-概念与导航.md)。

## 1. 安装

安装 = 把完整发布包解压到一个独立目录，并把该目录加入可执行文件查找路径（PATH）。不要只复制仓库中的 Debug/Release 中间产物。

1. 选择一个独立安装目录，例如当前用户目录下的 `Madorin/bin`。安装到用户目录不需要管理员权限。
2. 把发布包内 `publish/` 下的全部文件复制进该目录（保留子目录结构）。
3. 把安装目录加入当前用户 PATH。PATH 的设置方式随操作系统和 shell 而不同，按所在环境的标准做法操作即可。
4. 重开终端使 PATH 生效。

安装目录中至少包含可执行文件 `madorin`（Windows 上为 `madorin.exe`）及其运行时依赖。

## 2. 验证安装

重开终端后运行：

```text
madorin --help
madorin version --json
```

`version --json` 的判定标准：

- `success` 为 `true`
- `data.product` 为 `Madorin.AI.Runtime`
- `data.protocolVersion` 为 `1.1`

任一项不符，说明 PATH 指向了错误的二进制或发布包不完整，回到第 1 节重新安装。

## 3. 裸启动与双击启动

直接执行 `madorin`（无参数），或在图形界面中双击可执行文件，都会进入同一个轻量单行 REPL。首次启动若没有个人配置，会先进入初始化向导；配置完成后进入交互会话。

双击窗口立即关闭，通常表示配置、工作区或 Provider 检查失败。此时从终端运行 `madorin`，查看完整错误和退出码（见 [06-自动化与故障排查](./06-自动化与故障排查.md)）。

V1 不实现全屏 TUI、多行编辑器、输入队列或终端光标接管。交互形态和斜杠命令见 [03-命令行与交互使用](./03-命令行与交互使用.md)。
## 4. 个人目录与工作区

个人 CLI 文件位于当前系统用户主目录，供直接启动的个人 CLI 使用：

```text
~/.madorin/
├── config.json          个人配置：Provider、模型、默认 Agent
├── agents/
│   └── <agentId>.json   Agent 定义
├── memory.md            全局记忆
└── data/
    └── workspaces/
        └── <workspaceKey>/   各工作区隔离的 Runtime 数据
```

- `config.json`、`agents/` 和全局 `memory.md` 只供个人 CLI 使用；宿主集成不读取它们。
- `workspaceKey` 由规范化工作区路径稳定派生，不在目录名中暴露原始路径。
- 项目记忆固定为 `<workspace>/.madorin/memory.md`。
- 工作区可选文件 `<workspace>/.madorin/config.json` 只保存 Provider、Model、Agent 选择；它是 Runtime 保留目录中的唯一团队配置例外。
- 不要手工修改 Runtime 数据区的 `state.db`、`messages/`、`blobs/` 或实例文件（结构见 [01-概念与导航](./01-概念与导航.md) 第 5 节）。

用 `--workspace <path>` 显式选择工作区；`--data-dir <path>` 只在需要受控覆盖 Runtime 数据位置时使用。同一规范化工作区只允许一个写实例，不同工作区可以并行。

## 5. 首次配置

无参数首次启动会自动进入向导，也可以显式执行：

```text
madorin config init
madorin config validate
madorin config show
```

向导配置 Provider 协议、Base URL、API Key、模型和默认 Agent。API Key 通过无回显输入写入个人 `config.json`；CLI **不提供** `--api-key <value>`，避免密钥进入命令历史和进程参数。后续修改用 `madorin config edit`；`config show` 和诊断输出只显示脱敏值。

工作区可以按需添加以下文件；缺失、`null`、`{}` 或字段 `null` 都表示继承全局配置：

```json
{
  "schemaVersion": 1,
  "selection": {
    "provider": "openai",
    "model": "gpt-5",
    "agent": "default"
  }
}
```

CLI 只读取当前工作区的固定路径，不向父目录扫描，也不自动创建该文件。Agent 优先级是“命令行 > 工作区 > 全局”；Provider/Model 优先级是“命令行 > Agent 绑定 > 工作区 > 全局”。工作区配置不得包含 Provider 地址、凭据或 Agent 正文。

```text
madorin config show --workspace <path>
madorin config validate --workspace <path>
madorin doctor --workspace <path>
```

团队需要提交该文件时，推荐在仓库忽略规则中只放行它：

```gitignore
.madorin/*
!.madorin/config.json
```

### 5.1 Provider 支持矩阵

| 协议值 | 默认向导 | 认证 | Base URL | 模型来源 | 支持状态 |
| --- | --- | --- | --- | --- | --- |
| `OpenAI` | 显示 | Bearer API Key | 内置默认值，可覆盖 | 配置模型 | 正式 |
| `Anthropic` | 显示 | `x-api-key` | 内置默认值，可覆盖 | 配置模型 | 正式 |
| `OpenAI Compatible` | 显示 | 可配置 Header/Scheme，API Key 必填 | 必填 | 配置模型或 `ProbePath` | 正式 |
| `DeepSeek` | 显示 | Bearer API Key | 内置默认值，可覆盖 | 配置模型 | 正式 |
| `Kimi` | 显示 | Bearer API Key | 内置默认值，可覆盖 | 配置模型 | 正式 |
| `Aliyun` | 显示 | Bearer API Key | DashScope 默认端点，可覆盖 | `/models` 或手工输入 | 正式聊天；图片/视频不在本批契约内 |
| `Gemini` | 显示 | Bearer API Key | Google Compatible 默认端点，可覆盖 | `/models` 或手工输入 | 正式 |
| `GLM` | 显示 | Bearer API Key | 必填 | 标准 `models` 探测或手工输入 | 正式 |
| `Custom` | 显示 | 可配置 Header/Scheme，API Key 必填 | 必填 | 配置模型或 `ProbePath` | `OpenAI Compatible` 别名 |
| `Ollama` | 显示 | 默认无认证；提供 Key 时使用代理认证 | 本机默认端点，可覆盖 | `/api/tags` 或手工输入 | 正式 |
| `Azure OpenAI` | 隐藏 | `api-key` | Azure 资源请求基址，必填 | 手工配置 Deployment | 实验；真实资源验收前不进入默认向导 |

模型输入提示出现时，可以输入 `discover` 发起远程发现。单次发现最多等待 10 秒；不支持发现、返回空目录或发生连接、认证、限流、服务端、协议错误时，向导只显示脱敏的稳定错误类别并返回手工输入，不会写入半有效配置。取消向导也不会保存临时配置。

`doctor` 会先执行可用的模型发现，再探测 Provider 能力；单个 Provider 共用 10 秒超时。成功结果包含模型总数和最多三个模型样本，失败结果不包含 API Key、Authorization 或响应正文。Azure OpenAI 始终带有 `experimental` 标记。

## 6. 创建与管理 Agent

```text
madorin agent create [agentId]
madorin agent list
madorin agent edit <agentId>
madorin agent delete <agentId>
```

`agent create/edit` 在缺少参数时使用交互选择。自动化场景可传 `--name`、`--description`、`--system-prompt`、`--provider`、`--model`、`--temperature`，但 Provider 密钥仍只能通过安全输入写入配置。删除默认 Agent 时需用 `--replacement <agentId>` 指定接替者；非交互删除加 `--yes`。

Agent 集合决定了 meeting / work 模式在独立 CLI 下的参与者与子智能体（见 [03-命令行与交互使用](./03-命令行与交互使用.md) 第 4 节）。
## 7. 全局与项目记忆

两个固定记忆文件：全局 `~/.madorin/memory.md`，项目 `<workspace>/.madorin/memory.md`。初始化并查看：

```text
madorin memory init global
madorin memory init project --workspace <path>
madorin memory show effective --workspace <path>
```

`show effective` 按“全局后项目”的实际注入顺序展示来源，项目规则更具体。追加、编辑和清空：

```text
madorin memory add global
madorin memory edit project --workspace <path>
madorin memory clear project --workspace <path>
```

- `memory add` 从标准输入读取单行内容追加。
- `memory edit` 调用受控编辑流程；编辑器取自 `MADORIN_EDITOR`、`VISUAL` 或 `EDITOR` 环境变量。
- `memory clear` 非交互场景加 `--yes`。

记忆只由这些用户命令或经审批的 `builtin.memory` 工具写入，不从对话、项目文件或工具结果自动提取。`<scope>` 只接受 `global` 或 `project`；`effective` 仅用于 `show`。

## 8. 自检

```text
madorin version --json
madorin doctor --workspace <path>
madorin doctor --workspace <path> --fix
```

`doctor` 按 Runtime、个人配置、记忆、工作区、数据、Provider、传输、日志和 Blob 的固定顺序检查。`doctor --fix` 只修复已识别的可恢复数据库损坏，先展示计划并要求确认；JSON 模式下实际修复必须加 `--yes`（见 [05-安全与数据运维](./05-安全与数据运维.md)）。

配置就绪后，进入 [03-命令行与交互使用](./03-命令行与交互使用.md) 开始运行任务。

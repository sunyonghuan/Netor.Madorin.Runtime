# 工作计划模板规格（Runtime 默认契约）

> 仓库原先缺少本文件。本规格按《工作与会议模式》与合理默认落地，供 `mcli_work_*` 模板三件套实现与测试对齐。

## 1. 扫描根

| 根 | 路径 |
| --- | --- |
| 用户根 | `{LocalApplicationData}/madorin/work-templates` |
| 系统根 | `{AppContext.BaseDirectory}/work-templates` |

仅扫描各根下一层子目录。根不存在或为空时，`list` 返回空数组，不算失败。

## 2. 模板目录结构

```text
{root}/{template-dir}/
  TEMPLATE.md          # 必填
  references/**        # 可选，load 只索引不内联
  scripts/**           # 可选，load 只索引不内联
```

## 3. TEMPLATE.md

必须 UTF-8，以 YAML frontmatter 开头：

```yaml
---
name: monthly-report
description: 月报工作计划模板
category: reporting   # 可选，缺省空串
version: "1.0"        # 可选，缺省 1.0
---
使用说明正文……

## 计划骨架
计划骨架正文……
```

假设：

1. `name` / `description` 必填。
2. 正文若含 `## 计划骨架`，其后为 `planSkeleton`，之前为 `instructions`；否则全文为 `instructions`，`planSkeleton` 为空串。
3. **禁止**在 load/read 时替换 `{{占位符}}`。
4. `TEMPLATE.md` 上限 256 KiB；索引文件上限 64；单文件 read 上限 256 KiB。

## 4. 路径安全

1. `path` 必须是绝对路径，且规范化后落在用户根或系统根之下。
2. `relativePath` 必须用 `/`，禁止 `\`、`..`、盘符与绝对路径。
3. `read` 的 `relativePath` 必须等于 `load` 返回的 `files[].relativePath`。

## 5. 文件索引 kind

| relativePath | kind |
| --- | --- |
| `TEMPLATE.md` | `template` |
| `references/**` | `reference` |
| `scripts/**` | `script` |

## 6. JSON 契约

### 6.1 `mcli_work_list_plan_templates`

输入：`keyword?`、`category?`（字符串，可选）。

成功：

```json
{"ok":true,"templates":[{"name":"...","description":"...","path":"...","category":"...","version":"..."}]}
```

空结果：`{"ok":true,"templates":[]}`。

### 6.2 `mcli_work_load_plan_from_template`

输入：`path`（绝对路径，必填）。

成功：`ok=true`，含 `path/name/description/category/version/instructions/planSkeleton/files/note`。

失败：`{"ok":false,"error":"path_not_allowed|template_not_found|template_invalid","message":"..."}`。

### 6.3 `mcli_work_read_template_file`

输入：`path`、`relativePath`。

成功：`{"ok":true,"path":"...","relativePath":"...","content":"..."}`。

失败：同 6.2 的 `error` 枚举。

## 7. 模式可见性

三件套与 `mcli_work_set_plan` / `mcli_work_dispatch_step` 标注 `SupportedModes=["work"]`。Expert 目录不得暴露。

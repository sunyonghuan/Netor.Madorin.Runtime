# 工作模式 / 会议模式：流程、提示词注入、模式专用工具

本文给 Runtime / CLI 实现用。不要当产品说明书。

硬约束：

1. 下文 `mcli_work_*` / `mcli_meeting_*` / 共享 `mcli_ask_user` / `mcli_check_pending_user_input` **不得**进入专家模式工具目录。
2. 已有工具：**作用**与旧 Cortana 同名工具一致；**名字**全部改为 `mcli_*`。三个模板工具旧软件未实现，不适用本条，见第 6 条。
3. 工作、会议共用的工具只实现一份，按 Mode 注册到两个目录。禁止复制两套 `ask_user`。
4. `AgentRef` 无类型字段。谁进会、谁当 A/B，由宿主筛完再传。
5. 通用文件/记忆/HTTP/进程工具（`mcli_fs_*`、`mcli_memory_*`、`mcli_http`、`mcli_process`）仍走现有目录；本文只管模式编排工具。
6. `mcli_work_list_plan_templates`、`mcli_work_load_plan_from_template`、`mcli_work_read_template_file` 是**本期新增**，旧软件没有。提示词必须点名这三个 ToolId；§1 表必须登记。两处同时具备。由 **Runtime 内置**。禁止做成宿主回调。独立 CLI 无宿主时这三个工具必须仍可用。目录、`TEMPLATE.md` 格式、第一句解析、加载状态机以 `docs/工作模板/策划/工作计划模板规格.md` 为准。发给 Runtime 仓库时必须同时附上该文件。

## 2. 共享工具（一份实现，两模式注册）

实现模块建议：`Modes.Shared` 或 `Tools.ModeShared`。Work / Meeting 目录都引用同一 `AIFunction` 工厂。上下文用接口注入（当前 session/run/task/meeting id），不要在工具里写死模式。

### `mcli_ask_user`

作用：需要用户决策或补充关键信息时挂起，把问题交给宿主展示；用户回复后本 Run/本轮才继续。

参数：`question` string，必填，短句。

副作用：写 pending HITL（kind=`ask_user`）；发宿主可投影的 HITL 事件；当前 invocation 进入等待。

返回：已提问、等待用户。禁止假装用户已回答。

Work A：方向性选择、不可逆风险、缺了会导致方向错的信息。缺字段时优先合理假设，不要每步都问。
Meeting Host：主题不清、插话影响范围不清、议题成熟后征询是否结束。结束征询前必须先 `mcli_check_pending_user_input`。

### `mcli_check_pending_user_input`

作用：看当前会话有没有尚未消费的用户插话。`mcli_ask_user` 之前必须先调。

参数：无。

Work：消费工作任务插话队列；有则返回原文，无则「没有新的用户输入」。
Meeting：Peek 会议插话队列；有则列出内容并要求先处理插话，无则「没有未处理的用户插话」。

同一 ToolId、同一描述；内部按 Mode 选队列。不要拆成两个工具名。

## 3. 工作专用工具

只出现在 `Mode=Work` 的工具目录。A 规划轮和 B 执行轮按 §1 过滤。

### `mcli_work_set_plan`

作用：把任务写成可执行计划并落盘。JSON：`main_steps[].title` + `sub_steps[].title` + `sub_steps[].acceptance_criteria`。子步骤必须有验收标准。

成功：保存计划；发计划已更新事件；**阻塞执行**，向宿主要计划确认（旧行为：HITL kind=`plan_confirmation`，文案「工作计划已制定，确认后我再开始执行。」）。未确认前禁止 `mcli_work_dispatch_step`。

覆盖未执行部分时保留已完成步骤成果。

### `mcli_work_list_plan_templates`

本期新增。实现：Runtime 内置。扫用户根 `{LocalApplicationData}/madorin/work-templates` 与系统根 `{CLI AppContext.BaseDirectory}/work-templates`。禁止宿主回调。提示词必须点名本 ToolId。

作用：按 `keyword` / `category` 返回有效模板摘要（`name`、`description`、`path`、`category`、`version`）。不返回正文。无模板或过滤后为空返回 `{"ok":true,"templates":[]}`，这不是失败，不得报错停住，A 应直接 `mcli_work_set_plan`。

参数：`keyword` 可选字符串；`category` 可选字符串。完整 JSON 以规格 §6.1 为准。

### `mcli_work_load_plan_from_template`

本期新增。实现：Runtime 内置。参数只有绝对路径 `path`。禁止按「模板 id」查找。禁止宿主回调。提示词必须点名本 ToolId。

作用：读取并校验该目录的 `TEMPLATE.md`，返回使用说明、计划骨架、文件索引。只提供材料，**最终仍须** `mcli_work_set_plan`。禁止内联 `references/` / `scripts/` 正文。禁止替换 `{{占位符}}`。

`path` 必须落在两个来源根之下。空模板、缺 `TEMPLATE.md`、格式错误、超限一律返回 `ok=false`（`path_not_allowed` / `template_not_found` / `template_invalid`，条件以规格 §6.2 为准），不得结束会话。A 改为按任务文本 `mcli_work_set_plan`。完整 JSON 以规格 §6.2 为准。

### `mcli_work_read_template_file`

本期新增。实现：Runtime 内置。禁止用 `mcli_fs_read` 代替。禁止宿主回调。提示词必须点名本 ToolId。

作用：读取模板内一个已索引文件的 UTF-8 全文。参数：`path`（模板目录绝对路径）、`relativePath`（必须用 `/`，且等于 load 返回的 `files[].relativePath`）。

A 与 B 都可调用。完整 JSON 以规格 §6.3 为准。

### `mcli_work_load_plan_from_chat_history`

作用：读当前或指定 session 近期对话，当制定计划的参考。只提供材料，仍须 `mcli_work_set_plan`。

### `mcli_work_load_plan_from_groupchat`

作用：读群聊/会议历史当计划参考。可与 chat_history 共用读取链路，ToolId 必须分开（提示词按场景点名）。

### `mcli_work_get_recent_completed_task_plan`

作用：取最近已完成任务计划作「再做一份 / 改月份」参考。只提供材料，仍须 `mcli_work_set_plan`。

### `mcli_work_dispatch_step`

作用：执行计划中一个子步骤（同步）。参数：`stepIndex`、`subStepIndex`（均从 1）、`instruction`。

未 `set_plan` 或计划未确认：拒绝。
开始时发步骤开始事件。实际干活：按该步 `targetAgentId` 调 `AvailableAgents` 里对应 Agent（B=`project-lead`，专员=自定义 ULID）。

## 4. 会议专用工具

只出现在 `Mode=Meeting` 的工具目录。

### `mcli_meeting_output_summary`

作用：把会议总结写成独立 summary 消息（markdown：主题、各人观点、共识、分歧、下一步）。

拒绝把内部调度 JSON 当总结。成功后提示：下一步必须 `mcli_check_pending_user_input`；无插话再 `mcli_ask_user` 问是否结束。不要再点名讨论原话题。

### `mcli_meeting_confirm_end`

作用：老板已明确同意结束后调用。取最近 summary 写入 FinalSummary 并置终止。无总结则报错，要求先 `mcli_meeting_output_summary`。成功后禁止再讨论、再点名。

### `mcli_meeting_list_attachments`

作用：列出本场会议附件元数据，不读文件内容。无附件明确说没有。读内容用通用 `mcli_fs_read`，不要再发明会议读附件工具。

主持人、参会者都可以调。

## 5. 工作模式流程（实现必须按此状态走）

角色：A=`WorkModeOptions.GeneralManager`（`general-manager`）；B=池中 `project-lead`；C=池中自定义 ULID。

宿主注入：

```text
GeneralManager.AgentId = general-manager
GeneralManager.SystemPrompt = 库「总经理」全文 + 宿主发现段（tool.search / load_skill 等）
AvailableAgents = [
  general-manager 原文,
  project-lead 原文,          // B，禁止从池里丢掉
  default 原文,               // 不当 A
  <自定义 ULID> 原文, ...
]
不含 meeting-host / meeting-participant / meeting-summarizer
InitialInput = 第一句（仅创建时发）。宿主按规格 §5.1 从请求目标与可选模板路径生成。禁止把 TEMPLATE.md 全文写入 InitialInput。
```

A 本轮工具目录 = §1 中 Work A 为「是」的行 + 通用 `mcli_fs_*` 等（按现有授权）。
B 本轮工具目录 = `mcli_work_dispatch_step` + `mcli_work_read_template_file` + 通用工具，**无** ask_user / set_plan / list / load。

状态机：

```text
Planning
  第一句按规格 §5.2 解析。hasTemplate=true → A 必须先 load(templatePath)；此轮禁止先 list
  load 失败（空模板、缺文件、格式错、路径非法）→ 不得停；按任务文本 set_plan
  hasTemplate=false → A 可 list/load 模板或读历史；list 空数组不是失败
  A 必须 mcli_work_set_plan（参数禁止含 {{ ）
  -> 计划确认 HITL（WaitingForApproval）
用户确认「开始/同意/执行/可以」
  -> Executing
A 或 B 按计划调 mcli_work_dispatch_step
  步的执行者 = AvailableAgents[targetAgentId]
  B 执行时用 B 的 SystemPrompt；C 用该自定义 SystemPrompt
每步或耗时工具后 A 可 mcli_check_pending_user_input
  有插话：当补充约束 / 改目标 / 取消 / 备注
  改目标：A 再 set_plan（保留已完成步骤）后继续
缺方向或不可逆风险：A 调 mcli_ask_user，等回复
全部子步骤验收完：A 输出最终报告（自然语言即可）
```

禁止：规划轮只吐 JSON、不调 `mcli_work_set_plan` 就算计划已生效。
禁止：未确认就开始 dispatch。
禁止：B 调 `mcli_ask_user`。

## 6. 会议模式流程（实现必须按此状态走）

角色：Host=`HostAgent`（`meeting-host`）；参会者=`Participants[]`（仅自定义，≥2）；摘要=`Policy.Summarizer`（`meeting-summarizer`）。

宿主注入：

```text
Participants[i].Agent.SystemPrompt =
  库「会议参会上下文」+ "\n\n" + 该自定义 SystemPrompt
HostAgent.AgentId = meeting-host
HostAgent.SystemPrompt = 库「会议主持人」全文
  {participants} 已替换为当场 DisplayName，顿号拼接
SelectorPolicy.Type = HostDriven
Policy.Summarizer.AgentId = meeting-summarizer
Policy.Summarizer.SystemPrompt = 库「会议摘要」全文
Policy.SummaryMode = FinalOnly
Policy.HitlEnabled = 新建勾选
InitialInput = 会议主题（仅创建时发）
```

Host 本轮工具目录 = §1 Meeting Host 为「是」的行（含共享 ask/pending）+ 通用读写（按授权）。
参会者本轮 = `mcli_meeting_list_attachments` + 通用工具。**无** output_summary / confirm_end / ask_user。
Summarizer 本轮 = 无模式专用工具，只压缩文本。

状态机：

```text
开场（Host）
  主题不清 -> 发言说明缺口 -> mcli_ask_user
  主题清 -> 短开场（目标/依赖/当前缺口）-> 进入调度
调度循环（Host 自然语言控场，不要用 JSON 点名代替发言）
  Host 判断议题是否成熟（见主持人提示词）
  未成熟：安排下一位真实参会者（业务依赖，不点老板，不代部门发言）
  运行时按 Host 输出选择下一位；下一位用 Participants 里已拼接的 SystemPrompt 发言
  参会者可 mcli_meeting_list_attachments；读文件用 mcli_fs_read
老板插话
  当前条说完再注入
  Host 必须先处理插话（分类：补充/纠错/范围/优先级/结束/无关）
  局部恢复，禁止从零开场
收口（成熟后严格按序）
  1. mcli_meeting_output_summary
  2. mcli_check_pending_user_input
  3. 无插话 -> mcli_ask_user 问是否结束
  老板不同意：处理新问题，重新判断成熟，禁止立刻 confirm_end
  老板明确同意 -> mcli_meeting_confirm_end
  会终可用 Summarizer 做上下文压缩（FinalOnly），不得代替 output_summary
```

禁止：HostDriven 把 Host 锁成只吐 `{conclude,participantId}` 且不给会议工具。本规格要求 Host **能说话 + 能调 §4 工具**。点名可以是工具结果或编排器解析，但 `output_summary` / `ask_user` / `confirm_end` 必须是真工具。
禁止：把 host/participant/summarizer 再塞进 `Participants[]`。
禁止：参会者人数 &lt; 2。

## 7. 目录装配（避免专家模式看见）

```text
ResolveToolCatalog(Mode):
  Expert -> 现有通用目录。不含 §1 任何 ToolId
  Work   -> 通用目录
            + 共享 mcli_ask_user / mcli_check_pending_user_input
            + 全部 mcli_work_*
            再按调用者过滤：A 全开工作+共享；B 只 dispatch_step + read_template_file + 通用
  Meeting -> 通用目录
            + 共享两工具
            + 全部 mcli_meeting_*
            再按调用者过滤：Host 全开会议+共享；参会者只 list_attachments + 通用
```

`mcli_delegate_agent` 若专家模式已有，Work 可复用同一实现派 C；不要再为 Work 复制一套委派。Work/Meeting 专用工具仍禁止进 Expert。

## 8. CLI 接到宿主提示词之后

已传 `GeneralManager.SystemPrompt`：禁止内置英文 GM 覆盖。
已传 `AvailableAgents` 含 `project-lead`：禁止丢掉 B。
已传 `HostAgent`：用其 SystemPrompt；禁止 BuiltInHostAgent / BuiltInSelectorAgent。
已传 `Summarizer`：用其 SystemPrompt；禁止 BuiltInSummarizerAgent。
参会者 SystemPrompt 已含「会议参会上下文」前缀：禁止再拼一份。

缺 HostAgent / Summarizer / 工作池（旧测试）才允许回退内置英文稿。

## 9. 实现顺序

1. 共享 `mcli_ask_user` + `mcli_check_pending_user_input`（Work/Meeting 各接自己的 pending 队列）。
2. Work：`set_plan` + 计划确认门闩 + `dispatch_step`。
3. Work：三个本期新增模板工具（Runtime 内置扫盘：list / load / read_template_file；提示词点名 + §1 表登记，两处同时具备）+ 历史/群聊/最近计划。禁止把模板三工具做成宿主回调。
4. Meeting：`output_summary` → `confirm_end` → `list_attachments`。
5. 按 Mode+调用者装目录；加测试：Expert 目录断言不含 §1 ToolId。
6. 改 HostDriven：Host 可自然语言 + 本节工具，不要只吐 JSON。
